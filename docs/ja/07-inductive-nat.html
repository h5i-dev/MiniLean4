第 7 章

帰納型 I: 自然数

宇宙と Π\PiΠ 型があれば論理は表せますが、計算したり証明したりする対象となる自然数はまだありません。本章では帰納型を使ってカーネルに自然数を加え、その再帰子から計算と帰納法の両方を引き出します。

定数と定義

まず、名前のついた対象をカーネルに追加できるようにする必要があります。そこで項に定数（constant）ccc を加えます。

t,A,B  ::=  ⋯  ∣  ct, A, B \;::=\; \cdots \;\mid\; ct,A,B::=⋯∣c

シグネチャ（signature）Σ\SigmaΣ は定数の一覧です。各項目では、定数を型とともに宣言する（c:Cc : Cc:C と書きます）か、本体も合わせて与えます（c:C:=tc : C \mathrel{:=} tc:C:=t と書きます）。本体をもつ項目を定義（definition）と呼びます。たとえば下の Nat:Sort 1\Nat : \Sort{1}Nat:Sort1 は宣言で、本章の後半に出てくる add\addadd は定義です。項目を追加する前には、その型が空の文脈で型になっていることを検査し、本体があれば本体がその型をもつことも検査します。Lean が def のたびに行う処理と同じです。

シグネチャの使い道は二つあります。一つ目に、定数はシグネチャに書かれた型をもちます。

⊢Γ;ok(c:C)∈ΣΓ⊢c:C;(T-Const)\dfrac{\ctxok{\Gamma} \qquad (c : C) \in \Sigma}{\Gamma \vdash c : C}\rulename{T-Const}Γ⊢c:C⊢Γ;ok(c:C)∈Σ​;(T-Const)

ここで (c:C)∈Σ(c : C) \in \Sigma(c:C)∈Σ には宣言も定義も含まれます。二つ目に、定義は展開（unfold）できます。定数をその本体で置き換えるこの計算ステップを δ 簡約（delta-reduction）と呼びます。

c  →δ  tif (c:C:=t)∈Σ.c \;\deltared\; t \qquad \text{if } (c : C \mathrel{:=} t) \in \Sigma.c→δ​tif (c:C:=t)∈Σ.

たとえば add  2  1→δ(λ(m:Nat). λ(n:Nat). ⋯ )  2  1\add\;2\;1 \deltared (\tLam{m}{\Nat}{\tLam{n}{\Nat}{\cdots}})\;2\;1add21→δ​(λ(m:Nat).λ(n:Nat).⋯)21 となり、そのあとに β 簡約が続きます。Nat\NatNat や zero\zerozero のように本体のない宣言済みの定数が δ 簡約されることはありません。β と同じく、このステップはどの部分項に対しても行えます。

定数は変数ではなく、束縛されることもないので、FV(c)=∅\FV(c) = \emptysetFV(c)=∅ であり、代入しても定数は変わりません。これ以降、簡約は β、δ と、後で導入する ι の三種類からなり、定義的等価（第 12 章）もこの三つすべてを考慮して定めます。

シグネチャの実体は、src/kernel.rs にある Kernel のフィールド decls: HashMap<String, Decl> です。Decl は型と DeclKind の組です。DeclKind には、その定数が Axiom（宣言のみで本体なし）なのか、Definition(body) なのか、帰納的宣言から生成される三種類（Inductive、Constructor、Recursor）のどれなのかを記録します。Kernel::axiom と Kernel::define は、上で述べた検査をしてから項目を追加します。infer は型を引いて T-Const を処理し、whnf は Definition を展開して δ を処理します。

自然数

Lean では、自然数は次のように宣言されます。

inductive Nat where
  | zero : Nat
  | succ (n : Nat) : Nat

この宣言は、自然数が zero\zerozero か、ある自然数 nnn の後続数 succ  n\suc\;nsuccn のどちらかとして作られることを表しています。たとえば 222 は succ  (succ  zero)\suc\;(\suc\;\zero)succ(succzero) です。私たちのカーネルでは、この宣言によって本体のない定数が三つ追加されます。

Nat:Sort 1,zero:Nat,succ:Nat→Nat.\Nat : \Sort{1}, \qquad \zero : \Nat, \qquad \suc : \Nat \to \Nat.Nat:Sort1,zero:Nat,succ:Nat→Nat.

zero\zerozero と succ\sucsucc を構成子（constructor）と呼びます。構成子は値を作るだけで計算はしないので、succ  (succ  zero)\suc\;(\suc\;\zero)succ(succzero) はすでに正規形であり、これがそのまま数 222 です。以下では zero\zerozero、succ  zero\suc\;\zerosucczero、succ  (succ  zero)\suc\;(\suc\;\zero)succ(succzero) などを 0,1,2,…0, 1, 2, \ldots0,1,2,… と書きます。

これで数は手に入りましたが、まだ計算には使えません。加法を定義するには zero\zerozero と succ  n\suc\;nsuccn を見分ける必要があるのに、今の項にできるのは引数を受け渡すことだけで、中身を調べられないからです。

計算: 加法

加法はどう定義すればよいでしょうか。第二引数についての再帰を使います。

add  m  zero=m,add  m  (succ  k)=succ  (add  m  k).\add\;m\;\zero = m, \qquad \add\;m\;(\suc\;k) = \suc\;(\add\;m\;k).addmzero=m,addm(succk)=succ(addmk).

この定義の形に注目してください。mmm を固定すると、関数 add  m\add\;maddm は二つのデータで決まります。zero\zerozero での値（ここでは mmm）と、kkk での値 rrr から succ  k\suc\;ksucck での値を作る方法（ここでは succ  r\suc\;rsuccr）です。この種の再帰を構造的再帰（structural recursion）と呼びます。構造的再帰で定義される関数 f:Nat→Cf : \Nat \to Cf:Nat→C は、どれも次の形をしています。

f  zero=z,f  (succ  k)=s  k  (f  k),f\;\zero = z, \qquad f\;(\suc\;k) = s\;k\;(f\;k),fzero=z,f(succk)=sk(fk),

ここで z:Cz : Cz:C、s:Nat→C→Cs : \Nat \to C \to Cs:Nat→C→C です。ステップ関数 sss は、kkk と再帰呼び出しの結果 f  kf\;kfk の両方を受け取ります。そこで、zzz と sss から fff を組み立てる定数を一つだけ用意し、最初に追加しておきます。

この定数には二つの計算規則を添えます。これを ι 規則（iota-rule）と呼び、中身は上の等式そのものです。

recC  z  s  zero  →ι  z,recC  z  s  (succ  n)  →ι  s  n  (recC  z  s  n).\mathsf{rec}_C\;z\;s\;\zero \;\iotared\; z, \qquad \mathsf{rec}_C\;z\;s\;(\suc\;n) \;\iotared\; s\;n\;(\mathsf{rec}_C\;z\;s\;n).recC​zszero→ι​z,recC​zs(succn)→ι​sn(recC​zsn).

これで加法は、再帰を含まない普通の定義として書けます。

add:Nat→Nat→Nat:=λ(m:Nat). λ(n:Nat). recNat  m  s  n,s=λ(k:Nat). λ(r:Nat). succ  r.\add : \Nat \to \Nat \to \Nat \mathrel{:=} \tLam{m}{\Nat}{\tLam{n}{\Nat}{\mathsf{rec}_{\Nat}\;m\;s\;n}}, \qquad s = \tLam{k}{\Nat}{\tLam{r}{\Nat}{\suc\;r}}.add:Nat→Nat→Nat:=λ(m:Nat).λ(n:Nat).recNat​msn,s=λ(k:Nat).λ(r:Nat).succr.

add  m  n\add\;m\;naddmn を m+nm + nm+n と書くことにすると、カーネルは 2+12 + 12+1 を δ、β、ι のステップだけで計算できます。下のエクスプローラでは、add\addadd の定義を読み込んだカーネルが頭部ステップを一つずつ実行していきます。

def add : Nat -> Nat -> Nat := fun (m : Nat) => fun (n : Nat) => Nat.rec1 (fun (_n : Nat) => Nat) m (fun (k : Nat) => fun (r : Nat) => Nat.succ r) n

各行が一つの頭部ステップに対応し、強調された部分が簡約基（redex）、次の行がその簡約結果です。数字を変えてみたり、文脈 n : Nat のもとで add Nat.zero n を試して再帰子が行き詰まる様子を確かめたりしてください。

ほかの関数も同じパターンで定義できます。たとえば double  (succ  k)=succ  (succ  (double  k))\mathit{double}\;(\suc\;k) = \suc\;(\suc\;(\mathit{double}\;k))double(succk)=succ(succ(doublek)) を満たす二倍関数は、

であり、double  2→succ  (succ  (double  1))→succ4  (double  0)→succ4  zero=4\mathit{double}\;2 \to \suc\;(\suc\;(\mathit{double}\;1)) \to \suc^4\;(\mathit{double}\;0) \to \suc^4\;\zero = 4double2→succ(succ(double1))→succ4(double0)→succ4zero=4 となります。

帰納型の定数に recC\mathsf{rec}_CrecC​ とその二つの規則を加えるだけで Nat\NatNat 上の構造的再帰関数はすべて表せるので、新しい再帰の仕組みは必要ありません。しかも一般の再帰と違い、ι ステップのたびに引数から succ\sucsucc が一つ外れるので、この再帰は必ず停止します。

プログラマの目から見ると、recC\mathsf{rec}_CrecC​ は自然数上の fold（畳み込み）です。リストの fold が nil を値に、cons を関数に置き換えるのと同じことをしています。fold は引数の構成子を一つずつ処理するので、無限ループに陥りません。while ループほど自由には書けない代わりに、どのプログラムも必ず停止します。論理にはこの性質が欠かせません。

証明: 帰納法

次は証明です。P:Nat→Sort 0P : \Nat \to \Sort{0}P:Nat→Sort0 について、性質 P  nP\;nPn がすべての nnn で成り立つことを示すとき、数学では帰納法を使います。つまり基底ケース（base case）P  zeroP\;\zeroPzero と帰納ステップ（step）Π(k:Nat). P  k→P  (succ  k)\tPi{k}{\Nat}{P\;k \to P\;(\suc\;k)}Π(k:Nat).Pk→P(succk) を証明します。帰納ステップの引数 P  kP\;kPk が帰納法の仮定（induction hypothesis）です。

Curry-Howard の見方では、Π(n:Nat). P  n\tPi{n}{\Nat}{P\;n}Π(n:Nat).Pn の証明とは、nnn を受け取って P  nP\;nPn の証明を返す関数 fff のことです。では、base:P  zero\mathit{base} : P\;\zerobase:Pzero と step\mathit{step}step からこの fff をどう作ればよいでしょうか。333 に対する証明は step  2  (step  1  (step  0  base))\mathit{step}\;2\;(\mathit{step}\;1\;(\mathit{step}\;0\;\mathit{base}))step2(step1(step0base)) であり、一般には

となります。これも構造的再帰関数で、上の add\addadd とまったく同じ形をしており、z=basez = \mathit{base}z=base、s=steps = \mathit{step}s=step に当たります。帰納法とは、証明を返す再帰のことです。

違いは結果の型にあります。add\addadd では nnn によらず結果の型は同じ CCC でしたが、証明では f  zero:P  zerof\;\zero : P\;\zerofzero:Pzero、f  1:P  1f\;1 : P\;1f1:P1 のように型が nnn に依存します。recC\mathsf{rec}_CrecC​ の型には固定された CCC が現れるので、このままでは帰納法を表せません。

試してみる

カーネルは、Nat\NatNat とその再帰子が宣言済みの状態で起動します（src/kernel.rs の Kernel::standard）。下のスクリプトでは加法を定義し、2+12 + 12+1 と 333 が定義的に等しいことをカーネルに確かめさせます。rfl は両辺を計算して、この等しさを確かめます。three を Nat.succ three に書き換えて、カーネルが拒否するところを見てください。

def add : Nat -> Nat -> Nat := fun (m : Nat) => fun (n : Nat) => Nat.rec1 (fun (_n : Nat) => Nat) m (fun (k : Nat) => fun (r : Nat) => Nat.succ r) n
def one : Nat := Nat.succ Nat.zero
def two : Nat := Nat.succ one
def three : Nat := Nat.succ two
# 両辺とも succ (succ (succ zero)) に計算されるので、refl でこれを証明できる。
goal Eq Nat (add two one) three
rfl
qed

ゴールにある Eq は等式型で、第 9 章 で宣言します。今のところは、Eq Nat a b を「a=ba = ba=b」、rfl を「両辺は同じものに計算される」と読んでおけば十分です。

Lean は、ここで説明したとおりに inductive 宣言から Nat.rec を生成します。その型は、束縛変数の名前と暗黙の引数を除けば図 7.1 と一致します。実行時には、Lean のコンパイラが再帰子を効率のよい機械の算術に置き換えます。利用者はパターンマッチで再帰関数を書けますが、エラボレータが裏でそれを再帰子にコンパイルするので、カーネルが目にするのは再帰子だけです。
