第 10 章

策略：交互式地构造证明项

Lean 用户很少手写第 9 章末尾那样的项。他们写策略脚本，即一系列命令，逐步构造项，同时系统显示还剩下什么要证。本章展示常见的策略如何在我们的系统中构造项，以及为什么它们都不需要被信任。

在 Lean 中，第 9 章的定理是这样证明的：

theorem zero_add (n : Nat) : 0 + n = n := by
  induction n with
  | zero => rfl
  | succ k ih => rw [Nat.add_succ, ih]

每个策略都是一个小程序，构造证明项的一部分。策略在内核之外运行。它们的输出是普通的项，内核用算法 5.1 像检查其他任何项一样检查它。

目标与证明状态

目标 ⟨Γ⊢?m:T⟩\goal{\Gamma}{\hole{m}}{T}⟨Γ⊢?m​:T⟩ 要求在上下文 Γ\GammaΓ 中给出一个类型为 TTT 的项。洞 ?m\hole{m}?m​ 代表尚待找到的项；Lean 称之为元变量。证明状态是一个目标列表，连同一个部分证明项，即可能含有洞的项。

要证明 TTT，我们从部分项 ?0\hole{0}?0​ 和唯一的目标 ⟨⋅⊢?0:T⟩\goal{\cdot}{\hole{0}}{T}⟨⋅⊢?0​:T⟩ 出发。策略作用于第一个目标 ⟨Γ⊢?m:T⟩\goal{\Gamma}{\hole{m}}{T}⟨Γ⊢?m​:T⟩。它给 ?m\hole{m}?m​ 赋值一个可能含有新鲜洞的项，并把该目标替换为每个新鲜洞对应的一个新目标。当没有目标剩下时，部分项不再含洞，内核对照 TTT 检查它。洞可以位于绑定子之下，如 λ(x:A). ?1\tLam{x}{A}{\hole{1}}λ(x:A).?1​ 中的 ?1\hole{1}?1​，填入它的项可以使用那些约束变量。这就是每个目标都带有自己的上下文的原因。

每个策略都必须确保它的赋值在 Γ\GammaΓ 中具有类型 TTT，前提是每个新鲜洞随后都被填入其目标所述类型的项。我们写 ⟨Γ⊢?m:T⟩⇝new goals\goal{\Gamma}{\hole{m}}{T} \leadsto \text{new goals}⟨Γ⊢?m​:T⟩⇝new goals，后跟赋值。

第一个例子

脚本 examples/identity.leanmini 证明第 1 章开头的例子。下面的浏览器逐条命令运行它。

goal forall (P : Sort 0), P -> P
intro P
intro p
exact p
qed

用按钮或方向键逐步执行。中间面板是每条命令之后的目标列表，右侧面板是部分证明项，当前目标的洞高亮显示。三个面板始终一致：策略改变目标，正是因为它给某个洞赋了一个项。

单有目标列表是不够的：intro p 之后，目标 PPP 不记得它的解必须包在两个 λ\lambdaλ 里面。部分项记录了这一点。

基本策略

intro x。 若 TTT 规范化为 Π\PiΠ 类型，该策略把它的参数移入上下文：

⟨Γ⊢?m:Π(y:A). B⟩  ⇝  ⟨Γ,x:A⊢?1:B[y↦x]⟩,?m:=λ(x:A). ?1.\goal{\Gamma}{\hole{m}}{\tPi{y}{A}{B}} \;\leadsto\; \goal{\Gamma, x : A}{\hole{1}}{\subst{B}{y}{x}}, \qquad \hole{m} \mathrel{:=} \tLam{x}{A}{\hole{1}}.⟨Γ⊢?m​:Π(y:A).B⟩⇝⟨Γ,x:A⊢?1​:B[y↦x]⟩,?m​:=λ(x:A).?1​.

exact t。 该策略用给定的项关闭目标：

change T'。 该策略把目标替换为一个定义相等的目标：

⟨Γ⊢?m:T⟩  ⇝  ⟨Γ⊢?1:T′⟩,?m:=?1,\goal{\Gamma}{\hole{m}}{T} \;\leadsto\; \goal{\Gamma}{\hole{1}}{T'}, \qquad \hole{m} \mathrel{:=} \hole{1},⟨Γ⊢?m​:T⟩⇝⟨Γ⊢?1​:T′⟩,?m​:=?1​,

归纳

设 n:Natn : \Natn:Nat 是 Γ\GammaΓ 中的变量，且 Γ⊢T:Sort u\Gamma \vdash T : \Sort{u}Γ⊢T:Sortu。策略 induction n 把目标中的 nnn 抽象出来形成 motive，并为每个构造子产生一个目标：

  • motive 绑定一个新鲜的名字 zzz 而不是 nnn：由于 nnn 已在 Γ\GammaΓ 中，写 λ(n:Nat). T\tLam{n}{\Nat}{T}λ(n:Nat).T 会遮蔽它，这正是第 11 章的陷阱。同样，kkk 和 ih\mathit{ih}ih 也必须新鲜。（我们的实现把 motive 的变量命名为 ind_x，当 n 已被占用时把后继的字段命名为 k，把假设命名为 ih。）
  • motive 的层级 uuu 来自目标的类型，由 InferSort\InferSortInferSort 求得。对命题它是 000，而 Nat.rec0\NatRec{0}Nat.rec0​ 就是归纳。
  • 如果另一个假设提及 nnn，例如 h:n=2h : n = 2h:n=2，新目标仍然含有关于原来那个 nnn 的 hhh，而 ih\mathit{ih}ih 对它一无所言。此时目标是正确的，但可能无法证明。Lean 的 induction 会先把这类假设移回目标（回退它们），使之成为 motive 的一部分。我们的版本要求后面的假设都不提及 nnn，否则报告“induction: revert dependent hypotheses first”。

该实现并非专门针对 Nat\NatNat。它适用于任何没有索引的归纳类型：它从签名读出递归子的类型，为每个构造子剥下一个小前提，并把每个小前提变成一个目标，其上下文包含该构造子的字段和归纳假设。脚本 examples/generic-list.leanmini 把它用于用户声明的列表类型。

重写

设 h:Equ  A  a  bh : \Eq{u}\;A\;a\;bh:Equ​Aab，并设目标 TTT 是命题。策略 rw h 分三步把目标中的 aaa 替换为 bbb。

  1. 抽象。 选一个新鲜的 xxx，令 CCC 为把 TTT 中每处 aaa 替换为 xxx 所得的结果。出现位置按 α 等价而非按转换来查找；位于某个绑定子之下、且该绑定子绑定了 aaa 的自由变量的出现会被跳过，因为在那里它指的是别的东西。
  2. 检查 motive。 检查 Γ,x:A⊢C:Sort 0\Gamma, x : A \vdash C : \Sort{0}Γ,x:A⊢C:Sort0。这一步可能失败，见下文。
  3. 构造项。 新目标是 C[x↦b]\subst{C}{x}{b}C[x↦b]，即把 aaa 替换为 bbb 后的目标：
    ⟨Γ⊢?m:T⟩  ⇝  ⟨Γ⊢?1:C[x↦b]⟩,?m:=Eq.ndrecu,0  A  a  (λ(x:A). C→T)  (λ(p:T). p)  b  h  ?1.\goal{\Gamma}{\hole{m}}{T} \;\leadsto\; \goal{\Gamma}{\hole{1}}{\subst{C}{x}{b}}, \qquad \hole{m} \mathrel{:=} \EqRec{u,0}\;A\;a\;(\tLam{x}{A}{C \to T})\;(\tLam{p}{T}{p})\;b\;h\;\hole{1}.⟨Γ⊢?m​:T⟩⇝⟨Γ⊢?1​:C[x↦b]⟩,?m​:=Eq.ndrecu,0​Aa(λ(x:A).C→T)(λ(p:T).p)bh?1​.

策略是 src/proof.rs 中 ProofState 的方法。部分证明项是一个 Template（src/template.rs），即带有 Hole(i) 节点的项；materialize 代入各个解，若有洞未解则失败。ProofState::replace 执行一次赋值：它记录当前目标的解，并把新目标拼接到最前面。intro、exact、apply、change、rfl、induction 和 rw 各自遵循上面的描述；rw 用 replace_exact 做第 1 步、用 check_transport 做第 2 步；finish 就是 qed：它实体化项，并对照原始目标调用 Kernel::check。

示例：用策略证明 0 + n = n

在我们的系统中，第 9 章的证明变成下面的脚本，它是 examples/zero-add.leanmini 加上 add\addadd 的定义（脚本把 0+n0 + n0+n 写作 add Nat.zero n）。

def add : Nat -> Nat -> Nat := fun (m : Nat) => fun (n : Nat) => Nat.rec1 (fun (_n : Nat) => Nat) m (fun (k : Nat) => fun (r : Nat) => Nat.succ r) n
goal forall (n : Nat), Eq Nat (add Nat.zero n) n
intro n
induction n
rfl
change Eq Nat (Nat.succ (add Nat.zero k)) (Nat.succ k)
rw ih
rfl
qed

观察部分项如何增长：induction n 插入带两个洞的 Nat.rec0\NatRec{0}Nat.rec0​，rfl 填上第一个，change 不动项、只改写目标，rw ih 插入传输，留下一个洞给最后的 rfl。删掉 change 那一行再运行脚本，就能看到 rw 找不到它的左边。

# 对第二个参数递归的加法：
#   add m zero     = m
#   add m (succ k) = succ (add m k)
def add : Nat -> Nat -> Nat := fun (m : Nat) => fun (n : Nat) => Nat.rec1 (fun (_n : Nat) => Nat) m (fun (k : Nat) => fun (r : Nat) => Nat.succ r) n

# add zero n = n 不是定义相等，所以需要对 n 归纳。
goal forall (n : Nat), Eq Nat (add Nat.zero n) n
intro n
induction n
# 基础情形：add zero zero 归约为 zero。
rfl
# 归纳步骤：把 add zero (succ k) 展开为 succ (add zero k)，然后使用 ih。
change Eq Nat (Nat.succ (add Nat.zero k)) (Nat.succ k)
rw ih
rfl
qed

这个项与第 9 章手写的项有两处不同：由于 intro，它以 λ(n:Nat). …  n\tLam{n}{\Nat}{\ldots\;n}λ(n:Nat).…n 开头；它的归纳步骤使用 rw 构造的 motive。两者都是同一命题的证明，内核不在乎收到的是哪一个。试着在演练场中删掉 change 那一行，读一读 rw 给出的错误。

为什么策略不需要被信任

内核检查最终的项，所以策略不必正确，系统也能保持可靠。有错误的策略可能失败，也可能产生类型不正确的项，后者会被内核拒绝；它不可能让内核接受一个假定理。策略自己执行的检查，如 exact 中的 Check\CheckCheck 或 rw 中的 motive 检查，只是为了尽早、清楚地报告错误。

因此系统的可信部分很小：算法 5.1、第三部分的归约与比较函数，以及第 8 章构造签名的过程。src/proof.rs 和 src/syntax.rs 中的一切都在它之外。

Lean 的策略框架比这里勾勒的丰富得多。它有通过合一求解的元变量，有填入隐式参数并展开 0 + n 这类记法的繁饰器，有能回退依赖假设并处理带索引的族的 induction，还有 simp 这样的自动化。所有这些都在不可信的一侧：Lean 的内核和我们的一样，只会看到完整的项 [de Moura and Ullrich 2021]。

要点回顾

  • 证明状态是一个目标列表加上一个带洞的部分项。策略给第一个洞赋值一个项，并为每个新鲜洞开一个新目标。
  • intro 构造 λ\lambdaλ，exact 填入一个项，apply 构造一个以洞为参数的应用，change 使用 T-Conv，rfl 使用 refl\refl{}refl​。
  • induction 把变量抽象成 motive 并应用递归子；rw 把左边抽象成 motive 并应用传输。
  • 内核重新检查完整的项，所以策略在可信基之外。
