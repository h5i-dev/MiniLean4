逐步示例

本章在几个小项上手工运行算法 5.1，并把每一次运行与类型规则对应起来。所选的例子覆盖了算法的各项工作：构造推导、抓出错误的证明、使用假设、实例化全称命题，以及在类型内部进行计算。下面的每一条追踪都可以在演练场中用内核复现。

要验证 ttt 是定理 TTT 的证明，内核调用 Check(⋅,t,T)\Check(\cdot, t, T)Check(⋅,t,T)；它调用 Infer(⋅,t)\Infer(\cdot, t)Infer(⋅,t)，再把结果与 TTT 作比较。追踪展示了 Infer\InferInfer 发出的递归调用，以及每次调用所对应的类型规则。展开或折叠各节点即可跟随递归过程。

⋅⊢Sort 0:Sort 1;(T-Sort)Γ1⊢P:Sort 0;(T-Var)Γ2⊢h:P;(T-Var)Γ1⊢λ(h:P). h:P→P;(T-Lam)⋅⊢λ(P:Sort 0). λ(h:P). h:Π(P:Sort 0). P→P;(T-Lam)\dfrac{ \dfrac{}{\cdot \vdash \Sort{0} : \Sort{1}}\rulename{T-Sort} \qquad \dfrac{ \dfrac{}{\Gamma_1 \vdash P : \Sort{0}}\rulename{T-Var} \qquad \dfrac{}{\Gamma_2 \vdash h : P}\rulename{T-Var} }{\Gamma_1 \vdash \tLam{h}{P}{h} : P \to P}\rulename{T-Lam} }{\cdot \vdash \tLam{P}{\Sort{0}}{\tLam{h}{P}{h}} : \tPi{P}{\Sort{0}}{P \to P}}\rulename{T-Lam}⋅⊢λ(P:Sort0).λ(h:P).h:Π(P:Sort0).P→P⋅⊢Sort0:Sort1​;(T-Sort)Γ1​⊢λ(h:P).h:P→PΓ1​⊢P:Sort0​;(T-Var)Γ2​⊢h:P​;(T-Var)​;(T-Lam)​;(T-Lam)

一个错误的证明

假设用户声称 t=λ(P:Sort 0). λ(h:P). Pt = \tLam{P}{\Sort{0}}{\tLam{h}{P}{P}}t=λ(P:Sort0).λ(h:P).P 证明了 Π(P:Sort 0). P→P\tPi{P}{\Sort{0}}{P \to P}Π(P:Sort0).P→P。它的体返回的是命题 PPP，而不是证明 hhh。内核调用 Check(⋅,t,Π(P:Sort 0). P→P)\Check(\cdot, t, \tPi{P}{\Sort{0}}{P \to P})Check(⋅,t,Π(P:Sort0).P→P)，后者先调用 Infer\InferInfer。各次调用与上面相同，只是最后一次 Infer(Γ2,P)\Infer(\Gamma_2, P)Infer(Γ2​,P) 返回 Sort 0\Sort{0}Sort0。于是 Infer\InferInfer 成功，结果为

Infer(⋅,t)  =  Π(P:Sort 0). Π(h:P). Sort 0.\Infer(\cdot, t) \;=\; \tPi{P}{\Sort{0}}{\tPi{h}{P}{\Sort{0}}}.Infer(⋅,t)=Π(P:Sort0).Π(h:P).Sort0.

项 ttt 是良类型的，却不能证明所声称的命题。Check\CheckCheck 比较这两个类型时，发现两边都无法继续归约，重命名约束变量也不能使它们相等：最内层的体一边是 Sort 0\Sort{0}Sort0，另一边是 PPP。因此 IsDefEq\IsDefEqIsDefEq 失败，Check\CheckCheck 报告类型不匹配。（第 11 章用 IsDefEq\IsDefEqIsDefEq 的算法逐步重演这次比较。）

这个错误之所以能被发现，只是因为用户声明了要证明的命题。一个只运行 Infer\InferInfer 的内核会接受 ttt，并悄悄给它分配一个不同的类型。这就是为什么每个脚本都以 goal 开头，也是为什么 qed 要对照它来检查。

goal forall (P : Sort 0), P -> P
exact fun (P : Sort 0) => fun (h : P) => P
qed

项是良类型的，并不表示它证明了所声称的定理。每个通过 Infer\InferInfer 的闭项都有一个推断出的类型；内核还须确认它与定理所声称的类型一致。策略（第 10 章）会在构造项之前固定要证明的命题。

使用假设：肯定前件

到目前为止的例子从未应用过函数。考虑检查

t=λ(P:Sort 0). λ(Q:Sort 0). λ(f:P→Q). λ(p:P). f  pagainstΠ(P:Sort 0). Π(Q:Sort 0). (P→Q)→P→Q,t = \tLam{P}{\Sort{0}}{\tLam{Q}{\Sort{0}}{\tLam{f}{P \to Q}{\tLam{p}{P}{f\;p}}}} \quad\text{against}\quad \tPi{P}{\Sort{0}}{\tPi{Q}{\Sort{0}}{(P \to Q) \to P \to Q}},t=λ(P:Sort0).λ(Q:Sort0).λ(f:P→Q).λ(p:P).fpagainstΠ(P:Sort0).Π(Q:Sort0).(P→Q)→P→Q,

它说的是“如果 PPP 蕴涵 QQQ 且 PPP 成立，那么 QQQ 成立”。四个 λ\lambdaλ 像之前一样把上下文扩展为 Γ=P:Sort 0,  Q:Sort 0,  f:P→Q,  p:P\Gamma = P : \Sort{0},\; Q : \Sort{0},\; f : P \to Q,\; p : PΓ=P:Sort0,Q:Sort0,f:P→Q,p:P。体 f  pf\;pfp 进入 Infer\InferInfer 的应用分支：

  • Infer(Γ,  f  p)\Infer(\Gamma,\; f\;p)Infer(Γ,fp) T-App
    • Infer(Γ,  f)\Infer(\Gamma,\; f)Infer(Γ,f) 返回 P→QP \to QP→Q，即 Π(_:P). Q\tPi{\_}{P}{Q}Π(_:P).Q。Whnf\WhnfWhnf 保持它不变，它是一个 Π\PiΠ T-Var
    • Check(Γ,  p,  P)\Check(\Gamma,\; p,\; P)Check(Γ,p,P) 成功，因为 p:Pp : Pp:P 在 Γ\GammaΓ 中 T-Var, T-Conv
    • 返回 Q[_↦p]=Q\subst{Q}{\_}{p} = QQ[_↦p]=Q。名字 _\__ 不出现在 QQQ 中，所以替换什么也不做

如果用户写的是 f  ff\;fff，第二步就会调用 Check(Γ,f,P)\Check(\Gamma, f, P)Check(Γ,f,P)，它会失败，因为 P→QP \to QP→Q 不是 PPP：在这里函数不能喂给它自己。试一试：把下面的 f p 改成 f f。

goal forall (P : Sort 0), forall (Q : Sort 0), (P -> Q) -> P -> Q
exact fun (P : Sort 0) => fun (Q : Sort 0) => fun (f : P -> Q) => fun (p : P) => f p
qed

实例化全称命题

在依赖应用中，T-App 里的替换会做实际的工作。令 id=λ(P:Sort 0). λ(h:P). h\mathit{id} = \tLam{P}{\Sort{0}}{\tLam{h}{P}{h}}id=λ(P:Sort0).λ(h:P).h 为第一个例子中的证明，并令 Γ=Q:Sort 0\Gamma = Q : \Sort{0}Γ=Q:Sort0。那么 Infer(Γ,id  Q)\Infer(\Gamma, \mathit{id}\;Q)Infer(Γ,idQ)：

  • Infer(Γ,  id  Q)\Infer(\Gamma,\; \mathit{id}\;Q)Infer(Γ,idQ) T-App
    • Infer(Γ,  id)\Infer(\Gamma,\; \mathit{id})Infer(Γ,id) 返回 Π(P:Sort 0). Π(h:P). P\tPi{P}{\Sort{0}}{\tPi{h}{P}{P}}Π(P:Sort0).Π(h:P).P，已经是一个 Π\PiΠ T-Lam
    • Check(Γ,  Q,  Sort 0)\Check(\Gamma,\; Q,\; \Sort{0})Check(Γ,Q,Sort0) 成功 T-Var
    • 返回 (Π(h:P). P)[P↦Q]=Π(h:Q). Q\subst{(\tPi{h}{P}{P})}{P}{Q} = \tPi{h}{Q}{Q}(Π(h:P).P)[P↦Q]=Π(h:Q).Q，即 Q→QQ \to QQ→Q

从逻辑上看，这是 ∀\forall∀ 消去：从“每个命题都蕴涵自身”得到“QQQ 蕴涵 QQQ”。结果的类型取决于参数 QQQ 的值，这正是依赖 Π\PiΠ 类型所表达的东西，也是 T-App 要做替换的原因。在浏览器中，id\mathit{id}id 是一个已定义的常量，QQQ 来自上下文；T-App 节点上的注释记录了这次替换。

def id : forall (P : Sort 0), P -> P := fun (P : Sort 0) => fun (h : P) => h

转换

回忆第 3 章中的 Id=λ(X:Sort 0). X\mathit{Id} = \tLam{X}{\Sort{0}}{X}Id=λ(X:Sort0).X。核心系统没有定义，所以 Id  P\mathit{Id}\;PIdP 是项 (λ(X:Sort 0). X)  P(\tLam{X}{\Sort{0}}{X})\;P(λ(X:Sort0).X)P 的简写。考虑检查

t=λ(P:Sort 0). λ(h:Id  P). hagainstΠ(P:Sort 0). P→P.t = \tLam{P}{\Sort{0}}{\tLam{h}{\mathit{Id}\;P}{h}} \quad\text{against}\quad \tPi{P}{\Sort{0}}{P \to P}.t=λ(P:Sort0).λ(h:IdP).hagainstΠ(P:Sort0).P→P.

Infer\InferInfer 首先检查标注 Id  P\mathit{Id}\;PIdP 是一个类型。InferSort(Γ1,Id  P)\InferSort(\Gamma_1, \mathit{Id}\;P)InferSort(Γ1​,IdP) 进入 Infer\InferInfer 的应用分支：函数 λ(X:Sort 0). X\tLam{X}{\Sort{0}}{X}λ(X:Sort0).X 的类型是 Π(X:Sort 0). Sort 0\tPi{X}{\Sort{0}}{\Sort{0}}Π(X:Sort0).Sort0，参数 PPP 通过 Check(Γ1,P,Sort 0)\Check(\Gamma_1, P, \Sort{0})Check(Γ1​,P,Sort0)，结果是 Sort 0[X↦P]=Sort 0\subst{\Sort{0}}{X}{P} = \Sort{0}Sort0[X↦P]=Sort0。所以 Id  P\mathit{Id}\;PIdP 是一个类型，而且是一个命题。接着体 hhh 的类型是 Id  P\mathit{Id}\;PIdP，于是

Infer(⋅,t)  =  Π(P:Sort 0). Π(h:Id  P). Id  P.\Infer(\cdot, t) \;=\; \tPi{P}{\Sort{0}}{\tPi{h}{\mathit{Id}\;P}{\mathit{Id}\;P}}.Infer(⋅,t)=Π(P:Sort0).Π(h:IdP).IdP.

仅靠给约束变量改名，无法把它变成 Π(P:Sort 0). P→P\tPi{P}{\Sort{0}}{P \to P}Π(P:Sort0).P→P。但 IsDefEq\IsDefEqIsDefEq 在比较之前会先计算两边，而 Id  P→βP\mathit{Id}\;P \betared PIdP→β​P，所以推断出的类型变为 Π(P:Sort 0). Π(h:P). P\tPi{P}{\Sort{0}}{\tPi{h}{P}{P}}Π(P:Sort0).Π(h:P).P，比较像第一个例子一样成功。在类型规则中，这一步是在推导根部使用一次 T-Conv：

⋅⊢t:Π(P:Sort 0). Id  P→Id  P⋅⊢Π(P:Sort 0). P→P:Sort 0Π(P:Sort 0). Id  P→Id  P≡Π(P:Sort 0). P→P⋅⊢t:Π(P:Sort 0). P→P;(T-Conv)\dfrac{ \cdot \vdash t : \tPi{P}{\Sort{0}}{\mathit{Id}\;P \to \mathit{Id}\;P} \qquad \cdot \vdash \tPi{P}{\Sort{0}}{P \to P} : \Sort{0} \qquad \tPi{P}{\Sort{0}}{\mathit{Id}\;P \to \mathit{Id}\;P} \conv \tPi{P}{\Sort{0}}{P \to P} }{\cdot \vdash t : \tPi{P}{\Sort{0}}{P \to P}}\rulename{T-Conv}⋅⊢t:Π(P:Sort0).P→P⋅⊢t:Π(P:Sort0).IdP→IdP⋅⊢Π(P:Sort0).P→P:Sort0Π(P:Sort0).IdP→IdP≡Π(P:Sort0).P→P​;(T-Conv)

算法从不决定在哪里应用 T-Conv。正如第 5 章所述，转换隐藏在对 IsDefEq\IsDefEqIsDefEq 的调用中，而它只在比较两个类型的地方运行。

实时推导显示了计算发生的位置：标注 Id  P\mathit{Id}\;PIdP 由 T-App 检查，推断出的类型一直含有 Id  P\mathit{Id}\;PIdP，直到 Check\CheckCheck 把它与目标作比较。

# h 的标注是 (fun (X : Sort 0) => X) P，它计算到 P。
goal forall (P : Sort 0), P -> P
exact fun (P : Sort 0) => fun (h : (fun (X : Sort 0) => X) P) => h
qed

练习

像上面的例子那样，手工对这些项运行 Infer\InferInfer，是检验自己是否理解该算法的好办法。每一题也都可以在演练场中尝试。

证明 Π(P:Sort 0). Π(Q:Sort 0). P→Q→P\tPi{P}{\Sort{0}}{\tPi{Q}{\Sort{0}}{P \to Q \to P}}Π(P:Sort0).Π(Q:Sort0).P→Q→P。

解答

一个答案是 λ(P:Sort 0). λ(Q:Sort 0). λ(p:P). λ(q:Q). p\tLam{P}{\Sort{0}}{\tLam{Q}{\Sort{0}}{\tLam{p}{P}{\tLam{q}{Q}{p}}}}λ(P:Sort0).λ(Q:Sort0).λ(p:P).λ(q:Q).p。这个证明从不使用 qqq：系统允许假设不被使用。

证明蕴涵是传递的： Π(P:Sort 0). Π(Q:Sort 0). Π(R:Sort 0). (P→Q)→(Q→R)→P→R\tPi{P}{\Sort{0}}{\tPi{Q}{\Sort{0}}{\tPi{R}{\Sort{0}}{(P \to Q) \to (Q \to R) \to P \to R}}}Π(P:Sort0).Π(Q:Sort0).Π(R:Sort0).(P→Q)→(Q→R)→P→R。

解答

一个答案以 λ(f:P→Q). λ(g:Q→R). λ(p:P). g  (f  p)\tLam{f}{P \to Q}{\tLam{g}{Q \to R}{\tLam{p}{P}{g\;(f\;p)}}}λ(f:P→Q).λ(g:Q→R).λ(p:P).g(fp) 结尾；它两次用到应用分支，先是 f  p:Qf\;p : Qfp:Q，然后是 g  (f  p):Rg\;(f\;p) : Rg(fp):R。

goal forall (P : Sort 0), forall (Q : Sort 0), forall (R : Sort 0), (P -> Q) -> (Q -> R) -> P -> R
exact fun (P : Sort 0) => fun (Q : Sort 0) => fun (R : Sort 0) => fun (f : P -> Q) => fun (g : Q -> R) => fun (p : P) => g (f p)
qed

解释为什么 λ(P:Sort 0). λ(h:P). h  h\tLam{P}{\Sort{0}}{\tLam{h}{P}{h\;h}}λ(P:Sort0).λ(h:P).hh 会被拒绝，以及在算法 5.1 的哪一行被拒绝。

解答

在上下文 P:Sort 0,h:PP : \Sort{0}, h : PP:Sort0,h:P 中，体 h  hh\;hhh 进入应用分支。Infer\InferInfer 对函数 hhh 返回 PPP，而 Whnf(P)=P\Whnf(P) = PWhnf(P)=P 是一个变量，不是 Π\PiΠ。算法在 else fail "not a function" 这一行失败：PPP 的证明不是可以被应用的东西。在 Rust 中，错误信息是 application of non-function。

要点回顾

  • 一次 Infer\InferInfer 的运行对应一棵推导树；每一次返回的调用就是一个节点。
  • Infer\InferInfer 可以在一个并未证明所声明定理的项上成功。对照所声明的类型运行 Check\CheckCheck 才能抓出这种情况。
  • T-App 是使用假设（肯定前件）的地方，也是实例化全称命题（替换进 Π\PiΠ 的体）的地方。
  • 类型内部的计算完全由 IsDefEq\IsDefEqIsDefEq 处理；算法从不选择在哪里应用 T-Conv。
