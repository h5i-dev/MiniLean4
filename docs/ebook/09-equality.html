Chapter 9

Equality Is an Inductive Type Too

To state facts about numbers, such as 0+n=n0 + n = n0+n=n, we need a way to express equality. Although it might seem to require special rules built into the kernel, equality is another inductive type generated by the recipe of Chapter 8. Its recursor lets us turn a fact about aaa into a fact about bbb. This chapter declares the type, explains how it differs from definitional equality, and proves the book's first substantial theorem.

The declaration

In Lean, equality is declared as

inductive Eq {A : Sort u} (a : A) : A -> Prop where
  | refl : Eq a a

For a,b:Aa, b : Aa,b:A, the type Equ  A  a  b\Eq{u}\;A\;a\;bEqu​Aab is the proposition that aaa and bbb are equal; when AAA is Nat\NatNat we write it a=ba = ba=b. In the terms of Chapter 8, AAA and aaa are parameters and bbb is an index:

Equ:Π(A:Sort u). A→A→Sort 0,reflu:Π(A:Sort u). Π(a:A). Equ  A  a  a.\Eq{u} : \tPi{A}{\Sort{u}}{A \to A \to \Sort{0}}, \qquad \refl{u} : \tPi{A}{\Sort{u}}{\tPi{a}{A}{\Eq{u}\;A\;a\;a}}.Equ​:Π(A:Sortu).A→A→Sort0,reflu​:Π(A:Sortu).Π(a:A).Equ​Aaa.

The only constructor reflu\refl{u}reflu​ has no fields, and its index term is aaa: it can only prove equations whose two sides are the same aaa. So Eq\Eq{}Eq​ is an inductive family like Vec\mathsf{Vec}Vec, not a single type. The left side is fixed by the parameter; the right side varies, and the constructor pins it to the left side.

Why is one constructor enough? Because the declaration does not define when two things are equal; it says how proofs of equality can be built, and the only way is to observe that something equals itself. Everything else, such as symmetry, transitivity, and substitution, is derived from the recursor, which says what can be done with such a proof once one has it.

The recursor: transport

Informally, the recursor of Eq\Eq{}Eq​ says: if a=ba = ba=b, then whatever holds of aaa holds of bbb. This is Leibniz's principle, and in its most common form it reads

Eq.ndrecu,v:Π(A:Sort u). Π(a:A). Π(M:A→Sort v). M  a→Π(b:A). Equ  A  a  b→M  b.\EqRec{u,v} : \tPi{A}{\Sort{u}}{\tPi{a}{A}{\tPi{M}{A \to \Sort{v}}{M\;a \to \tPi{b}{A}{\Eq{u}\;A\;a\;b \to M\;b}}}}.Eq.ndrecu,v​:Π(A:Sortu).Π(a:A).Π(M:A→Sortv).Ma→Π(b:A).Equ​Aab→Mb.

Given a property MMM of elements of AAA, evidence m:M  am : M\;am:Ma, and a proof hhh that a=ba = ba=b, it returns evidence of M  bM\;bMb. We say that it transports mmm along hhh. Its computation rule says that transporting along refl\refl{}refl​ does nothing:

Eq.ndrecu,v  A  a  M  m  b  (reflu  A  c)  →  m.\EqRec{u,v}\;A\;a\;M\;m\;b\;(\refl{u}\;A\;c) \;\to\; m.Eq.ndrecu,v​AaMmb(reflu​Ac)→m.

The version the general recipe of Chapter 8 generates is slightly more general, and Eq.ndrec\EqRec{}Eq.ndrec​ is a definition built from it.

For example, suppose P:Nat→Sort 0P : \Nat \to \Sort{0}P:Nat→Sort0, a,b:Nata, b : \Nata,b:Nat, h:a=bh : a = bh:a=b, and pa:P  a\mathit{pa} : P\;apa:Pa. Choosing the motive M=PM = PM=P gives

Eq.ndrec1,0  Nat  a  P  pa  b  h  :  P  b.\EqRec{1,0}\;\Nat\;a\;P\;\mathit{pa}\;b\;h \;:\; P\;b.Eq.ndrec1,0​NataPpabh:Pb.

This one line is the logical content of rewriting: a fact about aaa becomes a fact about bbb. The rw tactic of Chapter 10 builds such terms automatically.

In Lean, the type argument of Eq is implicit, written {A} in the declaration, and the elaborator fills it in, so users write Eq a b or a = b. Our kernel sees only fully explicit terms, so we write every argument; filling them in is the job of the layer above the kernel. In the script language the constants are Eq, Eq.refl, and the dependent recursors Eq.rec0 and Eq.rec1; the non-dependent Eq.ndrec\EqRec{}Eq.ndrec​ is not predeclared, but it is a two-line definition, shown in the playground below. Since there is no universe polymorphism, the kernel declares Eq once, at A:Sort 1A : \Sort{1}A:Sort1, which covers Nat\NatNat and every user-declared data type; equality between proofs is not available.

Definitional versus propositional equality

There are now two notions of equality, and keeping them apart is essential to understanding how a proof assistant behaves.

  • Definitional equality ≡\conv≡ is decided by the kernel, by computation. It is a judgment about terms, not a type; no proof object is involved.
  • Propositional equality Eq\Eq{}Eq​ is a type. Its proofs are terms, and finding one may require real reasoning, such as induction.

The constructor refl\refl{}refl​ connects them: by T-Conv, reflu  A  a:Equ  A  a  b\refl{u}\;A\;a : \Eq{u}\;A\;a\;breflu​Aa:Equ​Aab whenever a≡ba \conv ba≡b. So every definitional equality yields a propositional one for free. The converse fails, and the standard example is the two halves of n+0=nn + 0 = nn+0=n and 0+n=n0 + n = n0+n=n. With the definition of add\addadd from Chapter 7 and sss its step function,

n+0  →δβ  Nat.rec1  (λ(_:Nat). Nat)  n  s  zero  →ι  n,n + 0 \;\to_{\delta\beta}\; \NatRec{1}\;(\tLam{\_}{\Nat}{\Nat})\;n\;s\;\zero \;\iotared\; n,n+0→δβ​Nat.rec1​(λ(_:Nat).Nat)nszero→ι​n,

so refl1  Nat  n:n+0=n\refl{1}\;\Nat\;n : n + 0 = nrefl1​Natn:n+0=n, and Lean proves this by rfl. In contrast,

0+n  →δβ  Nat.rec1  (λ(_:Nat). Nat)  0  s  n0 + n \;\to_{\delta\beta}\; \NatRec{1}\;(\tLam{\_}{\Nat}{\Nat})\;0\;s\;n0+n→δβ​Nat.rec1​(λ(_:Nat).Nat)0sn

is stuck: nnn is a variable, and the iota-rules fire only on zero\zerozero and succ\sucsucc. So 0+n=n0 + n = n0+n=n is not provable by refl\refl{}refl​ and needs induction.

The reduction explorer shows both computations with nnn as a variable in the context. The first reaches nnn; the second stops with the recursor waiting for a constructor it will never get.

def add : Nat -> Nat -> Nat := fun (m : Nat) => fun (n : Nat) => Nat.rec1 (fun (_n : Nat) => Nat) m (fun (k : Nat) => fun (r : Nat) => Nat.succ r) n

# n + 0 = n holds by computation: the recursor sees the constructor zero.
goal forall (n : Nat), Eq Nat (add n Nat.zero) n
intro n
rfl
qed

# 0 + n = n does not: the recursor is stuck on the variable n.
goal forall (n : Nat), Eq Nat (add Nat.zero n) n
intro n
rfl

Which equations hold by rfl depends on how a function was defined, not on what it computes. Addition by recursion on the second argument makes n+0=nn + 0 = nn+0=n definitional and 0+n=n0 + n = n0+n=n propositional; recursion on the first argument would swap them. Lean users meet this constantly: rfl closes a goal or does not depending on the direction of recursion in the definitions involved.

Example: proving 0 + n = n

We prove Π(n:Nat). 0+n=n\tPi{n}{\Nat}{0 + n = n}Π(n:Nat).0+n=n by induction, using Nat.rec0\NatRec{0}Nat.rec0​ with the motive M0=λ(n:Nat). 0+n=nM_0 = \tLam{n}{\Nat}{0 + n = n}M0​=λ(n:Nat).0+n=n.

Base. We need M0  0M_0\;0M0​0, which is convertible to 0+0=00 + 0 = 00+0=0. Since 0+00 + 00+0 computes to 000, the term refl1  Nat  0\refl{1}\;\Nat\;0refl1​Nat0 works.

Writing such terms by hand is tedious, and finding the right motive is the hard part: the motive NNN had to mention bbb in exactly one of the two places where 0+k0 + k0+k occurs. Tactics (Chapter 10) automate both the bookkeeping and the choice of motive.

Changes to the kernel

Little changed to get from propositional logic to arithmetic with equality. Infer\InferInfer gained a case for constants, which looks up the type in Σ\SigmaΣ (T-Const). Check\CheckCheck is unchanged. Only Whnf\WhnfWhnf, and through it IsDefEq\IsDefEqIsDefEq, learned the new delta- and iota-steps. Chapter 12 shows how a single Whnf\WhnfWhnf handles every inductive type, and Chapter 14 discusses what inductive types change in the metatheory.

(with ndrec defined as in the playground above).

Explain why Eq\Eq{}Eq​ eliminates into every universe although it is a proposition, but a type Or with two constructors does not.

Solution

Eq\Eq{}Eq​ is a subsingleton: one constructor with no fields. A function defined by its recursor cannot distinguish two proofs of a=ba = ba=b, because there is only one way to build any such proof. Or has two constructors, so its recursor into Nat\NatNat could return different numbers for the two injections, making the value of a program depend on which proof was supplied. Chapter 8 states the rule precisely.

What to remember

  • Eq\Eq{}Eq​ is an inductive family with parameters AAA and aaa, index bbb, and one constructor refl\refl{}refl​ with no fields.
  • Its recursor transports a fact about aaa to a fact about bbb along a proof of a=ba = ba=b, and does nothing on refl\refl{}refl​. This is rewriting.
  • Definitional equality is decided by computation; propositional equality is a type whose proofs may need induction. refl\refl{}refl​ turns the former into the latter.
  • n+0=nn + 0 = nn+0=n is definitional and 0+n=n0 + n = n0+n=n is not, because addition recurses on its second argument.
