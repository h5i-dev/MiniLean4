第 1 章

命題は型である

自然言語で書かれた証明を計算機に検査させるには、証明を型付きの項として表す必要があります。Curry-Howard 対応のもとでは、項の型がその項の証明する命題にあたり、証明の検査は型検査に帰着します。

証明はプログラムである

命題「AAA ならば BBB」の証明を、ふつうの数学の文章で書くと次のようになります。

AAA を仮定する。すると……（何らかの議論）……ゆえに BBB が成り立つ。

この証明は、形のうえでは関数です。AAA を信じる根拠を受け取り、BBB を信じる根拠を作り出すからです。これを文字どおりに受け取って「AAA を信じる根拠」を型 AAA の値とみなせば、A→BA \to BA→B の証明は AAA から BBB への関数になり、命題 A→BA \to BA→B はその関数の型になります。

この観察を Curry-Howard 対応（Curry-Howard correspondence）と呼びます。要点は次の三つです。

  • 命題は型である。
  • 命題の証明は、その型の項である。
  • 命題 AAA が真であるのは、型 AAA の項 ttt が存在するとき、かつそのときに限る。このとき t:At : At:A と書く。

この考えだけでどこまで進めるか、三つの例で見てみましょう。左の列が命題、中央の列が関数として書いたその証明、右の列が証明の考え方を言葉にしたものです。ここで λx. e\lambda x.\,eλx.e は、xxx を受け取って eee を返す関数を表します。

命題 証明 言葉で言えば
P→PP \to PP→P λp. p\lambda p.\,pλp.p 仮定をそのまま返します。
A→B→AA \to B \to AA→B→A λa. λb. a\lambda a.\,\lambda b.\,aλa.λb.a 二つ目の仮定を無視します。
(A→B)→(B→C)→A→C(A \to B) \to (B \to C) \to A \to C(A→B)→(B→C)→A→C λf. λg. λa. g (f a)\lambda f.\,\lambda g.\,\lambda a.\,g\,(f\,a)λf.λg.λa.g(fa) 二つの含意を合成します。

三行目をもう一度見てください。含意の推移性を証明するには、まず A→BA \to BA→B と B→CB \to CB→C を仮定します。そして AAA が与えられたら、一つ目の仮定を適用して BBB を得て、二つ目の仮定を適用して CCC を得ます。証明項はこの手順をそのまま表していて、fff と ggg が二つの仮定、aaa が AAA の証明であり、g (f a)g\,(f\,a)g(fa) で仮定を順に適用しています。つまり、仮定を使うとは関数を適用することです。仮定を言い直すだけの作業と本当の推論とを分けるのはこの一歩であり、第 3 章で改めて取り上げます。

型を仕様、項をその仕様を満たすものと考えてみましょう。「型 AAA の項がある」とは「仕様 AAA を満たせる」ということで、AAA が命題なら、満たすとは証明することです。項を一つも持たない型は、証明できない命題にあたります。後で False\mathsf{False}False が担うのは、まさにこの役割です。

量化子は依存関数になる

同じ考え方は「すべての」にも当てはまります。すべての x:Ax : Ax:A について B(x)B(x)B(x) が成り立つことを証明するには、どんな xxx を渡されても B(x)B(x)B(x) の証明を作り出せる方法を示せば十分です。これもやはり関数ですが、返り値の型が引数に依存する点が違います。x=3x = 3x=3 なら B(3)B(3)B(3) の証明を、x=7x = 7x=7 なら B(7)B(7)B(7) の証明を返すわけです。結果の型が引数に言及できる関数型を依存関数型（dependent function type）または Π\PiΠ 型と呼び、次のように書きます。

Π(x:A). B(x).\Pi(x : A).\,B(x).Π(x:A).B(x).

ふつうの関数型 A→BA \to BA→B は、BBB が xxx を含まない特別な場合にあたります。

たとえば「すべての命題は自分自身を含意する」は、命題について量化した主張です。Sort 0\Sort{0}Sort0 を命題全体の型とすると、この主張は

Π(P:Sort 0). P→P,\tPi{P}{\Sort{0}}{P \to P},Π(P:Sort0).P→P,

と書けます。その証明は、命題 PPP と PPP の証明 ppp を順に受け取り、ppp を返す関数です。

λ(P:Sort 0). λ(p:P). p.\tLam{P}{\Sort{0}}{\tLam{p}{P}{p}}.λ(P:Sort0).λ(p:P).p.

束縛子に型が付いている点に注意してください。λ(P:Sort 0)\lambda(P : \Sort{0})λ(P:Sort0) は PPP が命題全体を動くことを、λ(p:P)\lambda(p : P)λ(p:P) は ppp が受け取った PPP の証明であることを表します。型検査器には、この注釈が必要です。

カーネルの仕事

ここから、定理証明器の中心にある考え方が出てきます。

定理を証明するとは要求された型の項を構成することであり、証明を検証するとはその項を型検査することです。

カーネルは、真偽についてなんらかの推論をするわけではありません。項がどんなときに型を持つかを定めた型付け規則を実装し、与えられた項がその規則のもとで与えられた型を持つかを機械的に検査するだけです。これを証明の検査と呼べるかどうかは、型付け規則が何らかの論理を忠実に実装しているかにかかっており、この問題は第 4 章で扱います。規則が健全（sound）かどうか、つまり偽の命題に住む項が存在しないかどうかは、第 13 章と第 14 章で扱います。

本格的な証明器の設計は、この分業を前提にしています。証明を探すのはタクティクや自動化、決定手続き、最近では大規模言語モデルの役目で、それらにバグがあっても、出力された項はカーネルが検査します。正しさが求められるのはカーネルだけなので、カーネルをできるだけ小さく保つことが設計目標になります。本書のカーネルは、コメントを含めても千五百行に満たない Rust のコードです。

Lean 4 も同じ仕組みで動きます。theorem コマンドが主張を型へとエラボレートし、タクティクがその型の項を組み立て、カーネルがその項を検査したうえで、定理が環境に追加されます。Lean のカーネルは宇宙多相、相互・入れ子帰納型、定義的な証明無関係性に加え、キャッシュや遅延展開といった性能のための機能も備えているぶん、本書のものより大きくなっています。それでも仕事は同じで、Γ⊢t:A\Gamma \vdash t : AΓ⊢t:A が成り立つかを判定します。

本書の計画

第 I 部では、論理として使える最小限の型理論を対象に、カーネルを作ります。

  1. 第 2 章で、対象とする言語を定めます。構成要素は宇宙、変数、Π\PiΠ 型、λ\lambdaλ 抽象、適用です。
  2. 第 3 章で型付け規則を与えます。規則は、項の種類ごとに一つずつと、型の中での計算を許すためのものが一つです。
  3. 第 4 章で、これらの規則がある論理の推論規則にあたることを示し、整合性を定義します。
  4. 第 5 章で規則をアルゴリズムに書き換え、Rust の実装と突き合わせます。
  5. 第 6 章では、正しい証明、誤った証明、計算を必要とする証明を例に、アルゴリズムを手で動かしてみます。

代入と定義的等価という二つの操作は、第 III 部まであえてブラックボックスとして扱います。どちらも定義を書くのは簡単ですが、間違えるのも簡単で、しかもカーネルの正しさはこの二つにかかっています。

覚えておくこと

  • 命題は型、証明は項であり、t:At : At:A は ttt が AAA を証明することを意味します。
  • 含意は関数型で、仮定を使うとは関数を適用することです。
  • 全称量化は依存関数型 Π(x:A). B(x)\Pi(x : A).\,B(x)Π(x:A).B(x) です。
  • 定理証明器のカーネルは型検査器です。それ以外の部分は、カーネルが検査する項を作る役にすぎません。
