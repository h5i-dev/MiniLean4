第 8 章

帰納型 II: 一般的な手順

第 7 章では自然数の再帰子を手で組み立てた。Lean では、カーネルが inductive 宣言を検査して再帰子と計算規則を生成する。構成子を増やし、パラメータと添字を加えながら、この生成手順を導く。対応するカーネルのコードは約五百行である。

一般的な手順

本節では、パラメータと添字を持つ単一の帰納型に対する手続きを述べるが、Lean が対応している相互帰納型と入れ子帰納型は範囲外とする。

この手続きは、T-Const が未解決のまま残した問いにも答える。本体のない定数は仮定であり、T-Const は zero:Nat\zero : \Natzero:Nat を受け入れるのとまったく同じように c:Π(P:Sort 0). Pc : \tPi{P}{\Sort{0}}{P}c:Π(P:Sort0).P も受け入れ、それがあると体系は非整合になる。以下で生成する定数は恣意的な仮定ではなく、固定されたスキーマのインスタンス、すなわち Calculus of Inductive Constructions の帰納型であり、その整合性は知られている [Werner 1994]。

命題からの消去。 u≥1u \ge 1u≥1 なら、再帰子はすべてのレベル vvv について生成されるが、u=0u = 0u=0、つまり III が命題なら、再帰子は v=0v = 0v=0 についてのみ生成される。ただし III が部分単集合（subsingleton）なら話は別である。部分単集合とは、構成子が高々一つで、各フィールドが証明である（型が Sort 0\Sort{0}Sort0 に属する）か添字項 t⃗j\vec{t}_jtj​ の中に現れるかのいずれかである型をいう。この制限は、命題のどの証明が与えられたかにデータが依存することを防ぐ。たとえば P∨QP \vee QP∨Q には構成子が二つあるので、P∨QP \vee QP∨Q の証明から Nat\NatNat への関数は一方に 000 を、他方に 111 を返せてしまい、証明が計算上の情報を持つことになる。したがって Lean の Or.rec と Exists.rec は Prop へのみ消去し、And.rec と Eq.rec はすべての宇宙へ消去する。And の構成子は一つでそのフィールドはすべて証明であり、Eq（第 9 章）の構成子は一つでフィールドを持たないからである。

こうして、シグネチャが成長してもカーネルの規則は固定されたままである。一つの汎用の手続きが各宣言をシグネチャの項目に変え、一つの簡約関数がそれらの規則を実行する（第 12 章）。

コードでは

この手続きは src/inductive/ にあり、入力は InductiveSpec（src/declaration.rs）で、名前、パラメータと添字のテレスコープ、宇宙レベル uuu、そして構成子ごとにそのフィールドと添字項 t⃗j\vec{t}_jtj​ を与える ConstructorSpec からなる。スクリプトのパーサが inductive ブロックからこれを組み立てる。

  • src/inductive/mod.rs の Kernel::add_inductive は四つの受理条件を順に実行し（check_inductive_type が条件 1、check_constructor_fields がフィールドが型であることを確かめて条件 4 を課し、check_constructor_result が条件 2）、すべて通れば型構成子と構成子を登録して InductiveInfo を記録する。失敗した場合、シグネチャは変更されない。
  • src/inductive/positivity.rs が条件 3 であり、check_recursive_field はフィールドの型の先頭の Π\PiΠ を剥がし、定義域が III に言及するものを拒否する。そして標的が、III をちょうどパラメータ変数に適用し、その後に III に言及しない添字項を続けた形であることを要求する。戻り値は y⃗:B⃗\vec{y} : \vec{B}y​:B と s⃗\vec{s}s を記録した RecursiveFieldInfo で、再帰子の生成器に必要なのはこれだけである。
  • src/inductive/recursor.rs は上の式から再帰子の型を組み立てる。recursor_type がテレスコープ p⃗\vec{p}p​、motive、小前提、添字、大前提を組み合わせ、minor_premise_type が各 CjC_jCj​ を、induction_hypothesis_type が各 Hj,kH_{j,k}Hj,k​ を組み立てる。生成される束縛子の名前（__motive、__minor_j、__ih_j_k、__major）は下線二つで始まり、ユーザーの宣言ではこの形の名前を使えないので、フィールドと衝突することはない。
  • mod.rs の allows_large_elimination が部分単集合の判定を実装する。add_inductive は I.rec0 を常に登録し、大消去が許されるなら I.rec1 も登録する。より高いレベルは register_recursor が必要に応じて生成する。

ι 規則は項としては生成されず、whnf が、格納された InductiveInfo から直接それを適用する。詳細は第 12 章で説明する。

生成器の中心部は、全文を読めるほど短いので、CjC_jCj​ の式と見比べてほしい。

/// C_j = Pi (as : As_j). Pi (hs : Hs_j). M ts_j (c_j ps as)
fn minor_premise_type(info: &InductiveInfo, j: usize, constructor: &ConstructorInfo) -> Term {
    // c_j ps as
    let constructor_application = apps(
        const_term(&constructor.name),
        info.params.iter().chain(constructor.fields.iter()).map(|(name, _)| var(name)),
    );
    // (as : As_j) の後に (hs : Hs_j)
    let mut minor_premise_binders = constructor.fields.clone();
    for (k, recursive_field) in constructor.recursive_fields.iter().enumerate() {
        minor_premise_binders.push((
            format!("{INDUCTION_HYPOTHESIS_PREFIX}{j}_{k}"),
            induction_hypothesis_type(constructor, recursive_field),
        ));
    }
    telescope(&minor_premise_binders, apply_motive(&constructor.result_indices, constructor_application))
}

カーネルは Nat\NatNat を特別扱いせず、src/kernel.rs の Kernel::standard は、ユーザーのスクリプトが生成するのと同じ InductiveSpec で add_inductive を呼んで Nat\NatNat と Eq\mathsf{Eq}Eq を宣言する。つまり図 7.1 はハードコードされたものではなく生成されたものであり、src/inductive/tests.rs のテストは、生成された型が手書きのものと一致することを確かめる。

正値性の検査は健全性のための要件であって、便宜のためのものではない。Lean、Coq、Agda のいずれも、一般の場合（入れ子帰納型と相互帰納型、宇宙制約、他の帰納型に言及する添字）が複雑なため、カーネルのこの部分で長年にわたりバグを出してきた。本書の制限されたスキーマでは検査は八十行に収まるが、拡張するときに新機能のたびに問うべきことは一つである。その型を消費する関数から、その型の値を組み立てられないか。

次のそれぞれは、四つの受理条件のどれによって拒否されるか。拒否されないものはあるか。(a) inductive T : Sort 1 where | mk (f : Sort 1)。(b) inductive T : Sort 1 where | mk (f : T -> T)。(c) inductive T : Sort 0 where | mk (f : Sort 1)。

解答

(a) 条件 4。フィールド Sort 1\Sort{1}Sort1 の型は Sort 2\Sort{2}Sort2 で、u=1u = 1u=1 を超える。(b) 条件 3。フィールドの型の中で TTT が矢印の左側に現れる。(c) 受理される。u=0u = 0u=0 では条件 4 は何も課さず、この型は型を一つ包み込んだ命題である。これは Sort 0\Sort{0}Sort0 の非述語性の現れだが、TTT は Sort 0\Sort{0}Sort0 へしか消去できない（フィールドが証明でも添字でもないので部分単集合ではない）ため無害である。

覚えておくこと

  • 宣言は、パラメータと添字を持つ型構成子と、フィールドを持つ構成子を与え、パラメータは全体を通して固定される一方、添字は変化して motive の引数になる。
  • 再帰子は構成子ごとに小前提を一つ持ち、各小前提は再帰的フィールドごとに帰納法の仮定を一つ持ち、ι 規則は構成子ごとに一つである。
  • 受理には、整形式性、一様なパラメータ、正格な正値性、宇宙の上限が必要であり、再帰を停止させ、論理を整合的に保つのは正値性である。
  • 命題は、部分単集合でない限り Sort 0\Sort{0}Sort0 へしか消去できない。
  • カーネルはこれらすべてをデータから生成し、Nat\NatNat に固有のコードは含まれない。
