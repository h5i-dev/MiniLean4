第 11 章

代入、捕獲、α 同値

これまでの章では、項に対する三つの操作をブラックボックスとして扱ってきた。T-App と Freshen、そしてあらゆる計算ステップが使う代入。Π\PiΠ や宇宙を露わにするために使う弱頭正規化。Check が使う定義的等価である。この三つは信頼されたカーネルの一部であり、カーネルのバグの大半はここに潜む。束縛変数の名前を正しく扱わなければならないからだ。本章では最初の箱である代入を開け、同じ名前の問題が文脈にも現れることを示し、最後に、二つの項が束縛変数の名前を除いて等しいとはどういうことかを定義する。

問題は代入の場合と同じである。名前が、別の意味を持つスコープへ移動してしまう。文脈がリストであれハッシュマップであれ、変数を名前で識別する表現はすべてこの影響を受ける。よく使われる対処法は三つある。

  1. シャドーイングを一律に拒否する。最も単純な選択肢だが、A→BA \to BA→B が使う予約名 _ は例外にして、決して文脈に加えないようにしなければならない。
  2. 文脈に入るときに改名する。Freshen\FreshenFreshen がこれであり、本書の選択でもある。
  3. 束縛変数を位置で表す（de Bruijn インデックス [de Bruijn 1972]）か、locally nameless 方式を使う。後者では束縛変数はインデックスで表し、自由変数は一意な識別子を持つ。Lean 4 は後者の方式を採る。

テストスイートには上の ttt を含め、カーネルがそれを拒否するか、正しい型を割り当てるかを確認すべきである。

このバグは書いてしまいやすく、気づきにくい。普通の証明はすべて通ってしまうからだ。入れ子の束縛子で意図的に名前を使い回す項だけがこのバグを露わにする。カーネルのテストスイートには、正しい証明だけでなく、敵対的な項（adversarial terms）も必要である。

α 同値

束縛変数の名前には意味がない。λ(x:A). x\tLam{x}{A}{x}λ(x:A).x と λ(y:A). y\tLam{y}{A}{y}λ(y:A).y は同じ関数であり、Π(P:Sort 0). P→P\tPi{P}{\Sort{0}}{P \to P}Π(P:Sort0).P→P と Π(Q:Sort 0). Q→Q\tPi{Q}{\Sort{0}}{Q \to Q}Π(Q:Sort0).Q→Q は同じ命題である。束縛変数の名前だけが異なる項を α 同値（alpha-equivalent）であるという。カーネルは型を単なる構文的な等しさで比較するわけにはいかない。それでは後者の組が拒否されてしまう。

定義 11.3（α 同値）. =α\alphaeq=α​ は、□∈{Π,λ}\square \in \{\Pi, \lambda\}□∈{Π,λ} について次を含む最小の合同関係である。

（合同関係（congruence）とは、すべての項構成子で保たれる同値関係である。部分どうしが関係にあれば、全体どうしも関係にある。）この定義は述べるのは簡単だが、そのままでは実行できない。どの名前を選ぶべきかを言っていないからだ。実装は代わりに両方の項を足並みをそろえてたどり、それぞれの側で、ここまでに通過した束縛子のリストを覚えておく。束縛変数はこうして、名前ではなくどの束縛子を指しているかで識別される。

自由変数は名前で比較し（α\alphaα-Free）、束縛変数は位置で比較し（α\alphaα-Bound）、定数は名前で比較する（α\alphaα-Const）。一方で束縛され他方で自由な変数は何とも等しくならないので、その場合の規則はない。両側は束縛子を一緒に下っていくので、E1E_1E1​ と E2E_2E2​ の長さは常に等しい。したがって右から数えた位置の比較は左から数えた位置の比較と同じであり、実装は各リストを名前から束縛の深さへの写像として保持してもよい。ただし束縛子を抜けるときには以前の項目を復元する必要がある。名前の代わりに位置をあらゆる場所で使うと de Bruijn 表現になる。そこでは α 同値な項は構文的に同一である。

定理 11.4（アルゴリズム的 α 同値の正しさ）. すべての項 sss と ttt について、定義 11.3 の意味で s=αts \alphaeq ts=α​t であることと、⋅ ;⋅⊢s=αt\cdot\,;\cdot \vdash s \alphaeq t⋅;⋅⊢s=α​t が図 11.1 の規則で導出できることとは同値である。

証明の要点は、どちらの定義も「sss と ttt が同じ de Bruijn 表現を持つ」と言い換えられることである。アルゴリズムの規則は de Bruijn インデックスと同じ方法で位置を比較しているので、この言い換えはほぼ直接に分かる。一方、定義 11.3 については、束縛変数を改名しても de Bruijn 表現が変わらないことを示す必要がある。完全な証明は 付録 B にある。

図 11.1 は src/substitution.rs の関数 alpha である。二つの束縛子リストは Vec<String> で、本体への再帰呼び出しの前後で push と pop を行う。binder_distance が idx\mathrm{idx}idx にあたる。リストを末尾から探索するので、その名前を持つ最も近い外側の束縛子までの距離が最初に見つかる。

(Term::Var(x), Term::Var(y)) => {
    match (binder_distance(bound_a, x), binder_distance(bound_b, y)) {
        (Some(i), Some(j)) => i == j,     // alpha-Bound
        (None, None) => x == y,           // alpha-Free
        _ => false,                       // bound on one side only
    }
}

演習

(λ(y:A). λ(x:B). x  y)[x↦y]\subst{(\tLam{y}{A}{\tLam{x}{B}{x\;y}})}{x}{y}(λ(y:A).λ(x:B).xy)[x↦y] を一歩ずつ計算せよ。

解答

外側の束縛子は yyy で、これは置き換え項 yyy に自由に現れるので、捕獲の場合にあたる。yyy を新鮮な zzz に改名して本体 λ(x:B). x  z\tLam{x}{B}{x\;z}λ(x:B).xz を得てから代入する。内側の束縛子は置き換え対象の変数 xxx なので、内側の本体には手を付けない。結果は λ(z:A). λ(x:B). x  z\tLam{z}{A}{\tLam{x}{B}{x\;z}}λ(z:A).λ(x:B).xz である。内側の xxx はもともと自由な出現ではなかったので、実際には何も置き換わっていない。唯一の効果は、捕獲回避が強いた改名である。

λ(x:A). λ(y:A). y  x\tLam{x}{A}{\tLam{y}{A}{y\;x}}λ(x:A).λ(y:A).yx と λ(y:A). λ(x:A). x  y\tLam{y}{A}{\tLam{x}{A}{x\;y}}λ(y:A).λ(x:A).xy が α 同値かどうかを、図 11.1 を実行して判定せよ。

解答

同値である。α\alphaα-Lam を二回適用すると、束縛子のリストは x,yx, yx,y と y,xy, xy,x、本体は y  xy\;xyx と x  yx\;yxy になる。α\alphaα-App で yyy と xxx を比べるとインデックスは 000 と 000、続いて xxx と yyy を比べると 111 と 111 になる。名前は入れ替わっていても、位置が一致するので同値である。

覚えておくこと

  • 代入は自由な出現だけを置き換える。置き換え項が束縛子の名前を含むとき（捕獲）は、束縛子を改名しなければならない。
  • 同じ捕獲の問題は文脈でも起こる。束縛子が文脈の項目をシャドーイングすることを許すカーネルは False を証明できてしまう。Freshen がこれを防ぐ。
  • α 同値は、束縛変数をその束縛子の位置で、自由変数を名前で比較する。図 11.1 がそのアルゴリズムであり、定理 11.4 はそれが定義と一致することを述べる。
  • 三つとも src/substitution.rs にある。subst、fv、alpha である。
