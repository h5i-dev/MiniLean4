Chapter 3

Typing Rules

The kernel's job is to decide the judgment "term ttt has type AAA". This chapter defines that judgment by a small set of inference rules, one for each kind of term and one extra rule that lets computation happen inside types. Reading each rule bottom-up turns it into a recipe for checking a term, and that recipe becomes the algorithm of Chapter 5.

Contexts and judgments

A term such as f  pf\;pfp cannot be checked in isolation: its type depends on what fff and ppp are. A context Γ\GammaΓ records that information. It is an ordered list of assumptions

Γ  =  x1:A1,  x2:A2,  …,  xn:An,\Gamma \;=\; x_1 : A_1,\; x_2 : A_2,\; \ldots,\; x_n : A_n,Γ=x1​:A1​,x2​:A2​,…,xn​:An​,

giving the type of each variable in scope, and dom(Γ)\dom(\Gamma)dom(Γ) denotes the set of names {x1,…,xn}\{x_1, \ldots, x_n\}{x1​,…,xn​}. The empty context is written ⋅\cdot⋅.

Order matters. A later type may mention an earlier variable, as in P:Sort 0,  h:PP : \Sort{0},\; h : PP:Sort0,h:P: the assumption h:Ph : Ph:P only makes sense once PPP is known to be a proposition. Names in a context will be required to be distinct, so a context can be used like a dictionary from names to types; but it is a dictionary whose entries depend on each other in sequence.

Two judgments are defined together.

  • ⊢Γ;ok\ctxok{\Gamma}⊢Γ;ok means that the context Γ\GammaΓ is well formed: each assumed type is a genuine type in the context before it.
  • Γ⊢t:A\Gamma \vdash t : AΓ⊢t:A means that under the assumptions in Γ\GammaΓ, the term ttt has type AAA.

Through the Curry-Howard lens, Γ⊢t:A\Gamma \vdash t : AΓ⊢t:A says that ttt is a proof of AAA from the hypotheses Γ\GammaΓ.

Two of the rules use operations on terms that the next chapters treat as black boxes.

Substitution. T-App writes B[x↦a]\subst{B}{x}{a}B[x↦a] for the result of replacing every free occurrence of xxx in BBB by aaa. For example, (P→P)[P↦Q]=Q→Q\subst{(P \to P)}{P}{Q} = Q \to Q(P→P)[P↦Q]=Q→Q. Replacing names inside binders needs care, which Chapter 11 explains; until then the intuitive meaning is enough.

Definitional equality. T-Conv writes A≡BA \conv BA≡B when AAA and BBB are "the same type" in a sense the kernel can decide mechanically. Two kinds of difference are ignored.

  • The names of bound variables. Π(P:Sort 0). P→P\tPi{P}{\Sort{0}}{P \to P}Π(P:Sort0).P→P and Π(Q:Sort 0). Q→Q\tPi{Q}{\Sort{0}}{Q \to Q}Π(Q:Sort0).Q→Q state the same proposition. Terms that differ only in this way are alpha-equivalent, written A=αBA \alphaeq BA=α​B.
  • Computation. If Id=λ(X:Sort 0). X\mathit{Id} = \tLam{X}{\Sort{0}}{X}Id=λ(X:Sort0).X, then Id  P\mathit{Id}\;PIdP computes to PPP by plugging PPP in for XXX, so a proof of Id  P\mathit{Id}\;PIdP should count as a proof of PPP. The computation step (λ(x:A). t)  s→βt[x↦s](\tLam{x}{A}{t})\;s \betared \subst{t}{x}{s}(λ(x:A).t)s→β​t[x↦s] is called beta-reduction.

The kernel decides A≡BA \conv BA≡B by computing both sides as far as possible and then checking whether the results are alpha-equivalent. Chapter 12 defines this precisely.

Reading the rules

The rules are best read from the bottom up, as a recipe: to establish the conclusion, establish the premises.

C-Empty and C-Ext. A context is built one assumption at a time, and each new assumption must have a type as its type. The side condition x∉dom(Γ)x \notin \dom(\Gamma)x∈/dom(Γ) forbids two assumptions with the same name. Since the names of bound variables do not matter, this restricts nothing: a binder that would clash can always be renamed first. Chapter 11 shows what goes wrong in a kernel that skips this condition.

T-Sort. Every universe lives in the next one: Sort 0:Sort 1\Sort{0} : \Sort{1}Sort0:Sort1, Sort 1:Sort 2\Sort{1} : \Sort{2}Sort1:Sort2, and so on. Chapter 13 explains why a universe cannot be its own type.

T-Var. A variable has the type the context assigns to it. Logically: use a hypothesis.

T-Pi. Π(x:A). B\tPi{x}{A}{B}Π(x:A).B is a type if AAA is a type and BBB is a type once x:Ax : Ax:A is assumed. The resulting universe is imax(u,v)\imax(u, v)imax(u,v), which is 000 if v=0v = 0v=0 and max⁡(u,v)\max(u, v)max(u,v) otherwise. In words: a Π\PiΠ-type is a proposition whenever its body is a proposition, no matter what it quantifies over; otherwise it lives in the larger of the two universes. Logically, this rule says when A→BA \to BA→B and ∀x:A. B\forall x{:}A.\,B∀x:A.B are well-formed statements.

T-Lam. To build a function from AAA to BBB, assume x:Ax : Ax:A and build a term ttt of type BBB. The body's type BBB may mention xxx, and it is kept as is in the resulting Π\PiΠ-type, which is where dependency enters. Logically, this is the introduction rule for implication and for the universal quantifier: to prove A→BA \to BA→B, assume AAA and prove BBB.

T-App. If fff maps each x:Ax : Ax:A to an element of BBB, and a:Aa : Aa:A, then f  af\;afa has type BBB with xxx replaced by aaa. When BBB does not mention xxx this is modus ponens: from A→BA \to BA→B and AAA, conclude BBB. When it does, it is instantiation of a universal statement. For example, if f:Π(n:Nat). n+0=nf : \tPi{n}{\Nat}{n + 0 = n}f:Π(n:Nat).n+0=n, then f  3:3+0=3f\;3 : 3 + 0 = 3f3:3+0=3 (natural numbers arrive in Chapter 7).

T-Conv. Types that are equal up to computation are interchangeable: from h:Id  Ph : \mathit{Id}\;Ph:IdP we may conclude h:Ph : Ph:P. The premise Γ⊢B:Sort u\Gamma \vdash B : \Sort{u}Γ⊢B:Sortu ensures that the new type is itself a type. This is the only rule whose use is not determined by the shape of ttt, a fact that matters for the algorithm in Chapter 5.

Each rule is a small piece of common sense about functions. T-Lam says how to make a function; T-App says how to use one; T-Pi says when a function type makes sense; T-Var and T-Sort say what the basic things are; and T-Conv says that computing inside a type does not change what it means. There is nothing specifically "logical" in the rules. The logic is a consequence of reading them through Curry-Howard, which Chapter 4 makes precise.

Why application matters

It is tempting to think that the interesting rules are the ones that build things (T-Lam, T-Pi) and that T-App is bookkeeping. The opposite is closer to the truth. Without T-App a hypothesis can be returned but never used. Roughly, the provable propositions would then be only those whose conclusion is literally one of the hypotheses, such as P→Q→PP \to Q \to PP→Q→P. Composition,

(P→Q)→(Q→R)→P→R,(P \to Q) \to (Q \to R) \to P \to R,(P→Q)→(Q→R)→P→R,

has the proof λ(f:P→Q). λ(g:Q→R). λ(p:P). g (f p)\tLam{f}{P \to Q}{\tLam{g}{Q \to R}{\tLam{p}{P}{g\,(f\,p)}}}λ(f:P→Q).λ(g:Q→R).λ(p:P).g(fp), which applies fff and then ggg. Every proof that does more than restate an assumption goes through T-App, and in a dependent type theory T-App is also where substitution, and therefore most of the subtlety, lives.

Chapter 6 revisits this example with the algorithm.

The rules of this chapter are implemented by Kernel::infer and Kernel::check in src/typecheck.rs, which Chapter 5 reads line by line. Contexts are the Rust type Context = Vec<(String, Term)> in src/declaration.rs: a vector of name-type pairs, searched from the end so that the most recent assumption for a name wins.

Exercises

Which rule, applied bottom-up, handles each of the following judgments, and what premises does it produce? (a) Γ⊢λ(x:A). x:A→A\Gamma \vdash \tLam{x}{A}{x} : A \to AΓ⊢λ(x:A).x:A→A. (b) Γ⊢Sort 2:Sort 3\Gamma \vdash \Sort{2} : \Sort{3}Γ⊢Sort2:Sort3. (c) Γ⊢f  a:B\Gamma \vdash f\;a : BΓ⊢fa:B where f:A→Bf : A \to Bf:A→B.

Solution

(a) T-Lam, with premises Γ⊢A:Sort u\Gamma \vdash A : \Sort{u}Γ⊢A:Sortu for some uuu and Γ,x:A⊢x:A\Gamma, x : A \vdash x : AΓ,x:A⊢x:A; the latter is T-Var. The resulting type is Π(x:A). A\tPi{x}{A}{A}Π(x:A).A, which is A→AA \to AA→A up to the binder name. (b) T-Sort, with the single premise ⊢Γ;ok\ctxok{\Gamma}⊢Γ;ok. (c) T-App, with premises Γ⊢f:Π(_:A). B\Gamma \vdash f : \tPi{\_}{A}{B}Γ⊢f:Π(_:A).B and Γ⊢a:A\Gamma \vdash a : AΓ⊢a:A. The conclusion is B[_↦a]=B\subst{B}{\_}{a} = BB[_↦a]=B, since _ does not occur in BBB.

Using T-Pi, compute the universe of Π(P:Sort 0). P→P\tPi{P}{\Sort{0}}{P \to P}Π(P:Sort0).P→P and of Π(A:Sort 1). A→A\tPi{A}{\Sort{1}}{A \to A}Π(A:Sort1).A→A.

Solution

For the first, Sort 0:Sort 1\Sort{0} : \Sort{1}Sort0:Sort1 so u=1u = 1u=1, and P→P:Sort 0P \to P : \Sort{0}P→P:Sort0 (by T-Pi again with u=v=0u = v = 0u=v=0) so v=0v = 0v=0. Hence the universe is Sort imax(1,0)=Sort 0\Sort{\imax(1, 0)} = \Sort{0}Sortimax(1,0)=Sort0: a statement quantifying over all propositions is itself a proposition. For the second, u=2u = 2u=2 and A→A:Sort 1A \to A : \Sort{1}A→A:Sort1 so v=1v = 1v=1, giving Sort imax(2,1)=Sort 2\Sort{\imax(2,1)} = \Sort{2}Sortimax(2,1)=Sort2. Chapter 13 explains the asymmetry.

What to remember

  • A context is an ordered list of distinct assumptions x:Ax : Ax:A; the judgment Γ⊢t:A\Gamma \vdash t : AΓ⊢t:A says that ttt has type AAA under those assumptions.
  • There is one rule per kind of term, plus T-Conv, which identifies types up to computation and bound-variable renaming.
  • T-App is where hypotheses are used and where substitution happens; T-Conv is the only rule not triggered by the shape of the term.
  • Substitution and definitional equality are treated as black boxes until Part III.
