第 10 章

タクティク: 対話的に証明項を組み立てる

Lean のユーザーが、第 9 章の末尾にあるような項を手で書くことはめったにない。書くのはタクティクスクリプトであり、残っている証明すべきものをシステムが表示しながら、項を一歩ずつ組み立てていくコマンドの列である。本章では、よく使われるタクティクが本書の体系でどのように項を構築するか、そしてなぜそのどれも信頼する必要がないかを示す。

Lean では、第 9 章の定理は次のように証明される。

theorem zero_add (n : Nat) : 0 + n = n := by
  induction n with
  | zero => rfl
  | succ k ih => rw [Nat.add_succ, ih]

各タクティクは、証明項の一部を組み立てる小さなプログラムであり、カーネルの外側で動く。その出力はふつうの項であり、カーネルは他の項と同じようにアルゴリズム 5.1 でそれを検査する。

ゴールと証明状態

ゴール（goal）⟨Γ⊢?m:T⟩\goal{\Gamma}{\hole{m}}{T}⟨Γ⊢?m​:T⟩ は、文脈 Γ\GammaΓ における型 TTT の項を求める。ホール（hole）?m\hole{m}?m​ はまだ見つかっていない項を表し、Lean ではこれをメタ変数と呼ぶ。証明状態（proof state）は、ゴールのリストと、ホールを含みうる項である部分的な証明項を合わせたものである。

TTT を証明するには、部分項 ?0\hole{0}?0​ と唯一のゴール ⟨⋅⊢?0:T⟩\goal{\cdot}{\hole{0}}{T}⟨⋅⊢?0​:T⟩ から始める。タクティクは最初のゴール ⟨Γ⊢?m:T⟩\goal{\Gamma}{\hole{m}}{T}⟨Γ⊢?m​:T⟩ に対して働き、?m\hole{m}?m​ に、新鮮なホールを含みうる項を割り当て、そのゴールを新鮮なホールごとに一つの新しいゴールで置き換える。ゴールが残っていなければ部分項にホールはなく、カーネルがそれを TTT に対して検査する。ホールは束縛子の下に置かれることがあり、λ(x:A). ?1\tLam{x}{A}{\hole{1}}λ(x:A).?1​ の ?1\hole{1}?1​ がそうで、それを埋める項はその束縛変数を使ってよい。ゴールがそれぞれ自分の文脈を持つのはそのためである。

各タクティクは、新鮮な各ホールがのちにそのゴールの述べる型の項で埋められると仮定したうえで、自分の割り当てが Γ\GammaΓ において型 TTT を持つことを保証しなければならない。これを ⟨Γ⊢?m:T⟩⇝new goals\goal{\Gamma}{\hole{m}}{T} \leadsto \text{new goals}⟨Γ⊢?m​:T⟩⇝new goals と書き、続けて割り当てを書く。

最初の例

スクリプト examples/identity.leanmini は第 1 章の冒頭の例を証明し、下のエクスプローラはそれを一コマンドずつ実行する。

goal forall (P : Sort 0), P -> P
intro P
intro p
exact p
qed

ボタンか矢印キーで一歩ずつ進めてほしい。中央のパネルは各コマンドの後のゴールのリスト、右のパネルは部分的な証明項で、現在のゴールに対応するホールが強調されている。三つのパネルは常に一致する。タクティクがホールに項を割り当てるからこそ、ゴールが変わる。

ゴールのリストだけでは足りない。intro p のあと、ゴール PPP は、その解が二つの λ\lambdaλ で包まれなければならないことを覚えておらず、部分項がそれを記録する。

基本的なタクティク

intro x。 TTT が Π\PiΠ 型に正規化されるとき、このタクティクはその引数を文脈に移す。

⟨Γ⊢?m:Π(y:A). B⟩  ⇝  ⟨Γ,x:A⊢?1:B[y↦x]⟩,?m:=λ(x:A). ?1.\goal{\Gamma}{\hole{m}}{\tPi{y}{A}{B}} \;\leadsto\; \goal{\Gamma, x : A}{\hole{1}}{\subst{B}{y}{x}}, \qquad \hole{m} \mathrel{:=} \tLam{x}{A}{\hole{1}}.⟨Γ⊢?m​:Π(y:A).B⟩⇝⟨Γ,x:A⊢?1​:B[y↦x]⟩,?m​:=λ(x:A).?1​.

割り当てが正しい型を持つことは T-Lam による。名前 xxx は dom(Γ)\dom(\Gamma)dom(Γ) に含まれていてはならず、さもないと新しい仮定が既存の仮定をシャドーイングし、カーネルが不健全になる（第 11 章）。本書の intro はそのような名前を「binder name already in context」というメッセージで拒否するが、Lean は名前を付け替える。

exact t。 このタクティクは、与えられた項でゴールを閉じる。

⟨Γ⊢?m:T⟩  ⇝  no goals,?m:=t,\goal{\Gamma}{\hole{m}}{T} \;\leadsto\; \text{no goals}, \qquad \hole{m} \mathrel{:=} t,⟨Γ⊢?m​:T⟩⇝no goals,?m​:=t,

apply f。 fff が型 A1→⋯→An→BA_1 \to \cdots \to A_n \to BA1​→⋯→An​→B を持ち B≡TB \conv TB≡T であるとき、このタクティクは引数を新しいゴールとして残す。

⟨Γ⊢?m:T⟩  ⇝  ⟨Γ⊢?1:A1⟩,…,⟨Γ⊢?n:An⟩,?m:=f  ?1⋯?n.\goal{\Gamma}{\hole{m}}{T} \;\leadsto\; \goal{\Gamma}{\hole{1}}{A_1}, \ldots, \goal{\Gamma}{\hole{n}}{A_n}, \qquad \hole{m} \mathrel{:=} f\;\hole{1} \cdots \hole{n}.⟨Γ⊢?m​:T⟩⇝⟨Γ⊢?1​:A1​⟩,…,⟨Γ⊢?n​:An​⟩,?m​:=f?1​⋯?n​.

change T'。 このタクティクは、ゴールを定義的に等しいものに置き換える。

⟨Γ⊢?m:T⟩  ⇝  ⟨Γ⊢?1:T′⟩,?m:=?1,\goal{\Gamma}{\hole{m}}{T} \;\leadsto\; \goal{\Gamma}{\hole{1}}{T'}, \qquad \hole{m} \mathrel{:=} \hole{1},⟨Γ⊢?m​:T⟩⇝⟨Γ⊢?1​:T′⟩,?m​:=?1​,

ただし T′T'T′ は型で、T′≡TT' \conv TT′≡T でなければならない。項には何も加えず、ゴールの表示の仕方を変えるだけであり、それを正当化するのは T-Conv である。change が必要なのは、rw（後述）が部分項を α 同値までしか探さないからであり、計算してはじめて現れる部分項は、まず change で露出させなければならない。本章末尾の例がそうである。

帰納法

n:Natn : \Natn:Nat を Γ\GammaΓ の変数とし、Γ⊢T:Sort u\Gamma \vdash T : \Sort{u}Γ⊢T:Sortu とする。タクティク induction n は、ゴールの中の nnn を抽象化して motive を作り、構成子ごとに一つのゴールを生成する。

⟨Γ⊢?m:T⟩  ⇝  ⟨Γ⊢?z:T[n↦zero]⟩,  ⟨Γ,k:Nat,ih:T[n↦k]⊢?s:T[n↦succ  k]⟩,?m:=Nat.recu  (λ(z:Nat). T[n↦z])  ?z  (λ(k:Nat). λ(ih:T[n↦k]). ?s)  n.\begin{array}{l} \goal{\Gamma}{\hole{m}}{T} \;\leadsto\; \goal{\Gamma}{\hole{z}}{\subst{T}{n}{\zero}},\; \goal{\Gamma, k : \Nat, \mathit{ih} : \subst{T}{n}{k}}{\hole{s}}{\subst{T}{n}{\suc\;k}}, \\[4pt] \hole{m} \mathrel{:=} \NatRec{u}\;(\tLam{z}{\Nat}{\subst{T}{n}{z}})\;\hole{z}\;(\tLam{k}{\Nat}{\tLam{\mathit{ih}}{\subst{T}{n}{k}}{\hole{s}}})\;n. \end{array}⟨Γ⊢?m​:T⟩⇝⟨Γ⊢?z​:T[n↦zero]⟩,⟨Γ,k:Nat,ih:T[n↦k]⊢?s​:T[n↦succk]⟩,?m​:=Nat.recu​(λ(z:Nat).T[n↦z])?z​(λ(k:Nat).λ(ih:T[n↦k]).?s​)n.​

motive を M=λ(z:Nat). T[n↦z]M = \tLam{z}{\Nat}{\subst{T}{n}{z}}M=λ(z:Nat).T[n↦z] とすると、Nat.recu  M\NatRec{u}\;MNat.recu​M の型は M  zeroM\;\zeroMzero と Π(k:Nat). M  k→M  (succ  k)\tPi{k}{\Nat}{M\;k \to M\;(\suc\;k)}Π(k:Nat).Mk→M(succk) を求め、結果の型は M  nM\;nMn であり、これらは β により、二つのゴールの型および TTT と変換可能である。この構成が正しいのは、名前が新鮮で、レベル uuu が正しく、他のどの仮定も nnn に言及しないときに限る。

  • 他の仮定が nnn に言及しているとき、たとえば h:n=2h : n = 2h:n=2 があるとき、新しいゴールには元の nnn についての hhh が残ったままで、ih\mathit{ih}ih はそれについて何も言わず、ゴールは正しいが証明できないかもしれない。Lean の induction はそのような仮定をまずゴールの中に戻し（リバートし）、motive の一部にする一方、本書の実装では、後続の仮定が nnn に言及しないことを要求し、そうでなければ「induction: revert dependent hypotheses first」と報告する。

この実装は Nat\NatNat に固有のものではなく、添字を持たない任意の帰納型で動く。シグネチャから再帰子の型を読み、構成子ごとに小前提を一つずつ剥がし、それぞれを、構成子のフィールドと帰納法の仮定を文脈に持つゴールに変える。スクリプト examples/generic-list.leanmini は、ユーザーが宣言したリスト型に対してこれを使う。

書き換え

h:Equ  A  a  bh : \Eq{u}\;A\;a\;bh:Equ​Aab とし、ゴール TTT を命題とする。タクティク rw h は、ゴールの中の aaa を bbb に三段階で置き換える。

  1. 抽象化。 新鮮な xxx を選び、TTT の中の aaa のすべての出現を xxx で置き換えたものを CCC とする。出現は変換ではなく α 同値までで探す。aaa の自由変数を束縛する束縛子の下にある出現は、そこでは別のものを指すので飛ばす。
  2. motive の検査。 Γ,x:A⊢C:Sort 0\Gamma, x : A \vdash C : \Sort{0}Γ,x:A⊢C:Sort0 を検査する。これは後述のとおり失敗しうる。
  3. 項の構築。 新しいゴールは C[x↦b]\subst{C}{x}{b}C[x↦b]、つまり aaa を bbb に置き換えたゴールである。

motive の型が正しくないとき。 aaa を抽象化するとゴールが壊れることがある。Γ=n:Nat,  h:n=2,  q:n=0\Gamma = n : \Nat,\; h : n = 2,\; q : n = 0Γ=n:Nat,h:n=2,q:n=0 とし、証明 qqq についての主張であるゴール Eq0  (n=0)  q  q\Eq{0}\;(n = 0)\;q\;qEq0​(n=0)qq に rw h を実行したとしよう。nnn を抽象化すると C=Eq0  (x=0)  q  qC = \Eq{0}\;(x = 0)\;q\;qC=Eq0​(x=0)qq となるが、qqq の型は n=0n = 0n=0 であって x=0x = 0x=0 ではなく、qqq 自身は抽象化できないので、これは型が正しくない。段階 2 が失敗し、Lean も同じ状況を「motive is not type correct」と報告する。段階 2 がなければ、タクティクはカーネルに拒否される項を生成し、それは健全性には無害だが、ユーザーの役には立たない。

タクティクは src/proof.rs の ProofState のメソッドである。部分的な証明項は Template（src/template.rs）で、Hole(i) ノードを持つ項である。materialize は解を代入し、未解決のホールがあれば失敗する。ProofState::replace が割り当てを行い、現在のゴールの解を記録して、新しいゴールを先頭に継ぎ足す。intro、exact、apply、change、rfl、induction、rw はそれぞれ上の説明のとおりに動く。rw は段階 1 に replace_exact を、段階 2 に check_transport を使う。finish が qed であり、項を具体化して元のゴールに対して Kernel::check を呼ぶ。

例: タクティクによる 0 + n = n

本書の体系では、第 9 章の証明は次のスクリプトになり、これは examples/zero-add.leanmini に add\addadd の定義を含めたものである（スクリプトでは 0+n0 + n0+n を add Nat.zero n と書く）。

def add : Nat -> Nat -> Nat := fun (m : Nat) => fun (n : Nat) => Nat.rec1 (fun (_n : Nat) => Nat) m (fun (k : Nat) => fun (r : Nat) => Nat.succ r) n
goal forall (n : Nat), Eq Nat (add Nat.zero n) n
intro n
induction n
rfl
change Eq Nat (Nat.succ (add Nat.zero k)) (Nat.succ k)
rw ih
rfl
qed

部分項が育っていく様子を見てほしい。induction n が二つのホールを持つ Nat.rec0\NatRec{0}Nat.rec0​ を挿入し、rfl が最初のホールを埋め、change は項には触れずゴールだけを書き換え、rw ih が輸送を挿入して最後の rfl のためのホールを一つ残す。change の行を消してスクリプトを適用すると、rw が左辺を見つけられずに失敗するのが分かる。

# 第二引数に関する再帰による加法:
#   add m zero     = m
#   add m (succ k) = succ (add m k)
def add : Nat -> Nat -> Nat := fun (m : Nat) => fun (n : Nat) => Nat.rec1 (fun (_n : Nat) => Nat) m (fun (k : Nat) => fun (r : Nat) => Nat.succ r) n

# add zero n = n は定義的ではないので、n に関する帰納法が要る。
goal forall (n : Nat), Eq Nat (add Nat.zero n) n
intro n
induction n
# 基底ケース: add zero zero は zero に簡約される。
rfl
# ステップケース: add zero (succ k) を succ (add zero k) に展開し、ih を使う。
change Eq Nat (Nat.succ (add Nat.zero k)) (Nat.succ k)
rw ih

なぜタクティクを信頼する必要がないのか

カーネルが最終的な項を検査するので、体系が健全であるためにタクティクが正しい必要はない。バグのあるタクティクは、失敗するか、型の正しくない項を生成してカーネルに拒否されるかのどちらかであり、偽の定理をカーネルに受理させることはできない。exact の Check\CheckCheck や rw の motive の検査など、タクティク自身が行う検査は、エラーを早く分かりやすく報告するためにあるにすぎない。

したがって体系の信頼すべき部分は小さく、アルゴリズム 5.1、第 III 部の簡約関数と比較関数、そして第 8 章のシグネチャ構築手続きであり、src/proof.rs と src/syntax.rs の中身はすべてその外側にある。

Lean のタクティク基盤は、ここで素描したものよりはるかに豊かで、単一化で解かれるメタ変数、暗黙の引数を補い 0 + n のような記法を展開するエラボレータ、依存する仮定をリバートし添字付きの族も扱う induction、そして simp のような自動化がある。これらはすべて信頼されない側にあり、Lean のカーネルも本書のものと同じく、完成した項しか見ない [de Moura and Ullrich 2021]。

覚えておくこと

  • 証明状態は、ゴールのリストと、ホールを持つ部分項であり、タクティクは最初のホールに項を割り当て、新鮮なホールごとに新しいゴールを一つ開く。
  • intro は λ\lambdaλ を組み立て、exact は項を差し込み、apply は引数の位置にホールを持つ適用を組み立て、change は T-Conv を使い、rfl は refl\refl{}refl​ を使う。
  • induction は変数を motive へ抽象化して再帰子を適用し、rw は左辺を motive へ抽象化して輸送を適用する。
  • カーネルは完成した項を検査し直すので、タクティクは信頼基盤の外側にある。
