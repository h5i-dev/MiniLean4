Chapter 7

Inductive Types I: Natural Numbers

So far the only types are universes and Π\PiΠ-types. That is enough for propositional logic, but not for mathematics: there are no numbers to reason about and no way to state that two things are equal. Lean provides both through a single mechanism, inductive types. This chapter adds constants to the kernel, declares the natural numbers, and discovers that computing with numbers and proving things about them are the same operation.

Constants and definitions

First we need a way to add named objects to the kernel. Terms gain constants ccc:

t,A,B  ::=  ⋯  ∣  ct, A, B \;::=\; \cdots \;\mid\; ct,A,B::=⋯∣c

A signature Σ\SigmaΣ lists the constants. Each entry either declares a constant with its type, written c:Cc : Cc:C, or also gives it a body, written c:C:=tc : C \mathrel{:=} tc:C:=t. Entries with a body are definitions. For example, Nat:Sort 1\Nat : \Sort{1}Nat:Sort1 below is a declaration, and add\addadd later in this chapter is a definition. Before an entry is added, its type is checked to be a type in the empty context, and its body, if any, is checked against that type, exactly as Lean does for each def.

The signature is used in two ways. First, a constant has the type the signature gives it:

⊢Γ;ok(c:C)∈ΣΓ⊢c:C;(T-Const)\dfrac{\ctxok{\Gamma} \qquad (c : C) \in \Sigma}{\Gamma \vdash c : C}\rulename{T-Const}Γ⊢c:C⊢Γ;ok(c:C)∈Σ​;(T-Const)

where (c:C)∈Σ(c : C) \in \Sigma(c:C)∈Σ covers both declarations and definitions. Second, a definition can be unfolded: the constant is replaced by its body. This computation step is called delta-reduction:

c  →δ  tif (c:C:=t)∈Σ.c \;\deltared\; t \qquad \text{if } (c : C \mathrel{:=} t) \in \Sigma.c→δ​tif (c:C:=t)∈Σ.

For example, add  2  1→δ(λ(m:Nat). λ(n:Nat). ⋯ )  2  1\add\;2\;1 \deltared (\tLam{m}{\Nat}{\tLam{n}{\Nat}{\cdots}})\;2\;1add21→δ​(λ(m:Nat).λ(n:Nat).⋯)21, after which beta-reduction continues. A declared constant without a body, such as Nat\NatNat or zero\zerozero, never delta-reduces. Like beta, the step may be applied to any subterm.

Constants are not variables: they are never bound, so FV(c)=∅\FV(c) = \emptysetFV(c)=∅ and substitution leaves them unchanged. Reduction now consists of beta, delta, and the iota-rules introduced below, and definitional equality (Chapter 12) is taken with respect to all three.

The signature is the field decls: HashMap<String, Decl> of Kernel in src/kernel.rs. A Decl pairs a type with a DeclKind, which records whether the constant is an Axiom (declared, no body), a Definition(body), or one of the three kinds generated by an inductive declaration (Inductive, Constructor, Recursor). Kernel::axiom and Kernel::define add entries after the checks described above; infer handles T-Const by looking up the type; and whnf handles delta by unfolding a Definition.

Natural numbers

In Lean, the natural numbers are declared as

inductive Nat where
  | zero : Nat
  | succ (n : Nat) : Nat

The declaration says that every natural number is built in one of two ways: it is zero\zerozero, or it is succ  n\suc\;nsuccn, the successor of a natural number nnn. For example, 222 is succ  (succ  zero)\suc\;(\suc\;\zero)succ(succzero). In our kernel the declaration adds three constants without bodies:

Nat:Sort 1,zero:Nat,succ:Nat→Nat.\Nat : \Sort{1}, \qquad \zero : \Nat, \qquad \suc : \Nat \to \Nat.Nat:Sort1,zero:Nat,succ:Nat→Nat.

zero\zerozero and succ\sucsucc are called constructors. They build values but never compute: succ  (succ  zero)\suc\;(\suc\;\zero)succ(succzero) is already in normal form, and it is the number 222. We write 0,1,2,…0, 1, 2, \ldots0,1,2,… for zero\zerozero, succ  zero\suc\;\zerosucczero, succ  (succ  zero)\suc\;(\suc\;\zero)succ(succzero), and so on.

This gives us numbers, but nothing to do with them. A function such as addition must look at a number and act differently on zero\zerozero and on succ  n\suc\;nsuccn, and our terms have no way to do that yet. A λ\lambdaλ can only pass its argument along; it cannot inspect it.

Computing: addition

How should addition be defined? By recursion on the second argument:

add  m  zero=m,add  m  (succ  k)=succ  (add  m  k).\add\;m\;\zero = m, \qquad \add\;m\;(\suc\;k) = \suc\;(\add\;m\;k).addmzero=m,addm(succk)=succ(addmk).

Look at the shape of this definition. For a fixed mmm, the function add  m\add\;maddm is determined by two pieces of data: its value on zero\zerozero, which is mmm, and a way to turn its value rrr on kkk into its value on succ  k\suc\;ksucck, which is succ  r\suc\;rsuccr. Every function f:Nat→Cf : \Nat \to Cf:Nat→C defined by recursion of this kind, called structural recursion, has the same shape:

f  zero=z,f  (succ  k)=s  k  (f  k),f\;\zero = z, \qquad f\;(\suc\;k) = s\;k\;(f\;k),fzero=z,f(succk)=sk(fk),

for some z:Cz : Cz:C and s:Nat→C→Cs : \Nat \to C \to Cs:Nat→C→C. The step function sss receives both kkk and the result f  kf\;kfk of the recursive call. So we add one constant that builds fff from zzz and sss, once and for all:

recC:C→(Nat→C→C)→Nat→C,\mathsf{rec}_C : C \to (\Nat \to C \to C) \to \Nat \to C,recC​:C→(Nat→C→C)→Nat→C,

together with two computation rules, called iota-rules, which are exactly the equations above:

recC  z  s  zero  →ι  z,recC  z  s  (succ  n)  →ι  s  n  (recC  z  s  n).\mathsf{rec}_C\;z\;s\;\zero \;\iotared\; z, \qquad \mathsf{rec}_C\;z\;s\;(\suc\;n) \;\iotared\; s\;n\;(\mathsf{rec}_C\;z\;s\;n).recC​zszero→ι​z,recC​zs(succn)→ι​sn(recC​zsn).

Addition is now an ordinary, non-recursive definition:

add:Nat→Nat→Nat:=λ(m:Nat). λ(n:Nat). recNat  m  s  n,s=λ(k:Nat). λ(r:Nat). succ  r.\add : \Nat \to \Nat \to \Nat \mathrel{:=} \tLam{m}{\Nat}{\tLam{n}{\Nat}{\mathsf{rec}_{\Nat}\;m\;s\;n}}, \qquad s = \tLam{k}{\Nat}{\tLam{r}{\Nat}{\suc\;r}}.add:Nat→Nat→Nat:=λ(m:Nat).λ(n:Nat).recNat​msn,s=λ(k:Nat).λ(r:Nat).succr.

We write m+nm + nm+n for add  m  n\add\;m\;naddmn. The kernel computes 2+12 + 12+1 with delta, beta, and iota steps only. Step through it:

Other functions follow the same pattern. Doubling, with double  (succ  k)=succ  (succ  (double  k))\mathit{double}\;(\suc\;k) = \suc\;(\suc\;(\mathit{double}\;k))double(succk)=succ(succ(doublek)), is

and double  2→succ  (succ  (double  1))→succ4  (double  0)→succ4  zero=4\mathit{double}\;2 \to \suc\;(\suc\;(\mathit{double}\;1)) \to \suc^4\;(\mathit{double}\;0) \to \suc^4\;\zero = 4double2→succ(succ(double1))→succ4(double0)→succ4zero=4.

The interesting point is that no new recursion mechanism is needed. The constants of the inductive type, together with recC\mathsf{rec}_CrecC​ and its two rules, are enough to express every structurally recursive function on Nat\NatNat. And unlike general recursion, this one always terminates: each iota-step removes one succ\sucsucc from the argument.

Programmers know recC\mathsf{rec}_CrecC​ by another name: it is a fold over the natural numbers, in the same way that fold over a list replaces nil by a value and cons by a function. A fold cannot loop forever because it consumes its argument one constructor at a time. That is the price and the reward of structural recursion: less expressive than a while loop, but every program terminates, which a logic needs.

Proving: induction

Now consider proofs. To prove that a property P  nP\;nPn holds for every nnn, where P:Nat→Sort 0P : \Nat \to \Sort{0}P:Nat→Sort0, mathematics uses induction: prove the base case P  zeroP\;\zeroPzero, and the step Π(k:Nat). P  k→P  (succ  k)\tPi{k}{\Nat}{P\;k \to P\;(\suc\;k)}Π(k:Nat).Pk→P(succk), whose argument P  kP\;kPk is the induction hypothesis.

Through Curry-Howard, a proof of Π(n:Nat). P  n\tPi{n}{\Nat}{P\;n}Π(n:Nat).Pn is a function fff that takes nnn and returns a proof of P  nP\;nPn. How do we build such an fff from base:P  zero\mathit{base} : P\;\zerobase:Pzero and step\mathit{step}step? For 333, the proof is step  2  (step  1  (step  0  base))\mathit{step}\;2\;(\mathit{step}\;1\;(\mathit{step}\;0\;\mathit{base}))step2(step1(step0base)), and in general

f  zero=base,f  (succ  k)=step  k  (f  k).f\;\zero = \mathit{base}, \qquad f\;(\suc\;k) = \mathit{step}\;k\;(f\;k).fzero=base,f(succk)=stepk(fk).

This is a structurally recursive function again, with exactly the shape of add\addadd above: z=basez = \mathit{base}z=base and s=steps = \mathit{step}s=step. Induction is recursion that returns proofs.

There is one difference. For add\addadd, the result type CCC was the same for every nnn. Here it depends on nnn: f  zero:P  zerof\;\zero : P\;\zerofzero:Pzero, f  1:P  1f\;1 : P\;1f1:P1, and so on. So recC\mathsf{rec}_CrecC​, whose type mentions a fixed CCC, cannot express induction as it stands.

One recursor for both

Putting the two cases side by side shows what to generalize.

Recursion Induction
result for nnn CCC P  nP\;nPn
case zero\zerozero z:Cz : Cz:C base:P  zero\mathit{base} : P\;\zerobase:Pzero

The left column is the special case of the right column in which P  nP\;nPn is the same type CCC for every nnn. So we take the right column, with PPP replaced by an arbitrary function M:Nat→Sort uM : \Nat \to \Sort{u}M:Nat→Sortu that gives the type of the result for each nnn. This function is called the motive. The result is the recursor Nat.recu\NatRec{u}Nat.recu​ of Figure 7.1. Its arguments are the motive, one minor premise for each constructor, and finally the number nnn to recurse on, called the major premise. Its iota-rules are those of recC\mathsf{rec}_CrecC​. As in Lean, where the recursor is Nat.rec.{u}, there is one recursor for each universe level; since we have no universe polymorphism, the level is a subscript.

Induction. With a predicate M:Nat→Sort 0M : \Nat \to \Sort{0}M:Nat→Sort0 at level 000, the type of Nat.rec0\NatRec{0}Nat.rec0​ is the induction principle

M  zero→(∀n.  M  n→M  (succ  n))→∀n.  M  n.M\;\zero \to (\forall n.\; M\;n \to M\;(\suc\;n)) \to \forall n.\; M\;n.Mzero→(∀n.Mn→M(succn))→∀n.Mn.

Here the choice of imax\imaximax in T-Pi is essential. The conclusion Π(n:Nat). M  n\tPi{n}{\Nat}{M\;n}Π(n:Nat).Mn has type Sort imax(1,0)=Sort 0\Sort{\imax(1, 0)} = \Sort{0}Sortimax(1,0)=Sort0, so "M  nM\;nMn for every nnn" is a proposition although Nat\NatNat lives in Sort 1\Sort{1}Sort1. With max⁡\maxmax instead, it would live in Sort 1\Sort{1}Sort1, and statements about numbers would not be propositions at all.

The type of Nat.recu\NatRec{u}Nat.recu​ is not arbitrary: it can be read off the declaration of Nat\NatNat. There is one minor premise per constructor. Each minor premise takes the constructor's arguments, plus one induction hypothesis for each argument whose type is Nat\NatNat itself (a recursive argument), and returns the motive applied to the constructor. zero\zerozero has no arguments, so its case is just M  zeroM\;\zeroMzero; succ\sucsucc has one recursive argument nnn, so its case is Π(n:Nat). M  n→M  (succ  n)\tPi{n}{\Nat}{M\;n \to M\;(\suc\;n)}Π(n:Nat).Mn→M(succn). Chapter 8 applies this recipe to more and more general declarations.

Try it

The kernel starts with Nat\NatNat and its recursors already declared (Kernel::standard in src/kernel.rs). The script below defines addition and asks the kernel to confirm that 2+12 + 12+1 and 333 are definitionally equal, which rfl does by computing both sides. Try changing three to Nat.succ three and see the kernel refuse.

def add : Nat -> Nat -> Nat := fun (m : Nat) => fun (n : Nat) => Nat.rec1 (fun (_n : Nat) => Nat) m (fun (k : Nat) => fun (r : Nat) => Nat.succ r) n
def one : Nat := Nat.succ Nat.zero
def two : Nat := Nat.succ one
def three : Nat := Nat.succ two
# Both sides compute to succ (succ (succ zero)), so refl proves this.
goal Eq Nat (add two one) three
rfl
qed

The Eq in the goal is the equality type, declared in Chapter 9. For now, read Eq Nat a b as "a=ba = ba=b" and rfl as "both sides compute to the same thing".

Lean generates Nat.rec from the inductive declaration exactly as described here, and its type agrees with Figure 7.1 up to the names of bound variables and implicit arguments. Lean's compiler then replaces the recursor by efficient machine arithmetic for execution, and its elaborator lets users write recursive functions by pattern matching, compiling them to recursors behind the scenes. The kernel, however, only ever sees recursors.

Why can the kernel not accept a general fixed-point combinator fix:(C→C)→C\mathsf{fix} : (C \to C) \to Cfix:(C→C)→C with the rule fix  g→g  (fix  g)\mathsf{fix}\;g \to g\;(\mathsf{fix}\;g)fixg→g(fixg), which would make every recursive function definable?

Solution

With C=Π(P:Sort 0). PC = \tPi{P}{\Sort{0}}{P}C=Π(P:Sort0).P and g=λ(x:C). xg = \tLam{x}{C}{x}g=λ(x:C).x, the term fix  g\mathsf{fix}\;gfixg would have type Π(P:Sort 0). P\tPi{P}{\Sort{0}}{P}Π(P:Sort0).P, a proof of everything, and the system would be inconsistent. It also reduces to itself forever, so IsDefEq\IsDefEqIsDefEq would not terminate. Structural recursion avoids both problems because every iota-step consumes a constructor.

What to remember

  • Constants come from a signature Σ\SigmaΣ; definitions unfold by delta-reduction, declarations never do.
  • An inductive type adds a type former and constructors, which build values and do not compute.
  • Structural recursion on Nat\NatNat is captured by one constant, the recursor, with one iota-rule per constructor.
  • Induction is the same recursor with a dependent motive M:Nat→Sort 0M : \Nat \to \Sort{0}M:Nat→Sort0. Recursion and induction are one operation.
  • The imax\imaximax rule is what makes "for all nnn, M  nM\;nMn" a proposition.
