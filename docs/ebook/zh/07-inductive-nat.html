第 7 章

归纳类型 I：自然数

到目前为止，我们只有宇宙和 Π\PiΠ 类型，它们足以处理命题逻辑，但数学还需要自然数，以及表达两个对象相等的方式。Lean 通过归纳类型提供这两者。本章给内核加入常量并声明自然数，说明同一种机制如何支持关于数的计算与证明。

常量与定义

首先需要一种给内核添加具名对象的方式。项新增常量（constant）ccc：

t,A,B  ::=  ⋯  ∣  ct, A, B \;::=\; \cdots \;\mid\; ct,A,B::=⋯∣c

签名（signature）Σ\SigmaΣ 列出所有常量，每个条目要么只声明一个常量及其类型，写作 c:Cc : Cc:C；要么还给出它的体，写作 c:C:=tc : C \mathrel{:=} tc:C:=t，带体的条目是定义。例如，下文的 Nat:Sort 1\Nat : \Sort{1}Nat:Sort1 是声明，而本章后面的 add\addadd 是定义。在添加一个条目之前，要先在空上下文中检查它的类型确实是类型；如果有体，还要对照该类型检查它的体，正如 Lean 对每个 def 所做的那样。

签名有两种用法。其一，常量的类型就是签名给它的类型：

⊢Γ;ok(c:C)∈ΣΓ⊢c:C;(T-Const)\dfrac{\ctxok{\Gamma} \qquad (c : C) \in \Sigma}{\Gamma \vdash c : C}\rulename{T-Const}Γ⊢c:C⊢Γ;ok(c:C)∈Σ​;(T-Const)

其中 (c:C)∈Σ(c : C) \in \Sigma(c:C)∈Σ 同时涵盖声明和定义。其二，定义可以被展开：用它的体替换该常量。这一计算步骤称为 δ 归约（delta-reduction）：

c  →δ  tif (c:C:=t)∈Σ.c \;\deltared\; t \qquad \text{if } (c : C \mathrel{:=} t) \in \Sigma.c→δ​tif (c:C:=t)∈Σ.

例如 add  2  1→δ(λ(m:Nat). λ(n:Nat). ⋯ )  2  1\add\;2\;1 \deltared (\tLam{m}{\Nat}{\tLam{n}{\Nat}{\cdots}})\;2\;1add21→δ​(λ(m:Nat).λ(n:Nat).⋯)21，之后 β 归约继续进行。没有体的已声明常量，例如 Nat\NatNat 或 zero\zerozero，永远不会 δ 归约。与 β 一样，这一步可以应用于任何子项。

常量不是变量：它们从不被绑定，所以 FV(c)=∅\FV(c) = \emptysetFV(c)=∅，替换也保持它们不变。现在归约由 β、δ 以及下面引入的 ι 规则组成，而定义相等（第 12 章）是相对于这三者定义的。

签名是 src/kernel.rs 中 Kernel 的字段 decls: HashMap<String, Decl>。一个 Decl 把类型与一个 DeclKind 配对，后者记录该常量是 Axiom（已声明、无体）、Definition(body)，还是由归纳声明生成的三种之一（Inductive、Constructor、Recursor）。Kernel::axiom 和 Kernel::define 在完成上述检查后添加条目；infer 通过查找类型来处理 T-Const；whnf 通过展开 Definition 来处理 δ。

自然数

在 Lean 中，自然数声明为

inductive Nat where
  | zero : Nat
  | succ (n : Nat) : Nat

这个声明说，每个自然数都以两种方式之一构造：它是 zero\zerozero，或者是 succ  n\suc\;nsuccn，即某个自然数 nnn 的后继。例如，222 是 succ  (succ  zero)\suc\;(\suc\;\zero)succ(succzero)。在我们的内核中，这个声明添加三个没有体的常量：

Nat:Sort 1,zero:Nat,succ:Nat→Nat.\Nat : \Sort{1}, \qquad \zero : \Nat, \qquad \suc : \Nat \to \Nat.Nat:Sort1,zero:Nat,succ:Nat→Nat.

zero\zerozero 和 succ\sucsucc 称为构造子（constructor），它们构造值，但从不计算：succ  (succ  zero)\suc\;(\suc\;\zero)succ(succzero) 已经是范式，它就是数 222。我们用 0,1,2,…0, 1, 2, \ldots0,1,2,… 表示 zero\zerozero、succ  zero\suc\;\zerosucczero、succ  (succ  zero)\suc\;(\suc\;\zero)succ(succzero) 等等。

现在我们有了数，却还无法用它们计算：加法需要区分 zero\zerozero 和 succ  n\suc\;nsuccn，而目前的项只能传递参数，无法检查它的结构。

计算：加法

加法应当如何定义？对第二个参数做递归：

add  m  zero=m,add  m  (succ  k)=succ  (add  m  k).\add\;m\;\zero = m, \qquad \add\;m\;(\suc\;k) = \suc\;(\add\;m\;k).addmzero=m,addm(succk)=succ(addmk).

看看这个定义的形状。固定 mmm 后，函数 add  m\add\;maddm 由两份数据决定：它在 zero\zerozero 上的值，即 mmm；以及一种把它在 kkk 上的值 rrr 变成它在 succ  k\suc\;ksucck 上的值的方法，即 succ  r\suc\;rsuccr。每个用这种递归（称为结构递归，structural recursion）定义的函数 f:Nat→Cf : \Nat \to Cf:Nat→C 都具有相同的形状：

f  zero=z,f  (succ  k)=s  k  (f  k),f\;\zero = z, \qquad f\;(\suc\;k) = s\;k\;(f\;k),fzero=z,f(succk)=sk(fk),

其中 z:Cz : Cz:C，s:Nat→C→Cs : \Nat \to C \to Cs:Nat→C→C，步骤函数 sss 同时接收 kkk 和递归调用的结果 f  kf\;kfk。于是我们一劳永逸地添加一个常量，它从 zzz 和 sss 构造出 fff：

recC:C→(Nat→C→C)→Nat→C,\mathsf{rec}_C : C \to (\Nat \to C \to C) \to \Nat \to C,recC​:C→(Nat→C→C)→Nat→C,

并配上两条计算规则，称为 ι 规则（iota-rules），它们就是上面的两个等式：

recC  z  s  zero  →ι  z,recC  z  s  (succ  n)  →ι  s  n  (recC  z  s  n).\mathsf{rec}_C\;z\;s\;\zero \;\iotared\; z, \qquad \mathsf{rec}_C\;z\;s\;(\suc\;n) \;\iotared\; s\;n\;(\mathsf{rec}_C\;z\;s\;n).recC​zszero→ι​z,recC​zs(succn)→ι​sn(recC​zsn).

现在加法是一个普通的、非递归的定义：

add:Nat→Nat→Nat:=λ(m:Nat). λ(n:Nat). recNat  m  s  n,s=λ(k:Nat). λ(r:Nat). succ  r.\add : \Nat \to \Nat \to \Nat \mathrel{:=} \tLam{m}{\Nat}{\tLam{n}{\Nat}{\mathsf{rec}_{\Nat}\;m\;s\;n}}, \qquad s = \tLam{k}{\Nat}{\tLam{r}{\Nat}{\suc\;r}}.add:Nat→Nat→Nat:=λ(m:Nat).λ(n:Nat).recNat​msn,s=λ(k:Nat).λ(r:Nat).succr.

我们把 add  m  n\add\;m\;naddmn 写作 m+nm + nm+n。内核只用 δ、β 和 ι 步骤就能算出 2+12 + 12+1，下面的浏览器就是内核在做这件事，一次一个头步骤，并已加载 add\addadd 的定义。

def add : Nat -> Nat -> Nat := fun (m : Nat) => fun (n : Nat) => Nat.rec1 (fun (_n : Nat) => Nat) m (fun (k : Nat) => fun (r : Nat) => Nat.succ r) n

每一行是一个头步骤：高亮部分是可归约式（redex），下一行显示它变成了什么。改动数字，或者在上下文 n : Nat 下试试 add Nat.zero n，就能看到递归子卡住。

其他函数遵循同样的模式：满足 double  (succ  k)=succ  (succ  (double  k))\mathit{double}\;(\suc\;k) = \suc\;(\suc\;(\mathit{double}\;k))double(succk)=succ(succ(doublek)) 的加倍函数是

double:=λ(n:Nat). recNat  zero  (λ(k:Nat). λ(r:Nat). succ  (succ  r))  n,\mathit{double} \mathrel{:=} \tLam{n}{\Nat}{\mathsf{rec}_{\Nat}\;\zero\;(\tLam{k}{\Nat}{\tLam{r}{\Nat}{\suc\;(\suc\;r)}})\;n},double:=λ(n:Nat).recNat​zero(λ(k:Nat).λ(r:Nat).succ(succr))n,

并且 double  2→succ  (succ  (double  1))→succ4  (double  0)→succ4  zero=4\mathit{double}\;2 \to \suc\;(\suc\;(\mathit{double}\;1)) \to \suc^4\;(\mathit{double}\;0) \to \suc^4\;\zero = 4double2→succ(succ(double1))→succ4(double0)→succ4zero=4。

不需要新的递归机制：归纳类型的常量，加上 recC\mathsf{rec}_CrecC​ 及其两条规则，足以表达 Nat\NatNat 上所有的结构递归函数。而且与一般递归不同，这种递归总是终止：每一个 ι 步骤都从参数中去掉一个 succ\sucsucc。

对程序员来说，recC\mathsf{rec}_CrecC​ 就是自然数上的 fold：正如列表的 fold 用一个值处理 nil、用一个函数处理 cons。fold 每次处理参数的一个构造子，因此不会无限循环。它不如 while 循环灵活，但能保证程序终止，而逻辑需要这一保证。

证明：归纳

现在考虑证明。要证明性质 P  nP\;nPn 对每个 nnn 成立，其中 P:Nat→Sort 0P : \Nat \to \Sort{0}P:Nat→Sort0，数学上使用归纳法：证明基础情形 P  zeroP\;\zeroPzero，以及归纳步骤 Π(k:Nat). P  k→P  (succ  k)\tPi{k}{\Nat}{P\;k \to P\;(\suc\;k)}Π(k:Nat).Pk→P(succk)，后者的参数 P  kP\;kPk 就是归纳假设。

通过 Curry-Howard 对应，Π(n:Nat). P  n\tPi{n}{\Nat}{P\;n}Π(n:Nat).Pn 的证明是一个函数 fff，它接收 nnn 并返回 P  nP\;nPn 的证明。如何从 base:P  zero\mathit{base} : P\;\zerobase:Pzero 和 step\mathit{step}step 构造出这样的 fff？对于 333，证明是 step  2  (step  1  (step  0  base))\mathit{step}\;2\;(\mathit{step}\;1\;(\mathit{step}\;0\;\mathit{base}))step2(step1(step0base))，一般地

f  zero=base,f  (succ  k)=step  k  (f  k).f\;\zero = \mathit{base}, \qquad f\;(\suc\;k) = \mathit{step}\;k\;(f\;k).fzero=base,f(succk)=stepk(fk).

这又是一个结构递归函数，形状与上面的 add\addadd 完全相同：z=basez = \mathit{base}z=base，s=steps = \mathit{step}s=step。归纳就是返回证明的递归。

区别在于结果类型：add\addadd 对每个 nnn 都返回同一类型 CCC，而证明的类型依赖于 nnn，例如 f  zero:P  zerof\;\zero : P\;\zerofzero:Pzero、f  1:P  1f\;1 : P\;1f1:P1。因此，类型中带有固定 CCC 的 recC\mathsf{rec}_CrecC​ 还无法表达归纳。

动手试试

内核启动时已经声明了 Nat\NatNat 及其递归子（src/kernel.rs 中的 Kernel::standard）。下面的脚本定义加法，并请内核确认 2+12 + 12+1 与 333 定义相等，rfl 通过计算两边来完成这一点。试着把 three 改成 Nat.succ three，看看内核如何拒绝。

def add : Nat -> Nat -> Nat := fun (m : Nat) => fun (n : Nat) => Nat.rec1 (fun (_n : Nat) => Nat) m (fun (k : Nat) => fun (r : Nat) => Nat.succ r) n
def one : Nat := Nat.succ Nat.zero
def two : Nat := Nat.succ one
def three : Nat := Nat.succ two
# 两边都计算到 succ (succ (succ zero))，所以 refl 能证明它。
goal Eq Nat (add two one) three
rfl
qed

目标中的 Eq 是相等类型，将在第 9 章声明。目前可以把 Eq Nat a b 读作“a=ba = ba=b”，把 rfl 读作“两边计算到同一个东西”。

Lean 按本章所述从 inductive 声明生成 Nat.rec，其类型与图 7.1 一致，只差约束变量的名字和隐式参数。Lean 的编译器在执行时把递归子替换为高效的机器算术；它的繁饰器允许用户用模式匹配编写递归函数，并在幕后把它们编译成递归子，但内核看到的始终只有递归子。

内核为什么不能接受一般的不动点组合子 fix:(C→C)→C\mathsf{fix} : (C \to C) \to Cfix:(C→C)→C 及其规则 fix  g→g  (fix  g)\mathsf{fix}\;g \to g\;(\mathsf{fix}\;g)fixg→g(fixg)？有了它，每个递归函数都能定义出来。

解答

取 C=Π(P:Sort 0). PC = \tPi{P}{\Sort{0}}{P}C=Π(P:Sort0).P 和 g=λ(x:C). xg = \tLam{x}{C}{x}g=λ(x:C).x，项 fix  g\mathsf{fix}\;gfixg 的类型将是 Π(P:Sort 0). P\tPi{P}{\Sort{0}}{P}Π(P:Sort0).P，即一切命题的证明，系统因此不一致；它还会永远归约到自身，所以 IsDefEq\IsDefEqIsDefEq 不会终止。结构递归避免了这两个问题，因为每个 ι 步骤都消耗一个构造子。

要点回顾

  • 常量来自签名 Σ\SigmaΣ；定义通过 δ 归约展开，声明永远不展开。
  • 归纳类型添加一个类型构造器和若干构造子；构造子构造值，不做计算。
  • Nat\NatNat 上的结构递归由一个常量即递归子来刻画，每个构造子对应一条 ι 规则。
  • 归纳就是同一个递归子配上依赖 motive M:Nat→Sort 0M : \Nat \to \Sort{0}M:Nat→Sort0。递归和归纳是同一种操作。
  • imax\imaximax 规则使“对所有 nnn，M  nM\;nMn”成为命题。
