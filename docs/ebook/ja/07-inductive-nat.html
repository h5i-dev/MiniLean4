第 7 章

帰納型 I: 自然数

ここまでに扱った型は宇宙と Π\PiΠ 型だけであり、命題論理には足りても、数学に必要な数や等しさを表す手段はまだない。Lean はその両方を帰納型で提供する。本章ではカーネルに定数を加えて自然数を宣言し、同じ仕組みで数の計算と証明を扱えることを示す。

定数と定義

まず、名前のついた対象をカーネルに追加する手段が要るので、項に定数（constant）ccc を加える。

t,A,B  ::=  ⋯  ∣  ct, A, B \;::=\; \cdots \;\mid\; ct,A,B::=⋯∣c

シグネチャ（signature）Σ\SigmaΣ は定数を列挙する。各項目は、定数をその型とともに宣言する（c:Cc : Cc:C と書く）か、さらに本体も与える（c:C:=tc : C \mathrel{:=} tc:C:=t と書く）かのどちらかである。本体をもつ項目を定義（definition）と呼ぶ。たとえば、下の Nat:Sort 1\Nat : \Sort{1}Nat:Sort1 は宣言で、本章の後半に出てくる add\addadd は定義である。項目を追加する前に、その型が空の文脈で型であることを検査し、本体があればそれをその型に対して検査する。Lean が各 def に対して行うのと同じである。

シグネチャは二通りに使われる。第一に、定数はシグネチャが与える型をもつ。

⊢Γ;ok(c:C)∈ΣΓ⊢c:C;(T-Const)\dfrac{\ctxok{\Gamma} \qquad (c : C) \in \Sigma}{\Gamma \vdash c : C}\rulename{T-Const}Γ⊢c:C⊢Γ;ok(c:C)∈Σ​;(T-Const)

ここで (c:C)∈Σ(c : C) \in \Sigma(c:C)∈Σ は宣言と定義の両方を含む。第二に、定義は展開（unfold）でき、定数をその本体で置き換えるこの計算ステップを δ 簡約（delta-reduction）と呼ぶ。

c  →δ  tif (c:C:=t)∈Σ.c \;\deltared\; t \qquad \text{if } (c : C \mathrel{:=} t) \in \Sigma.c→δ​tif (c:C:=t)∈Σ.

たとえば add  2  1→δ(λ(m:Nat). λ(n:Nat). ⋯ )  2  1\add\;2\;1 \deltared (\tLam{m}{\Nat}{\tLam{n}{\Nat}{\cdots}})\;2\;1add21→δ​(λ(m:Nat).λ(n:Nat).⋯)21 であり、その後は β 簡約が続く。Nat\NatNat や zero\zerozero のような本体のない宣言された定数は、決して δ 簡約されない。β と同様に、このステップはどの部分項にも適用できる。

定数は変数ではなく、決して束縛されないので、FV(c)=∅\FV(c) = \emptysetFV(c)=∅ であり、代入は定数を変えない。簡約はここから β、δ、そして以下で導入する ι 規則からなり、定義的等価（第 12 章）はこの三つすべてに関して定められる。

シグネチャは src/kernel.rs の Kernel のフィールド decls: HashMap<String, Decl> である。Decl は型と DeclKind の組で、DeclKind はその定数が Axiom（宣言のみ、本体なし）か、Definition(body) か、帰納的宣言から生成される三種類（Inductive、Constructor、Recursor）のいずれかを記録する。Kernel::axiom と Kernel::define は、上で述べた検査の後に項目を追加する。infer は型を引くことで T-Const を扱い、whnf は Definition を展開することで δ を扱う。

自然数

Lean では、自然数は次のように宣言される。

inductive Nat where
  | zero : Nat
  | succ (n : Nat) : Nat

この宣言によれば、自然数は zero\zerozero か、ある自然数 nnn の後続数 succ  n\suc\;nsuccn として作られる。たとえば 222 は succ  (succ  zero)\suc\;(\suc\;\zero)succ(succzero) である。私たちのカーネルでは、この宣言によって本体のない三つの定数が追加される。

Nat:Sort 1,zero:Nat,succ:Nat→Nat.\Nat : \Sort{1}, \qquad \zero : \Nat, \qquad \suc : \Nat \to \Nat.Nat:Sort1,zero:Nat,succ:Nat→Nat.

zero\zerozero と succ\sucsucc を構成子（constructor）と呼ぶ。構成子は値を作るが決して計算しないので、succ  (succ  zero)\suc\;(\suc\;\zero)succ(succzero) はすでに正規形であり、それ自体が数 222 である。以下では zero\zerozero、succ  zero\suc\;\zerosucczero、succ  (succ  zero)\suc\;(\suc\;\zero)succ(succzero) などを 0,1,2,…0, 1, 2, \ldots0,1,2,… と書く。

これで数は手に入ったが、まだ計算には使えない。加法には zero\zerozero と succ  n\suc\;nsuccn を区別する手段が必要なのに、今の項は引数を受け渡すだけで、その中身を調べられないからである。

計算: 加法

加法はどう定義すべきか。第二引数に関する再帰で定義する。

add  m  zero=m,add  m  (succ  k)=succ  (add  m  k).\add\;m\;\zero = m, \qquad \add\;m\;(\suc\;k) = \suc\;(\add\;m\;k).addmzero=m,addm(succk)=succ(addmk).

この定義の形に注目してほしい。mmm を固定すると、関数 add  m\add\;maddm は二つのデータ、すなわち zero\zerozero での値（これは mmm）と、kkk での値 rrr を succ  k\suc\;ksucck での値に変える方法（これは succ  r\suc\;rsuccr）で決まる。この種の再帰を構造的再帰（structural recursion）と呼び、構造的再帰で定義される関数 f:Nat→Cf : \Nat \to Cf:Nat→C はどれも同じ形をしている。

f  zero=z,f  (succ  k)=s  k  (f  k),f\;\zero = z, \qquad f\;(\suc\;k) = s\;k\;(f\;k),fzero=z,f(succk)=sk(fk),

ここで z:Cz : Cz:C、s:Nat→C→Cs : \Nat \to C \to Cs:Nat→C→C である。ステップ関数 sss は、kkk と再帰呼び出しの結果 f  kf\;kfk の両方を受け取る。そこで、zzz と sss から fff を組み立てる定数を一つ、一度だけ追加する。

recC:C→(Nat→C→C)→Nat→C,\mathsf{rec}_C : C \to (\Nat \to C \to C) \to \Nat \to C,recC​:C→(Nat→C→C)→Nat→C,

これに二つの計算規則を添える。ι 規則（iota-rule）と呼ばれるもので、上の等式そのものである。

recC  z  s  zero  →ι  z,recC  z  s  (succ  n)  →ι  s  n  (recC  z  s  n).\mathsf{rec}_C\;z\;s\;\zero \;\iotared\; z, \qquad \mathsf{rec}_C\;z\;s\;(\suc\;n) \;\iotared\; s\;n\;(\mathsf{rec}_C\;z\;s\;n).recC​zszero→ι​z,recC​zs(succn)→ι​sn(recC​zsn).

加法はこれで、再帰を含まないふつうの定義になる。

add:Nat→Nat→Nat:=λ(m:Nat). λ(n:Nat). recNat  m  s  n,s=λ(k:Nat). λ(r:Nat). succ  r.\add : \Nat \to \Nat \to \Nat \mathrel{:=} \tLam{m}{\Nat}{\tLam{n}{\Nat}{\mathsf{rec}_{\Nat}\;m\;s\;n}}, \qquad s = \tLam{k}{\Nat}{\tLam{r}{\Nat}{\suc\;r}}.add:Nat→Nat→Nat:=λ(m:Nat).λ(n:Nat).recNat​msn,s=λ(k:Nat).λ(r:Nat).succr.

add  m  n\add\;m\;naddmn を m+nm + nm+n と書くと、カーネルは 2+12 + 12+1 を δ、β、ι のステップだけで計算する。下のエクスプローラは、add\addadd の定義を読み込んだカーネルが、頭部ステップを一度に一つずつ実行しているところである。

def add : Nat -> Nat -> Nat := fun (m : Nat) => fun (n : Nat) => Nat.rec1 (fun (_n : Nat) => Nat) m (fun (k : Nat) => fun (r : Nat) => Nat.succ r) n

各行が一つの頭部ステップであり、強調された部分が簡約基（redex）で、次の行にその結果が示される。数字を変えてみるか、文脈 n : Nat で add Nat.zero n を試して、再帰子が行き詰まるところを見てほしい。

ほかの関数も同じパターンに従う。double  (succ  k)=succ  (succ  (double  k))\mathit{double}\;(\suc\;k) = \suc\;(\suc\;(\mathit{double}\;k))double(succk)=succ(succ(doublek)) となる二倍は、

であり、double  2→succ  (succ  (double  1))→succ4  (double  0)→succ4  zero=4\mathit{double}\;2 \to \suc\;(\suc\;(\mathit{double}\;1)) \to \suc^4\;(\mathit{double}\;0) \to \suc^4\;\zero = 4double2→succ(succ(double1))→succ4(double0)→succ4zero=4 となる。

帰納型の定数と、recC\mathsf{rec}_CrecC​ およびその二つの規則だけで Nat\NatNat 上の構造的再帰関数はすべて表せるので、新しい再帰の仕組みは要らない。しかも一般の再帰と違って、各 ι ステップが引数から succ\sucsucc を一つ取り除くので、この再帰は必ず停止する。

プログラマにとって、recC\mathsf{rec}_CrecC​ は自然数上の fold（畳み込み）であり、リストの fold が nil を値で、cons を関数で置き換えるのと同じである。fold は引数の構成子を一つずつ処理するため、無限ループしない。while ループほど自由には書けないが、どのプログラムも停止する。論理にはこの性質が必要である。

証明: 帰納法

次に証明を考える。P:Nat→Sort 0P : \Nat \to \Sort{0}P:Nat→Sort0 について、性質 P  nP\;nPn がすべての nnn で成り立つことを示すには、数学では帰納法を使い、基底ケース（base case）P  zeroP\;\zeroPzero と、帰納ステップ（step）Π(k:Nat). P  k→P  (succ  k)\tPi{k}{\Nat}{P\;k \to P\;(\suc\;k)}Π(k:Nat).Pk→P(succk) を証明する。帰納ステップの引数 P  kP\;kPk が帰納法の仮定（induction hypothesis）である。

Curry-Howard を通して見ると、Π(n:Nat). P  n\tPi{n}{\Nat}{P\;n}Π(n:Nat).Pn の証明とは、nnn を受け取って P  nP\;nPn の証明を返す関数 fff である。base:P  zero\mathit{base} : P\;\zerobase:Pzero と step\mathit{step}step から、そのような fff をどう作るか。333 に対する証明は step  2  (step  1  (step  0  base))\mathit{step}\;2\;(\mathit{step}\;1\;(\mathit{step}\;0\;\mathit{base}))step2(step1(step0base)) であり、一般には

となる。これもまた構造的再帰関数であり、上の add\addadd とまったく同じ形をしており、z=basez = \mathit{base}z=base、s=steps = \mathit{step}s=step である。帰納法とは、証明を返す再帰である。

違いは結果の型にあり、add\addadd ではどの nnn に対しても同じ型 CCC だったが、証明では f  zero:P  zerof\;\zero : P\;\zerofzero:Pzero、f  1:P  1f\;1 : P\;1f1:P1 のように nnn に依存する。recC\mathsf{rec}_CrecC​ の型には固定された CCC が現れるため、このままでは帰納法を表せない。

試してみる

カーネルは、Nat\NatNat とその再帰子をあらかじめ宣言した状態で始まる（src/kernel.rs の Kernel::standard）。下のスクリプトは加法を定義し、2+12 + 12+1 と 333 が定義的に等しいことをカーネルに確かめさせ、rfl は両辺を計算してこれを行う。three を Nat.succ three に変えて、カーネルが拒否するのを見てほしい。

def add : Nat -> Nat -> Nat := fun (m : Nat) => fun (n : Nat) => Nat.rec1 (fun (_n : Nat) => Nat) m (fun (k : Nat) => fun (r : Nat) => Nat.succ r) n
def one : Nat := Nat.succ Nat.zero
def two : Nat := Nat.succ one
def three : Nat := Nat.succ two
# 両辺とも succ (succ (succ zero)) に計算されるので、refl でこれを証明できる。
goal Eq Nat (add two one) three
rfl
qed

ゴールの Eq は等式型であり、第 9 章 で宣言する。今のところは、Eq Nat a b を「a=ba = ba=b」、rfl を「両辺は同じものに計算される」と読んでおけばよい。

Lean は、ここで述べたとおりに inductive 宣言から Nat.rec を生成し、その型は、束縛変数の名前と暗黙の引数を除けば図 7.1 と一致する。Lean のコンパイラは、実行時には再帰子を効率的な機械の算術で置き換える。エラボレータは、利用者がパターンマッチで再帰関数を書くことを許し、裏でそれを再帰子にコンパイルするが、カーネルが目にするのは再帰子だけである。

解答

C=Π(P:Sort 0). PC = \tPi{P}{\Sort{0}}{P}C=Π(P:Sort0).P、g=λ(x:C). xg = \tLam{x}{C}{x}g=λ(x:C).x とすると、項 fix  g\mathsf{fix}\;gfixg は型 Π(P:Sort 0). P\tPi{P}{\Sort{0}}{P}Π(P:Sort0).P をもつことになり、これはあらゆる命題の証明であって、体系は整合性を失う。さらにこの項は自分自身へ際限なく簡約されるので、IsDefEq\IsDefEqIsDefEq が停止しない。構造的再帰は、各 ι ステップが構成子を一つ消費するので、どちらの問題も起こさない。

覚えておくこと

  • 定数はシグネチャ Σ\SigmaΣ に由来し、定義は δ 簡約で展開され、宣言は決して展開されない。
  • 帰納型は型構成子と構成子を追加し、構成子は値を作るが計算はしない。
  • Nat\NatNat 上の構造的再帰は、再帰子という一つの定数に集約され、ι 規則は構成子ごとに一つである。
  • 帰納法は、依存的な motive M:Nat→Sort 0M : \Nat \to \Sort{0}M:Nat→Sort0 を与えた同じ再帰子である。再帰と帰納法は一つの操作である。
  • imax\imaximax の規則があるからこそ、「すべての nnn について M  nM\;nMn」は命題になる。
