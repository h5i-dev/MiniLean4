Universes: Why Sort u?

What is the type of Sort 0\Sort{0}Sort0? Putting it in itself makes the system inconsistent. Lean instead uses the hierarchy Sort 0:Sort 1:Sort 2:⋯\Sort{0} : \Sort{1} : \Sort{2} : \cdotsSort0:Sort1:Sort2:⋯, with an impredicative bottom universe. That choice also explains the imax\imaximax in the T-Pi rule.

What is the type of Sort 0?

A proposition variable appears in the type theory as an assumption P:Sort 0P : \Sort{0}P:Sort0. It can occur in two places: in a context, as in the left judgment below, or bound by λ\lambdaλ or Π\PiΠ, as in the right one:

P:Sort 0⊢λ(h:P). h:P→Pversus⊢λ(P:Sort 0). λ(h:P). h:Π(P:Sort 0). P→P.P : \Sort{0} \vdash \tLam{h}{P}{h} : P \to P \qquad\text{versus}\qquad \vdash \tLam{P}{\Sort{0}}{\tLam{h}{P}{h}} : \tPi{P}{\Sort{0}}{P \to P}.P:Sort0⊢λ(h:P).h:P→Pversus⊢λ(P:Sort0).λ(h:P).h:Π(P:Sort0).P→P.

The left judgment proves P→PP \to PP→P for one fixed PPP supplied from outside. The right one is a single closed term that proves it for every PPP, and it can be applied later to any particular proposition; this is what the ∀\forall∀ rows of Figure 4.1 need.

Both forms require Sort 0\Sort{0}Sort0 to be a type. C-Ext, which adds P:Sort 0P : \Sort{0}P:Sort0 to a context, and T-Lam and T-Pi, which bind P:Sort 0P : \Sort{0}P:Sort0, all have the premise Γ⊢A:Sort u\Gamma \vdash A : \Sort{u}Γ⊢A:Sortu for the type AAA of the new variable. With A=Sort 0A = \Sort{0}A=Sort0, this premise reads Γ⊢Sort 0:Sort u\Gamma \vdash \Sort{0} : \Sort{u}Γ⊢Sort0:Sortu for some uuu: the universe of propositions must itself have a type. The question is which.

Type is not a type

Suppose we replace all universes by a single universe Type\mathsf{Type}Type that contains itself:

⊢Γ;okΓ⊢Type:TypeΓ⊢A:TypeΓ,x:A⊢B:TypeΓ⊢Π(x:A). B:Type\dfrac{\ctxok{\Gamma}}{\Gamma \vdash \mathsf{Type} : \mathsf{Type}} \qquad \dfrac{\Gamma \vdash A : \mathsf{Type} \qquad \Gamma, x : A \vdash B : \mathsf{Type}}{\Gamma \vdash \tPi{x}{A}{B} : \mathsf{Type}}Γ⊢Type:Type⊢Γ;ok​Γ⊢Π(x:A).B:TypeΓ⊢A:TypeΓ,x:A⊢B:Type​

Translate ∀P. φ\forall P.\,\varphi∀P.φ as Π(P:Type). φ∗\tPi{P}{\mathsf{Type}}{\varphi^\ast}Π(P:Type).φ∗. Then PPP ranges over a collection that contains Type\mathsf{Type}Type itself and every type built from it. Such a collection is the type-theoretic analogue of the set of all sets, and naive set theory shows that such collections lead to contradictions. The best-known example is Russell's paradox: for R={ x∣x∉x }R = \{\, x \mid x \notin x \,\}R={x∣x∈/x}, both R∈RR \in RR∈R and R∉RR \notin RR∈/R lead to a contradiction.

Type theory has no membership test like x∉xx \notin xx∈/x, so Russell's argument does not carry over word for word. Girard instead adapted a related paradox about the collection of all well-orderings, due to Burali-Forti [Girard 1972], and Hurkens simplified the resulting term [Hurkens 1995]. The result is a closed term tHt_{\mathrm{H}}tH​ with

⊢tH:Π(P:Type). P,\vdash t_{\mathrm{H}} : \tPi{P}{\mathsf{Type}}{P},⊢tH​:Π(P:Type).P,

so the system is inconsistent: ⊥\bot⊥ has no proof, yet ⊥∗\bot^\ast⊥∗ has a term, and a kernel built on these rules accepts a proof of every statement. The essential ingredient is a type UUU that quantifies over all of Type\mathsf{Type}Type while being a member of Type\mathsf{Type}Type, which lets UUU contain a copy of its own double power set, something no set can do. Appendix C gives tHt_{\mathrm{H}}tH​ in full, explains how it works, and shows how to reproduce the result by changing one line of the kernel.

The damage reaches the algorithm as well. Subject reduction still holds, so if tHt_{\mathrm{H}}tH​ had a normal form, it would be a normal closed term of type Π(p:Type). p\tPi{p}{\mathsf{Type}}{p}Π(p:Type).p. The part of the consistency proof in Appendix D that analyses normal terms does not use strong normalization and carries over to Type:Type\mathsf{Type} : \mathsf{Type}Type:Type; it shows that no such normal term exists. Hence tHt_{\mathrm{H}}tH​ has no normal form, strong normalization fails, and Normalize\NormalizeNormalize runs forever on it. A kernel with Type:Type\mathsf{Type} : \mathsf{Type}Type:Type is not only unsound but also, on some inputs, non-terminating.

Martin-Löf's first type theory of 1971 had this rule, and Girard's paradox was discovered against it the following year. Every dependent type theory since then has had either a hierarchy of universes or some other device to break the self-reference. The paradox is not a curiosity: the self-containing universe is the obvious design, and the obvious design is wrong.

A hierarchy with an impredicative bottom

The second answer is that Sort 0\Sort{0}Sort0 lives in a larger universe, which lives in a larger one still:

⊢Γ;okΓ⊢Sort u:Sort (u+1);(T-Sort)soSort 0:Sort 1:Sort 2:⋯ .\dfrac{\ctxok{\Gamma}}{\Gamma \vdash \Sort{u} : \Sort{(u+1)}}\rulename{T-Sort} \qquad\text{so}\qquad \Sort{0} : \Sort{1} : \Sort{2} : \cdots.Γ⊢Sortu:Sort(u+1)⊢Γ;ok​;(T-Sort)soSort0:Sort1:Sort2:⋯.

No universe contains itself. A Π\PiΠ-type takes an argument from one universe and returns a type in another, so T-Pi must also say which universe the Π\PiΠ-type itself belongs to. Lean's answer uses the function imax\imaximax:

Γ⊢A:Sort uΓ,x:A⊢B:Sort vΓ⊢Π(x:A). B:Sort imax(u,v);(T-Pi)imax(u,v)={0if v=0,max⁡(u,v)otherwise.\dfrac{\Gamma \vdash A : \Sort{u} \qquad \Gamma, x : A \vdash B : \Sort{v}}{\Gamma \vdash \tPi{x}{A}{B} : \Sort{\imax(u, v)}}\rulename{T-Pi} \qquad \imax(u, v) = \begin{cases} 0 & \text{if } v = 0, \\ \max(u, v) & \text{otherwise.} \end{cases}Γ⊢Π(x:A).B:Sortimax(u,v)Γ⊢A:SortuΓ,x:A⊢B:Sortv​;(T-Pi)imax(u,v)={0max(u,v)​if v=0,otherwise.​

The case split in imax\imaximax makes a Π\PiΠ-type impredicative when its body is a proposition, and predicative otherwise. Pick the universes of AAA and BBB below and watch where the Π\PiΠ-type lands.

Propositions are impredicative. If the body BBB is a proposition (v=0v = 0v=0), the whole Π\PiΠ is a proposition, whatever it quantifies over. In particular (∀P. φ)∗=Π(P:Sort 0). φ∗(\forall P.\,\varphi)^\ast = \tPi{P}{\Sort{0}}{\varphi^\ast}(∀P.φ)∗=Π(P:Sort0).φ∗ is in Sort 0\Sort{0}Sort0, although it quantifies over all of Sort 0\Sort{0}Sort0. A universe that contains types quantifying over itself is called impredicative. Because every translated formula lies in Sort 0\Sort{0}Sort0, the premise ψ∗:Sort 0\psi^\ast : \Sort{0}ψ∗:Sort0 of ∀\forall∀-elim always holds, so a universal statement can be instantiated with any proposition, even with itself. For example, with id=λ(P:Sort 0). λ(h:P). h\mathit{id} = \tLam{P}{\Sort{0}}{\tLam{h}{P}{h}}id=λ(P:Sort0).λ(h:P).h,

id:Π(P:Sort 0). P→PandΠ(P:Sort 0). P→P:Sort 0,\mathit{id} : \tPi{P}{\Sort{0}}{P \to P} \qquad\text{and}\qquad \tPi{P}{\Sort{0}}{P \to P} : \Sort{0},id:Π(P:Sort0).P→PandΠ(P:Sort0).P→P:Sort0,

so id  (Π(P:Sort 0). P→P)  id\mathit{id}\;(\tPi{P}{\Sort{0}}{P \to P})\;\mathit{id}id(Π(P:Sort0).P→P)id is well typed, with type Π(P:Sort 0). P→P\tPi{P}{\Sort{0}}{P \to P}Π(P:Sort0).P→P. The same case makes ∀n:Nat, n+0=n\forall n : \Nat,\, n + 0 = n∀n:Nat,n+0=n a proposition, even though Nat\NatNat lives in Sort 1\Sort{1}Sort1; Chapter 7 relied on this for induction.

# "Every proposition implies itself" is itself a proposition,
# so it can be instantiated with itself.
def id : forall (P : Sort 0), P -> P := fun (P : Sort 0) => fun (h : P) => h
def self : forall (P : Sort 0), P -> P := id (forall (P : Sort 0), P -> P) id

# The analogous statement one level up is NOT its own instance:
# forall (A : Sort 1), A -> A lives in Sort 2, not Sort 1.
def idT : forall (A : Sort 1), A -> A := fun (A : Sort 1) => fun (a : A) => a
def selfT : forall (A : Sort 1), A -> A := idT (forall (A : Sort 1), A -> A) idT

Types are predicative. If the body is not a proposition (v≥1v \ge 1v≥1), the Π\PiΠ lives in the larger of the two universes. A type that quantifies over Sort u\Sort{u}Sortu then lives in Sort (max⁡(u+1,v))\Sort{(\max(u+1, v))}Sort(max(u+1,v)), which is never Sort u\Sort{u}Sortu:

Γ⊢Sort u:Sort (u+1);(T-Sort)Γ,x:Sort u⊢B:Sort vΓ⊢Π(x:Sort u). B:Sort (max⁡(u+1,v));(T-Pi)\dfrac{ \dfrac{}{\Gamma \vdash \Sort{u} : \Sort{(u+1)}}\rulename{T-Sort} \qquad \Gamma, x : \Sort{u} \vdash B : \Sort{v} }{\Gamma \vdash \tPi{x}{\Sort{u}}{B} : \Sort{(\max(u+1, v))}}\rulename{T-Pi}Γ⊢Π(x:Sortu).B:Sort(max(u+1,v))Γ⊢Sortu:Sort(u+1)​;(T-Sort)Γ,x:Sortu⊢B:Sortv​;(T-Pi)

This property is called predicativity. For example, the identity on types λ(A:Sort 1). λ(a:A). a\tLam{A}{\Sort{1}}{\tLam{a}{A}{a}}λ(A:Sort1).λ(a:A).a has type Π(A:Sort 1). A→A\tPi{A}{\Sort{1}}{A \to A}Π(A:Sort1).A→A, which lives in Sort 2\Sort{2}Sort2, so it cannot be applied to its own type; a copy at Sort 2\Sort{2}Sort2 can. Each level holds the level beneath it, and in practice a few levels suffice; higher levels appear when one quantifies over large collections, such as the category of all small categories.

Why this is safe. Impredicativity looks like the self-reference that the previous section warned against, but it is confined: Sort 0\Sort{0}Sort0 contains types that quantify over Sort 0\Sort{0}Sort0, yet Sort 0\Sort{0}Sort0 is not a member of itself. Coquand showed that one impredicative universe at the bottom is consistent [Coquand 1988], whereas Girard's paradox can already be derived once two levels are impredicative [Hurkens 1995]. With these rules the system is consistent and strongly normalizing (Chapter 14).

Why may propositions be impredicative when types may not? A proof of a proposition carries no data that a program can extract, as the elimination restriction of Chapter 8 enforces. Quantifying over all propositions to define one is like defining a set by a property that mentions all sets: trouble arises if the result falls within the quantifier's range and can be inspected, whereas using it only as a hypothesis does not create that problem. The paradox requires inspecting the object it builds, and proofs of propositions do not permit that.

Comparison with Lean

In Lean [de Moura and Ullrich 2021], Sort 0\Sort{0}Sort0 is Prop, Sort (u+1)\Sort{(u+1)}Sort(u+1) is Type u, and Π\PiΠ-types are assigned universes with imax\imaximax as above. Two differences remain.

First, Prop in Lean has definitional proof irrelevance: any two proofs of the same proposition are definitionally equal. Our conversion does not identify proofs; adding this would make conversion depend on types, so the simple "normalize and compare" check of Chapter 12 would no longer suffice.

Second, Lean has universe polymorphism, so definitions can be stated once for all levels uuu, and imax\imaximax then matters for level variables as well, with constraints such as imax(u,v)≤w\imax(u, v) \le wimax(u,v)≤w solved symbolically. In our system every level is a concrete number.

Two sorts ∗:□\ast : \square∗:□ ∗\ast∗ only □\square□ itself has no type

The whole of this chapter is two lines of infer in src/typecheck.rs: the Sort(u) case returns Sort(u + 1), and the Pi case returns Sort(0) when the body's level is 0 and the maximum otherwise. Appendix C shows that changing the first line to return Sort(u) makes the kernel accept Hurkens' term.

What to remember

  • Sort 0\Sort{0}Sort0 needs a type, because proposition variables are bound by λ\lambdaλ and Π\PiΠ.
  • A universe containing itself is inconsistent (Girard, Hurkens) and breaks normalization.
  • The hierarchy Sort u:Sort (u+1)\Sort{u} : \Sort{(u+1)}Sortu:Sort(u+1) avoids self-containment; imax\imaximax makes propositions impredicative and everything else predicative.
  • One impredicative universe at the bottom is safe; two are not. Lean adds proof irrelevance and universe polymorphism on top of the same design.
