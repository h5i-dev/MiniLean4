Chapter 11

Substitution, Capture, and Alpha-Equivalence

The previous chapters treated three operations on terms as black boxes: substitution, used by T-App, by Freshen, and by every computation step; weak head normalization, used to expose a Π\PiΠ or a universe; and definitional equality, used by Check. These operations are part of the trusted kernel, and most kernel bugs hide in them, because they must handle the names of bound variables correctly. This chapter opens the first box, substitution, shows the same naming problem in contexts, and then defines when two terms are equal up to the names of their bound variables.

Free variables and substitution

Π\PiΠ and λ\lambdaλ bind their variable: in λ(x:A). t\tLam{x}{A}{t}λ(x:A).t, occurrences of xxx inside ttt refer to the argument. The binder's scope is the body only; xxx is not bound in the annotation AAA. A variable occurrence that is not bound by an enclosing Π\PiΠ or λ\lambdaλ is free.

We write t[x↦s]\subst{t}{x}{s}t[x↦s] for the result of replacing the free occurrences of xxx in ttt with sss. The only subtle case is a binder. Consider (λ(y:A). x)[x↦y]\subst{(\tLam{y}{A}{x})}{x}{y}(λ(y:A).x)[x↦y]. The body says "ignore the argument and return the outer xxx". Definitions 11.1 and 11.2 are fv and subst in src/substitution.rs. The binder case of subst is below. It has one extra shortcut compared with the definition: if xxx does not occur free in the body at all, the body is returned unchanged, which saves a traversal and never changes the result.

Term::Pi(y, domain, body) | Term::Lam(y, domain, body) => {
    let substituted_domain = subst(domain, x, replacement);
    let (renamed_binder, substituted_body) = if y == x || !fv(body).contains(x) {
        (y.clone(), (**body).clone())                       // shadowed, or nothing to do
    } else if !fv(replacement).contains(y) {
        (y.clone(), subst(body, x, replacement))            // no capture possible
    } else {
        let mut avoid = all_names(body);                    // capture: rename y to a fresh z
        avoid.extend(all_names(domain));
        avoid.extend(all_names(replacement));
        avoid.insert(x.to_string());
        let z = fresh(y, &avoid);
        let body_with_z = subst(body, y, &var(&z));
        (z, subst(&body_with_z, x, replacement))
    };
    // ... rebuild the Pi or Lam with renamed_binder, substituted_domain, substituted_body
}

The fresh function appends primes to the hint until the name is unused. The avoid set is all_names, every name in the terms involved rather than just the free ones, which is more than the definition requires but makes the output easier to read.

Variable capture in contexts

It is tempting to drop the side condition x∉dom(Γ)x \notin \dom(\Gamma)x∈/dom(Γ) of C-Ext and let a new assumption simply shadow an old one, as most programming languages do. Doing so makes the kernel unsound. Consider

t=λ(x:Sort 0). λ(y:x). λ(x:Sort 0). y.t = \tLam{x}{\Sort{0}}{\tLam{y}{x}{\tLam{x}{\Sort{0}}{y}}}.t=λ(x:Sort0).λ(y:x).λ(x:Sort0).y.

The variable yyy has the outer xxx as its type, and the innermost λ\lambdaλ ignores its argument. So the correct type of ttt is

Π(x:Sort 0). Π(y:x). Π(x′:Sort 0). x.\tPi{x}{\Sort{0}}{\tPi{y}{x}{\tPi{x'}{\Sort{0}}{x}}}.Π(x:Sort0).Π(y:x).Π(x′:Sort0).x.

A checker without Freshen\FreshenFreshen looks up yyy in the context x:Sort 0,  y:x,  x:Sort 0x : \Sort{0},\; y : x,\; x : \Sort{0}x:Sort0,y:x,x:Sort0 and returns its type, the bare name xxx. At that point xxx refers to the inner binder, and the checker returns

Π(x:Sort 0). Π(y:x). Π(x:Sort 0). x,\tPi{x}{\Sort{0}}{\tPi{y}{x}{\tPi{x}{\Sort{0}}{x}}},Π(x:Sort0).Π(y:x).Π(x:Sort0).x,

which says "from any element of any type, produce an element of every type". Given A:Sort 0A : \Sort{0}A:Sort0 and a:Aa : Aa:A, the term t  A  at\;A\;atAa then has type Π(B:Sort 0). B\tPi{B}{\Sort{0}}{B}Π(B:Sort0).B, a proof of False. Such AAA and aaa exist even in the empty context: A=Π(P:Sort 0). P→PA = \tPi{P}{\Sort{0}}{P \to P}A=Π(P:Sort0).P→P is itself a proposition, and the identity function a=λ(P:Sort 0). λ(h:P). ha = \tLam{P}{\Sort{0}}{\tLam{h}{P}{h}}a=λ(P:Sort0).λ(h:P).h proves it.

With Freshen\FreshenFreshen, the innermost binder is renamed to x′x'x′ before it enters the context, so the context becomes x:Sort 0,  y:x,  x′:Sort 0x : \Sort{0},\; y : x,\; x' : \Sort{0}x:Sort0,y:x,x′:Sort0, the lookup of yyy returns xxx, which still refers to the outer binder, and Infer\InferInfer returns the correct type above. The derivation explorer shows the renaming happen: the note on the innermost T-Lam node reports it, and the context of the leaf contains x′x'x′.

The problem is the same as in substitution: a name is moved into a scope where it means something else. It affects any representation that identifies variables by name, whether the context is a list or a hash map. There are three common remedies.

  1. Reject shadowing outright. This is the simplest option, but the reserved name _ used by A→BA \to BA→B must be exempt and never added to the context.
  2. Rename on entry, as Freshen\FreshenFreshen does. This is our choice.
  3. Represent bound variables by position (de Bruijn indices [de Bruijn 1972]) or use the locally nameless style, in which bound variables are indices and free variables carry unique identifiers. Lean 4 takes the latter approach.

A test suite should include ttt above and check that the kernel either rejects it or assigns it the correct type.

This bug is easy to write and hard to notice, because every ordinary proof still checks. Only a term that deliberately reuses a name in a nested binder exposes it. A kernel's test suite needs adversarial terms, not just correct proofs.

Alpha-equivalence

The names of bound variables carry no meaning. λ(x:A). x\tLam{x}{A}{x}λ(x:A).x and λ(y:A). y\tLam{y}{A}{y}λ(y:A).y are the same function, and Π(P:Sort 0). P→P\tPi{P}{\Sort{0}}{P \to P}Π(P:Sort0).P→P and Π(Q:Sort 0). Q→Q\tPi{Q}{\Sort{0}}{Q \to Q}Π(Q:Sort0).Q→Q are the same proposition. Terms that differ only in the names of bound variables are called alpha-equivalent. A kernel cannot compare types with plain syntactic equality, which would reject the second pair.

Definition 11.3 (Alpha-equivalence). =α\alphaeq=α​ is the smallest congruence on terms containing, for □∈{Π,λ}\square \in \{\Pi, \lambda\}□∈{Π,λ},

□(x:A). B  =α  □(y:A). B[x↦y]whenever y∉FV(B).\square(x{:}A).\,B \;\alphaeq\; \square(y{:}A).\,\subst{B}{x}{y} \qquad \text{whenever } y \notin \FV(B).□(x:A).B=α​□(y:A).B[x↦y]whenever y∈/FV(B).

(A congruence is an equivalence relation that is preserved by every term constructor: if the parts are related, so are the wholes.) This definition is easy to state but not directly executable, since it does not say which names to choose. An implementation instead walks both terms in lockstep and remembers, for each side, the list of binders passed so far. A bound variable is then identified by which binder it refers to, not by its name.

To describe this walk, we use a judgment of the form E1;E2⊢s=αtE_1; E_2 \vdash s \alphaeq tE1​;E2​⊢s=α​t, where E1E_1E1​ and E2E_2E2​ are lists of names. The list E1E_1E1​ records the binders that enclose sss, from the outermost to the innermost, and E2E_2E2​ records those that enclose ttt. The judgment reads: "sss, placed inside the binders E1E_1E1​, and ttt, placed inside the binders E2E_2E2​, are the same term up to the names of bound variables". Two lists are needed because the two terms may use different names for corresponding binders. For example, comparing λ(x:A). λ(y:B). x\tLam{x}{A}{\tLam{y}{B}{x}}λ(x:A).λ(y:B).x with λ(a:A). λ(b:B). a\tLam{a}{A}{\tLam{b}{B}{a}}λ(a:A).λ(b:B).a passes two binders on each side and arrives at

x,y;  a,b⊢x=αa,x, y;\; a, b \vdash x \alphaeq a,x,y;a,b⊢x=α​a,

which holds because xxx and aaa both refer to the outer of the two binders. Comparing two whole terms starts from empty lists, ⋅ ;⋅⊢s=αt\cdot\,;\cdot \vdash s \alphaeq t⋅;⋅⊢s=α​t.

To say "the same binder" precisely, let idx(E,x)\mathrm{idx}(E, x)idx(E,x) be the position of the last occurrence of xxx in EEE, counted from the right starting at 000, or undefined if x∉Ex \notin Ex∈/E. In the example, idx((x,y),x)=idx((a,b),a)=1\mathrm{idx}((x, y), x) = \mathrm{idx}((a, b), a) = 1idx((x,y),x)=idx((a,b),a)=1. Taking the last occurrence handles shadowing: in λ(x:A). λ(x:B). x\tLam{x}{A}{\tLam{x}{B}{x}}λ(x:A).λ(x:B).x the body refers to the inner xxx.

Free variables are compared by name (α\alphaα-Free), bound variables by position (α\alphaα-Bound), and constants by name (α\alphaα-Const). A variable that is bound on one side and free on the other is never equal to anything, which is why there is no rule for that case. Because both sides descend through binders together, E1E_1E1​ and E2E_2E2​ always have the same length. So comparing positions counted from the right is the same as comparing positions counted from the left, and an implementation may store each list as a map from names to binding depths, provided it restores the previous entry when it leaves a binder. Using positions instead of names everywhere gives the de Bruijn representation, in which alpha-equivalent terms are syntactically identical.

Positions also tell apart terms that a careless comparison of names would confuse. λ(x:A). λ(y:A). x\tLam{x}{A}{\tLam{y}{A}{x}}λ(x:A).λ(y:A).x and λ(a:A). λ(b:A). b\tLam{a}{A}{\tLam{b}{A}{b}}λ(a:A).λ(b:A).b are not alpha-equivalent: the bodies reach x,y; a,b⊢x=αbx, y;\, a, b \vdash x \alphaeq bx,y;a,b⊢x=α​b, and idx\mathrm{idx}idx gives 111 for xxx but 000 for bbb. Conversely, λ(x:A). λ(x:A). x\tLam{x}{A}{\tLam{x}{A}{x}}λ(x:A).λ(x:A).x and λ(a:A). λ(b:A). b\tLam{a}{A}{\tLam{b}{A}{b}}λ(a:A).λ(b:A).b are alpha-equivalent, because the last occurrence of xxx in (x,x)(x, x)(x,x) has index 000, the same as bbb in (a,b)(a, b)(a,b).

The rules of Figure 11.1 are a different definition from Definition 11.3, so we must check that they agree.

Theorem 11.4 (Correctness of algorithmic alpha-equivalence). For all terms sss and ttt, s=αts \alphaeq ts=α​t in the sense of Definition 11.3 if and only if ⋅ ;⋅⊢s=αt\cdot\,;\cdot \vdash s \alphaeq t⋅;⋅⊢s=α​t is derivable by the rules of Figure 11.1.

The idea of the proof is that both sides say the same thing: sss and ttt have the same de Bruijn representation. For the algorithm this is almost immediate, since its rules compare positions exactly as de Bruijn indices do. For Definition 11.3, the key fact is that renaming a bound variable does not change the de Bruijn representation. Appendix B gives the full proof.

Figure 11.1 is the function alpha in src/substitution.rs. The two binder lists are Vec<String>s pushed and popped around the recursive call on bodies, and binder_distance is idx\mathrm{idx}idx: it searches the list from the end, so the distance to the nearest enclosing binder of that name is found first.

(Term::Var(x), Term::Var(y)) => {
    match (binder_distance(bound_a, x), binder_distance(bound_b, y)) {
        (Some(i), Some(j)) => i == j,     // alpha-Bound
        (None, None) => x == y,           // alpha-Free
        _ => false,                       // bound on one side only
    }
}

Exercises

Compute (λ(y:A). λ(x:B). x  y)[x↦y]\subst{(\tLam{y}{A}{\tLam{x}{B}{x\;y}})}{x}{y}(λ(y:A).λ(x:B).xy)[x↦y] step by step.

Solution

The outer binder is yyy, which is free in the replacement yyy, so the capture case applies: rename yyy to a fresh zzz, giving body λ(x:B). x  z\tLam{x}{B}{x\;z}λ(x:B).xz, then substitute. The inner binder is xxx, the variable being replaced, so the inner body is untouched. Result: λ(z:A). λ(x:B). x  z\tLam{z}{A}{\tLam{x}{B}{x\;z}}λ(z:A).λ(x:B).xz. Note that the inner xxx was never a free occurrence, so nothing was replaced at all; the only effect was the renaming forced by capture avoidance.

Decide whether λ(x:A). λ(y:A). y  x\tLam{x}{A}{\tLam{y}{A}{y\;x}}λ(x:A).λ(y:A).yx and λ(y:A). λ(x:A). x  y\tLam{y}{A}{\tLam{x}{A}{x\;y}}λ(y:A).λ(x:A).xy are alpha-equivalent by running Figure 11.1.

Solution

Yes. After two α\alphaα-Lam steps the lists are x,yx, yx,y and y,xy, xy,x, and the bodies are y  xy\;xyx and x  yx\;yxy. α\alphaα-App compares yyy with xxx: indices 000 and 000. Then xxx with yyy: indices 111 and 111. Both hold. Names are swapped, positions agree.

What to remember

  • Substitution replaces free occurrences only, and must rename a binder when the replacement mentions the binder's name (capture).
  • The same capture problem arises in contexts. A kernel that lets a binder shadow a context entry can prove False; Freshen prevents it.
  • Alpha-equivalence compares bound variables by the position of their binder and free variables by name. Figure 11.1 is the algorithm; Theorem 11.4 says it matches the definition.
  • All three live in src/substitution.rs: subst, fv, and alpha.
