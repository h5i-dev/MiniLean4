第 1 章

命題は型である

自然言語で書かれた証明を計算機が検査するには、証明を型付きの項として表す必要がある。Curry-Howard 対応では、その型が証明される命題であり、証明の検査は型検査になる。

証明はプログラムである

命題「AAA ならば BBB」の証明を、ふつうの数学の文章で書くとこうなる。

AAA を仮定する。すると……（何らかの議論）……ゆえに BBB が成り立つ。

この証明の形は関数であり、何か、つまり AAA を信じる根拠を受け取って、別の何か、つまり BBB を信じる根拠を作り出す。これを文字どおりに受け取って「AAA を信じる根拠」を型 AAA の値とみなせば、A→BA \to BA→B の証明は AAA から BBB への関数であり、命題 A→BA \to BA→B はその関数の型である。

この観察が Curry-Howard 対応（Curry-Howard correspondence）である。それによれば、

  • 命題は型であり、
  • その命題の証明はその型の項であり、
  • 命題 AAA が真であるのは、型 AAA の項 ttt が存在するとき、そのときに限る。これを t:At : At:A と書く。

これだけでどこまで行けるかを、三つの例で示す。左が命題、中央が関数として書いたその証明、右が証明の考えを言葉にしたものである。ここで λx. e\lambda x.\,eλx.e は、xxx を受け取って eee を返す関数を表す。

命題 証明 言葉で言えば
P→PP \to PP→P λp. p\lambda p.\,pλp.p 仮定をそのまま返す。
A→B→AA \to B \to AA→B→A λa. λb. a\lambda a.\,\lambda b.\,aλa.λb.a 二つ目の仮定を無視する。
(A→B)→(B→C)→A→C(A \to B) \to (B \to C) \to A \to C(A→B)→(B→C)→A→C λf. λg. λa. g (f a)\lambda f.\,\lambda g.\,\lambda a.\,g\,(f\,a)λf.λg.λa.g(fa) 二つの含意を合成する。

三行目をもう一度見てほしい。含意が推移的であることを証明するには、A→BA \to BA→B と B→CB \to CB→C を仮定し、AAA が与えられたら、一つ目の仮定を適用して BBB を得て、二つ目を適用して CCC を得る。証明項はまさにそれを言っており、fff と ggg が仮定、aaa が AAA の証明で、g (f a)g\,(f\,a)g(fa) がそれらを順に適用する。仮定を使うことは関数を適用することである。これこそが、仮定を言い直すだけの作業と本当の推論を分ける一歩であり、第 3 章で再び取り上げる。

型を仕様、項をそれを満たすものと考えてみよう。「型 AAA の項がある」とは「仕様 AAA は満たせる」ということであり、AAA が命題なら、満たすことは証明することにあたる。項を一つも持たない型は証明できない命題であり、これがまさに後で False\mathsf{False}False が担う役割である。

量化子は依存関数になる

同じ考えは「すべての」にも広がる。すべての x:Ax : Ax:A について B(x)B(x)B(x) が成り立つことを証明するには、どんな xxx を渡されても B(x)B(x)B(x) の証明を作り出す方法を与えればよい。これもやはり関数だが、返り値の型が引数に依存するというひとつのひねりがある。x=3x = 3x=3 なら B(3)B(3)B(3) の証明を返し、x=7x = 7x=7 なら B(7)B(7)B(7) の証明を返す。結果の型が引数に言及してよい関数型を依存関数型（dependent function type）または Π\PiΠ 型と呼び、次のように書く。

Π(x:A). B(x).\Pi(x : A).\,B(x).Π(x:A).B(x).

ふつうの関数型 A→BA \to BA→B は、BBB が xxx に言及しない特別な場合である。

たとえば「すべての命題は自分自身を含意する」は命題の上の量化である。Sort 0\Sort{0}Sort0 を命題の型とすれば、この主張は

Π(P:Sort 0). P→P,\tPi{P}{\Sort{0}}{P \to P},Π(P:Sort0).P→P,

であり、その証明は、命題 PPP を受け取り、次に PPP の証明 ppp を受け取って、ppp を返す関数である。

λ(P:Sort 0). λ(p:P). p.\tLam{P}{\Sort{0}}{\tLam{p}{P}{p}}.λ(P:Sort0).λ(p:P).p.

束縛子に型が付いていることに注意してほしい。λ(P:Sort 0)\lambda(P : \Sort{0})λ(P:Sort0) は PPP が命題の範囲を動くことを言い、λ(p:P)\lambda(p : P)λ(p:P) は ppp が渡されたその PPP の証明であることを言う。型検査器にはこの注釈が必要になる。

カーネルの仕事

ここから定理証明器の中心となる考えが得られる。

定理を証明するとは要求された型の項を構成することであり、証明を検証するとはその項を型検査することである。

カーネルは真偽について推論するのではなく、項がいつ型を持つかを定める型付け規則を実装し、与えられた項が与えられた型をその規則のもとで持つことを機械的に検査するだけである。それが証明の検査と呼べるかどうかは、型付け規則がある論理を忠実に実装しているかどうかにかかっており、それは第 4 章の主題である。規則が健全（sound）であるか、すなわち偽の命題の型に住む項が存在しないかは、第 13 章と第 14 章の主題である。

この分業が、本格的な証明器の設計を方向づける。タクティクや自動化、決定手続き、さらには大規模言語モデルが証明を探す役を担い、そこにバグがあっても、出力された項はカーネルが検査する。正しさが求められるのはカーネルだけなので、できるだけ小さく保つことが設計目標になり、本書のカーネルはコメントを含めても千五百行に満たない Rust である。

Lean 4 も同じ仕組みで動く。theorem コマンドが主張を型へとエラボレートし、タクティクがその型の項を組み立て、カーネルがその項を検査してから定理が環境に追加される。Lean のカーネルは、宇宙多相、相互・入れ子帰納型、定義的な証明無関係性、それにキャッシュや遅延展開といった性能のための機能を備えている分だけ本書のものより大きいが、仕事は同じで、Γ⊢t:A\Gamma \vdash t : AΓ⊢t:A を判定することである。

本書の計画

第 I 部の各章では、論理として使えるぎりぎりの大きさの型理論に対するカーネルを作る。

  1. 第 2 章で言語を固定する。宇宙、変数、Π\PiΠ 型、λ\lambdaλ 抽象、適用である。
  2. 第 3 章で型付け規則を与える。項の種類ごとに一つと、型の内部で計算を許すための一つである。
  3. 第 4 章でこれらの規則がある論理の規則であることを示し、整合性を定義する。
  4. 第 5 章で規則をアルゴリズムに変え、Rust の実装と突き合わせる。
  5. 第 6 章で、正しい証明、誤った証明、計算を必要とする証明に対して、アルゴリズムを手で動かす。

二つの操作、代入と定義的等価は、第 III 部まで意図的にブラックボックスとして扱う。どちらも述べるのは簡単で、間違えるのも簡単であり、カーネルの正しさはこの二つにかかっている。

覚えておくこと

  • 命題は型、証明は項であり、t:At : At:A は ttt が AAA を証明することを意味する。
  • 含意は関数型であり、仮定を使うことは関数を適用することである。
  • 全称量化は依存関数型 Π(x:A). B(x)\Pi(x : A).\,B(x)Π(x:A).B(x) である。
  • 定理証明器のカーネルは型検査器であり、それ以外のすべては、カーネルが検査する項を作るだけである。
