第 8 章

归纳类型 II：通用方法

第 7 章手工构造了自然数的递归子。在 Lean 中，用户从不这样做：他们写下一个 inductive 声明，由内核检查它，并生成类型构造器、构造子、递归子及其计算规则。本章分三步建立这一过程，从更多的构造子，到参数，再到索引，最后给出一般性的表述。内核中对应的代码约有五百行。

更多构造子：树

Nat\NatNat 有两个构造子，其中只有一个带递归参数。考虑一个有三个构造子的类型：

  | leaf   : Tree
  | node   : Tree -> Tree
  | branch : Tree -> Tree -> Tree

参数：列表

一个数的列表要么为空，要么是一个数接在一个数的列表前面，因此我们可以声明类型 ListNat\mathsf{ListNat}ListNat，其构造子为 nil\mathsf{nil}nil 和 cons:Nat→ListNat→ListNat\mathsf{cons} : \Nat \to \mathsf{ListNat} \to \mathsf{ListNat}cons:Nat→ListNat→ListNat。但这样一来，树的列表又需要另一个声明 ListTree\mathsf{ListTree}ListTree，带同样的构造子和一个单独的递归子，每种元素类型都要如此。更好的做法是让元素类型成为该类型本身的参数：

inductive List (A : Sort 1) where
  | nil  : List A
  | cons : A -> List A -> List A

现在 List  Nat\mathsf{List}\;\NatListNat 和 List  Tree\mathsf{List}\;\mathsf{Tree}ListTree 是同一个声明的两个实例。该声明添加

索引：向量

List  Nat\mathsf{List}\;\NatListNat 可以有任意长度，但如果我们想把长度放进类型里，使 Vec  Nat  0\mathsf{Vec}\;\Nat\;0VecNat0 和 Vec  Nat  2\mathsf{Vec}\;\Nat\;2VecNat2 成为不同的类型，该怎么办？

inductive Vec (A : Sort 1) : Nat -> Sort 1 where
  | vnil  : Vec A 0
  | vcons : (n : Nat) -> A -> Vec A n -> Vec A (succ n)

元素类型 AAA 仍然是参数，而长度则不是：vnil\mathsf{vnil}vnil 的长度为 000，而 vcons\mathsf{vcons}vcons 接受一个长度为 nnn 的向量，返回一个长度为 succ  n\suc\;nsuccn 的向量。在不同构造子之间、以及构造子与其递归参数之间可以不同的类型参数称为索引（index）。构造子为

由于索引会变化，递归子不能预先固定它，而是由 motive 把它作为参数接受，M:Π(n:Nat). Vec  A  n→Sort vM : \tPi{n}{\Nat}{\mathsf{Vec}\;A\;n \to \Sort{v}}M:Π(n:Nat).VecAn→Sortv，而 vcons\mathsf{vcons}vcons 的情形是

Π(n:Nat). Π(a:A). Π(xs:Vec  A  n). M  n  xs→M  (succ  n)  (vcons  A  n  a  xs).\tPi{n}{\Nat}{\tPi{a}{A}{\tPi{\mathit{xs}}{\mathsf{Vec}\;A\;n}{M\;n\;\mathit{xs} \to M\;(\suc\;n)\;(\mathsf{vcons}\;A\;n\;a\;\mathit{xs})}}}.Π(n:Nat).Π(a:A).Π(xs:VecAn).Mnxs→M(succn)(vconsAnaxs).

归纳假设谈的是长度为 nnn 的向量，这从递归参数的类型 Vec  A  n\mathsf{Vec}\;A\;nVecAn 读出；结论谈的是长度为 succ  n\suc\;nsuccn 的向量，这从构造子的结果类型读出。脚本 examples/generic-vec.leanmini（附录 E）声明了这个类型，并检查了一个使用它的小项。

通用方法

本节给出处理带参数和索引的单个归纳类型的过程；Lean 还支持互归纳类型和嵌套归纳类型，但它们不在本书范围之内。

这一过程还回答了 T-Const 留下的一个问题。没有体的常量是一条假设：T-Const 接受 c:Π(P:Sort 0). Pc : \tPi{P}{\Sort{0}}{P}c:Π(P:Sort0).P 就像接受 zero:Nat\zero : \Natzero:Nat 一样轻易，而有了它，系统就不一致了。下面生成的常量不是任意的假设，而是一个固定模式的实例，即归纳构造演算（Calculus of Inductive Constructions）的归纳类型，其一致性是已知的 [Werner 1994]。

接受条件。 只有当以下四个条件都成立时，内核才接受一个声明。

  1. III 的类型在当前签名中是一个类型。
  2. 把 III 加入签名后，每个构造子类型都是一个类型，并且以 I  p⃗  t⃗jI\;\vec{p}\;\vec{t}_jIp​tj​ 结尾，其中 p⃗\vec{p}p​ 恰好是按顺序排列的参数，且 III 不出现在 t⃗j\vec{t}_jtj​ 中。
  3. 严格正性。 每个字段类型要么不提及 III，要么具有形式 Π(y⃗:B⃗). I  p⃗  s⃗\tPi{\vec{y}}{\vec{B}}{I\;\vec{p}\;\vec{s}}Π(y​:B).Ip​s，其中 III 既不出现在 B⃗\vec{B}B 中也不出现在 s⃗\vec{s}s 中。第二种形式的字段称为递归的。
  4. 宇宙。 若 u≥1u \ge 1u≥1，每个字段类型都位于某个 Sort w\Sort{w}Sortw 中，且 w≤uw \le uw≤u。若 u=0u = 0u=0，则没有条件。

  | mk : (Bad -> False) -> Bad

条件 4 防止一个类型包含更大的宇宙：没有它，带构造子 mk:Sort 1→T\mathsf{mk} : \Sort{1} \to Tmk:Sort1→T 的声明 T:Sort 1T : \Sort{1}T:Sort1 就会把整个 Sort 1\Sort{1}Sort1 的一份副本放进 Sort 1\Sort{1}Sort1 里，这正是第 13 章证明为不一致的自我包含。对 u=0u = 0u=0 不需要条件，因为 Sort 0\Sort{0}Sort0 是非谓词的。

从命题消去。 若 u≥1u \ge 1u≥1，则对每个层级 vvv 都生成递归子；若 u=0u = 0u=0，即 III 是命题，则只对 v=0v = 0v=0 生成递归子，除非 III 是子单元（subsingleton）：它至多有一个构造子，并且每个字段要么是证明（其类型位于 Sort 0\Sort{0}Sort0 中），要么出现在索引项 t⃗j\vec{t}_jtj​ 之中。这一限制使数据不会依赖于给出的是命题的哪一个证明。例如，P∨QP \vee QP∨Q 有两个构造子，于是从 P∨QP \vee QP∨Q 的证明到 Nat\NatNat 的函数可以对其中一个返回 000、对另一个返回 111，证明便携带了计算信息。因此 Lean 的 Or.rec 和 Exists.rec 只消去到 Prop，而 And.rec 和 Eq.rec 可以消去到每个宇宙：And 只有一个构造子，其字段都是证明；Eq（第 9 章）只有一个没有字段的构造子。

于是，签名不断增长而内核的规则保持不变：一个通用过程把每个声明变成签名条目，一个归约函数运行它们的规则（第 12 章）。

代码中

该过程位于 src/inductive/ 中。输入是一个 InductiveSpec（src/declaration.rs）：名字、参数和索引的 telescope、宇宙层级 uuu，以及每个构造子对应的一个 ConstructorSpec，给出其字段和索引项 t⃗j\vec{t}_jtj​。脚本解析器从一个 inductive 块构造它。

  • src/inductive/mod.rs 中的 Kernel::add_inductive 依次运行四个接受条件（check_inductive_type 是条件 1，check_constructor_fields 检查字段都是类型并执行条件 4，check_constructor_result 是条件 2），全部通过后注册类型构造器和构造子，并记录一个 InductiveInfo。失败时签名保持不变。
  • src/inductive/positivity.rs 是条件 3。check_recursive_field 剥去字段类型开头的各个 Π\PiΠ，拒绝任何定义域提及 III 的情况，并要求目标是 III 恰好应用于参数变量，后跟不提及 III 的索引项。它返回一个 RecursiveFieldInfo，记录 y⃗:B⃗\vec{y} : \vec{B}y​:B 和 s⃗\vec{s}s，这正是递归子生成器所需的全部信息。
  • src/inductive/recursor.rs 按上面的公式构造递归子类型。recursor_type 组装 telescope p⃗\vec{p}p​、motive、各小前提、索引和大前提；minor_premise_type 构造每个 CjC_jCj​；induction_hypothesis_type 构造每个 Hj,kH_{j,k}Hj,k​。生成的绑定子名字（__motive、__minor_j、__ih_j_k、__major）以两个下划线开头，用户声明不得使用这种名字，因此它们永远不会与字段冲突。
  • mod.rs 中的 allows_large_elimination 实现子单元测试。add_inductive 总是注册 I.rec0，在允许大消去时还注册 I.rec1；register_recursor 按需生成更高的层级。

ι 规则不会生成为项，而是由 whnf 直接依据存储的 InductiveInfo 应用，第 12 章会解释这一点。

生成器的核心短到可以通读，请把它与 CjC_jCj​ 的公式对照。

/// C_j = Pi (as : As_j). Pi (hs : Hs_j). M ts_j (c_j ps as)
fn minor_premise_type(info: &InductiveInfo, j: usize, constructor: &ConstructorInfo) -> Term {
    // c_j ps as
    let constructor_application = apps(
        const_term(&constructor.name),
        info.params.iter().chain(constructor.fields.iter()).map(|(name, _)| var(name)),
    );
    // (as : As_j)，随后是 (hs : Hs_j)
    let mut minor_premise_binders = constructor.fields.clone();
    for (k, recursive_field) in constructor.recursive_fields.iter().enumerate() {
        minor_premise_binders.push((
            format!("{INDUCTION_HYPOTHESIS_PREFIX}{j}_{k}"),
            induction_hypothesis_type(constructor, recursive_field),
        ));
    }
    telescope(&minor_premise_binders, apply_motive(&constructor.result_indices, constructor_application))
}

内核从不对 Nat\NatNat 做特殊处理。src/kernel.rs 中的 Kernel::standard 通过调用 add_inductive 来声明 Nat\NatNat 和 Eq\mathsf{Eq}Eq，传入的 InductiveSpec 与用户脚本会产生的完全相同，所以图 7.1 是生成出来的，而不是硬编码的；src/inductive/tests.rs 中的测试检查生成的类型与手写的类型一致。

正性检查是可靠性的要求，而不是为了方便。多年来 Lean、Coq 和 Agda 在内核的这一部分都出过错误，因为一般情形（嵌套和互归纳类型、宇宙约束、提及其他归纳类型的索引）十分复杂。我们受限的模式把检查控制在八十行以内。扩展它时，对每个新特性都要问同一个问题：该类型的值能否由一个消耗该类型的函数构造出来？

以下各项分别被四个接受条件中的哪一个拒绝（如果有的话）？(a) inductive T : Sort 1 where | mk (f : Sort 1)。(b) inductive T : Sort 1 where | mk (f : T -> T)。(c) inductive T : Sort 0 where | mk (f : Sort 1)。

解答

(a) 条件 4：字段 Sort 1\Sort{1}Sort1 的类型是 Sort 2\Sort{2}Sort2，超过了 u=1u = 1u=1。(b) 条件 3：TTT 出现在某个字段类型中箭头的左侧。(c) 接受：对 u=0u = 0u=0，条件 4 不施加任何要求，这个类型是一个把类型打包起来的命题；这是 Sort 0\Sort{0}Sort0 的非谓词性在起作用，而且它是无害的，因为 TTT 只能消去到 Sort 0\Sort{0}Sort0（它不是子单元，因为它的字段既不是证明也不是索引）。

要点回顾

  • 一个声明给出带参数和索引的类型构造器，以及带字段的构造子。参数自始至终固定；索引可变，并成为 motive 的参数。
  • 递归子对每个构造子有一个小前提，其中每个递归字段对应一个归纳假设；每个构造子对应一条 ι 规则。
  • 接受一个声明需要良构性、统一的参数、严格正性和宇宙上界。正性是保证递归终止、逻辑一致的关键。
  • 命题只能消去到 Sort 0\Sort{0}Sort0，除非它是子单元。
  • 内核从数据生成这一切；它不含任何针对 Nat\NatNat 的专门代码。
