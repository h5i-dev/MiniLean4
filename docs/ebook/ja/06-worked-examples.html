第 6 章

実例で追う

本章では、いくつかの小さな項に対してアルゴリズム 5.1 を手で実行し、各実行を型付け規則に対応づける。例は、アルゴリズムの仕事を一つずつ見せるように選んである。導出を組み立てること、誤った証明を捕まえること、仮定を使うこと、全称命題を具体化すること、型の内部で計算することである。以下のトレースはどれも、プレイグラウンドでカーネル上に再現できる。

定理 TTT の証明 ttt を検証するために、カーネルは Check(⋅,t,T)\Check(\cdot, t, T)Check(⋅,t,T) を呼ぶ。これは Infer(⋅,t)\Infer(\cdot, t)Infer(⋅,t) を呼び、その結果を TTT と比較する。トレースには、Infer\InferInfer が行う再帰呼び出しと、各呼び出しが対応する型付け規則を示す。ノードを開いたり閉じたりして、再帰を追ってほしい。

誤った証明

利用者が、t=λ(P:Sort 0). λ(h:P). Pt = \tLam{P}{\Sort{0}}{\tLam{h}{P}{P}}t=λ(P:Sort0).λ(h:P).P は Π(P:Sort 0). P→P\tPi{P}{\Sort{0}}{P \to P}Π(P:Sort0).P→P を証明すると主張したとしよう。本体は証明 hhh ではなく命題 PPP を返している。カーネルは Check(⋅,t,Π(P:Sort 0). P→P)\Check(\cdot, t, \tPi{P}{\Sort{0}}{P \to P})Check(⋅,t,Π(P:Sort0).P→P) を呼び、まず Infer\InferInfer が走る。呼び出しは上と同じだが、最後の Infer(Γ2,P)\Infer(\Gamma_2, P)Infer(Γ2​,P) だけが Sort 0\Sort{0}Sort0 を返す。つまり Infer\InferInfer は成功し、結果は

Infer(⋅,t)  =  Π(P:Sort 0). Π(h:P). Sort 0.\Infer(\cdot, t) \;=\; \tPi{P}{\Sort{0}}{\tPi{h}{P}{\Sort{0}}}.Infer(⋅,t)=Π(P:Sort0).Π(h:P).Sort0.

となる。項 ttt は正しく型付けされるが、主張された命題の証明にはなっていない。Check\CheckCheck が二つの型を比較しても、どちらもこれ以上計算できず、束縛変数を改名しても一致しない。いちばん内側の本体が片方では Sort 0\Sort{0}Sort0、もう片方では PPP だからである。そのため IsDefEq\IsDefEqIsDefEq は失敗し、Check\CheckCheck は型の不一致を報告する。（第 11 章 では、IsDefEq\IsDefEqIsDefEq が使うアルゴリズムでこの比較を一歩ずつ再現する。）

この誤りが見つかったのは、利用者が証明すべき命題を宣言したからにほかならない。Infer\InferInfer だけを走らせるカーネルなら、ttt を受理し、黙って別の型を割り当てていただろう。どのスクリプトでも goal が先頭に来るのはこのためであり、qed がそれと照合するのもこのためである。

goal forall (P : Sort 0), P -> P
exact fun (P : Sort 0) => fun (h : P) => P
qed

項が正しく型付けされていても、主張された定理を証明したことにはならない。Infer\InferInfer を通る閉じた項には型を推論できるが、カーネルはそれが定理に対して主張された型と一致するかも確かめなければならない。タクティク（第 10 章）は、項を組み立てる前にその主張を固定するよう設計されている。

仮定を使う: モーダス・ポネンス

ここまでの例では、関数を一度も適用していない。次の検査を考えよう。

t=λ(P:Sort 0). λ(Q:Sort 0). λ(f:P→Q). λ(p:P). f  pagainstΠ(P:Sort 0). Π(Q:Sort 0). (P→Q)→P→Q,t = \tLam{P}{\Sort{0}}{\tLam{Q}{\Sort{0}}{\tLam{f}{P \to Q}{\tLam{p}{P}{f\;p}}}} \quad\text{against}\quad \tPi{P}{\Sort{0}}{\tPi{Q}{\Sort{0}}{(P \to Q) \to P \to Q}},t=λ(P:Sort0).λ(Q:Sort0).λ(f:P→Q).λ(p:P).fpagainstΠ(P:Sort0).Π(Q:Sort0).(P→Q)→P→Q,

この型は「PPP ならば QQQ であり、PPP が成り立つなら、QQQ が成り立つ」と述べている。四つの λ\lambdaλ が、これまでと同じように文脈を Γ=P:Sort 0,  Q:Sort 0,  f:P→Q,  p:P\Gamma = P : \Sort{0},\; Q : \Sort{0},\; f : P \to Q,\; p : PΓ=P:Sort0,Q:Sort0,f:P→Q,p:P まで拡張する。本体 f  pf\;pfp は Infer\InferInfer の適用のケースに達する。

  • Infer(Γ,  f  p)\Infer(\Gamma,\; f\;p)Infer(Γ,fp) T-App
    • Infer(Γ,  f)\Infer(\Gamma,\; f)Infer(Γ,f) は P→QP \to QP→Q、すなわち Π(_:P). Q\tPi{\_}{P}{Q}Π(_:P).Q を返す。Whnf\WhnfWhnf はこれを変えず、これは Π\PiΠ である T-Var
    • Check(Γ,  p,  P)\Check(\Gamma,\; p,\; P)Check(Γ,p,P) は成功する。p:Pp : Pp:P が Γ\GammaΓ にあるからである T-Var, T-Conv
    • Q[_↦p]=Q\subst{Q}{\_}{p} = QQ[_↦p]=Q を返す。名前 _\__ は QQQ に現れないので、代入は何もしない

利用者が代わりに f  ff\;fff と書いていたら、二つ目のステップで Check(Γ,f,P)\Check(\Gamma, f, P)Check(Γ,f,P) が呼ばれ、P→QP \to QP→Q は PPP ではないので失敗する。ここでは関数を自分自身に食わせることはできない。下で f p を f f に変えて試してほしい。

goal forall (P : Sort 0), forall (Q : Sort 0), (P -> Q) -> P -> Q
exact fun (P : Sort 0) => fun (Q : Sort 0) => fun (f : P -> Q) => fun (p : P) => f p
qed

全称命題の具体化

依存的な適用では、T-App の代入が実質的な仕事をする。最初の例の証明を id=λ(P:Sort 0). λ(h:P). h\mathit{id} = \tLam{P}{\Sort{0}}{\tLam{h}{P}{h}}id=λ(P:Sort0).λ(h:P).h とし、Γ=Q:Sort 0\Gamma = Q : \Sort{0}Γ=Q:Sort0 とする。このとき Infer(Γ,id  Q)\Infer(\Gamma, \mathit{id}\;Q)Infer(Γ,idQ) は次のようになる。

  • Infer(Γ,  id  Q)\Infer(\Gamma,\; \mathit{id}\;Q)Infer(Γ,idQ) T-App
    • Infer(Γ,  id)\Infer(\Gamma,\; \mathit{id})Infer(Γ,id) は Π(P:Sort 0). Π(h:P). P\tPi{P}{\Sort{0}}{\tPi{h}{P}{P}}Π(P:Sort0).Π(h:P).P を返す。すでに Π\PiΠ である T-Lam
    • Check(Γ,  Q,  Sort 0)\Check(\Gamma,\; Q,\; \Sort{0})Check(Γ,Q,Sort0) は成功する T-Var
    • (Π(h:P). P)[P↦Q]=Π(h:Q). Q\subst{(\tPi{h}{P}{P})}{P}{Q} = \tPi{h}{Q}{Q}(Π(h:P).P)[P↦Q]=Π(h:Q).Q、すなわち Q→QQ \to QQ→Q を返す

論理的には、これは ∀\forall∀ 除去である。「どの命題も自分自身を含意する」から「QQQ は QQQ を含意する」を得ている。結果の型は引数 QQQ の値に依存する。依存 Π\PiΠ 型が表しているのはまさにこのことであり、T-App が代入を行う理由でもある。エクスプローラでは、id\mathit{id}id は定義された定数で、QQQ は文脈から来る。T-App ノードの注記に代入が記録される。

def id : forall (P : Sort 0), P -> P := fun (P : Sort 0) => fun (h : P) => h

変換

第 3 章 の Id=λ(X:Sort 0). X\mathit{Id} = \tLam{X}{\Sort{0}}{X}Id=λ(X:Sort0).X を思い出そう。核となる体系には定義がないので、Id  P\mathit{Id}\;PIdP は項 (λ(X:Sort 0). X)  P(\tLam{X}{\Sort{0}}{X})\;P(λ(X:Sort0).X)P の略記である。次の検査を考える。

t=λ(P:Sort 0). λ(h:Id  P). hagainstΠ(P:Sort 0). P→P.t = \tLam{P}{\Sort{0}}{\tLam{h}{\mathit{Id}\;P}{h}} \quad\text{against}\quad \tPi{P}{\Sort{0}}{P \to P}.t=λ(P:Sort0).λ(h:IdP).hagainstΠ(P:Sort0).P→P.

Infer\InferInfer はまず、注釈 Id  P\mathit{Id}\;PIdP が型であることを確かめる。InferSort(Γ1,Id  P)\InferSort(\Gamma_1, \mathit{Id}\;P)InferSort(Γ1​,IdP) は Infer\InferInfer の適用のケースに達する。関数 λ(X:Sort 0). X\tLam{X}{\Sort{0}}{X}λ(X:Sort0).X の型は Π(X:Sort 0). Sort 0\tPi{X}{\Sort{0}}{\Sort{0}}Π(X:Sort0).Sort0 で、引数 PPP は Check(Γ1,P,Sort 0)\Check(\Gamma_1, P, \Sort{0})Check(Γ1​,P,Sort0) を通り、結果は Sort 0[X↦P]=Sort 0\subst{\Sort{0}}{X}{P} = \Sort{0}Sort0[X↦P]=Sort0 である。したがって Id  P\mathit{Id}\;PIdP は型であり、しかも命題である。本体 hhh の型は Id  P\mathit{Id}\;PIdP なので、

Infer(⋅,t)  =  Π(P:Sort 0). Π(h:Id  P). Id  P.\Infer(\cdot, t) \;=\; \tPi{P}{\Sort{0}}{\tPi{h}{\mathit{Id}\;P}{\mathit{Id}\;P}}.Infer(⋅,t)=Π(P:Sort0).Π(h:IdP).IdP.

となる。束縛変数を改名するだけでは、これは Π(P:Sort 0). P→P\tPi{P}{\Sort{0}}{P \to P}Π(P:Sort0).P→P にならない。しかし IsDefEq\IsDefEqIsDefEq は比較の前に両辺を計算する。Id  P→βP\mathit{Id}\;P \betared PIdP→β​P なので、推論された型は Π(P:Sort 0). Π(h:P). P\tPi{P}{\Sort{0}}{\tPi{h}{P}{P}}Π(P:Sort0).Π(h:P).P になり、最初の例と同じく比較は成功する。型付け規則で言えば、このステップは導出の根における T-Conv の一回の使用である。

⋅⊢t:Π(P:Sort 0). Id  P→Id  P⋅⊢Π(P:Sort 0). P→P:Sort 0Π(P:Sort 0). Id  P→Id  P≡Π(P:Sort 0). P→P⋅⊢t:Π(P:Sort 0). P→P;(T-Conv)\dfrac{ \cdot \vdash t : \tPi{P}{\Sort{0}}{\mathit{Id}\;P \to \mathit{Id}\;P} \qquad \cdot \vdash \tPi{P}{\Sort{0}}{P \to P} : \Sort{0} \qquad \tPi{P}{\Sort{0}}{\mathit{Id}\;P \to \mathit{Id}\;P} \conv \tPi{P}{\Sort{0}}{P \to P} }{\cdot \vdash t : \tPi{P}{\Sort{0}}{P \to P}}\rulename{T-Conv}⋅⊢t:Π(P:Sort0).P→P⋅⊢t:Π(P:Sort0).IdP→IdP⋅⊢Π(P:Sort0).P→P:Sort0Π(P:Sort0).IdP→IdP≡Π(P:Sort0).P→P​;(T-Conv)

アルゴリズムは、T-Conv をどこで適用するかを決して決めない。第 5 章 で述べたとおり、変換は IsDefEq\IsDefEqIsDefEq の呼び出しの中に隠れており、二つの型が比較される場所でしか走らない。

ライブの導出を見ると、計算がどこで起きるかが分かる。注釈 Id  P\mathit{Id}\;PIdP は T-App で検査され、推論された型には、Check\CheckCheck がゴールと比較するまで Id  P\mathit{Id}\;PIdP が残ったままである。

演習

上の例のように Infer\InferInfer を手で走らせてみると、アルゴリズムの理解を確かめるよい練習になる。どれもプレイグラウンドで試せる。

Π(P:Sort 0). Π(Q:Sort 0). P→Q→P\tPi{P}{\Sort{0}}{\tPi{Q}{\Sort{0}}{P \to Q \to P}}Π(P:Sort0).Π(Q:Sort0).P→Q→P を証明せよ。

解答

一つの答えは λ(P:Sort 0). λ(Q:Sort 0). λ(p:P). λ(q:Q). p\tLam{P}{\Sort{0}}{\tLam{Q}{\Sort{0}}{\tLam{p}{P}{\tLam{q}{Q}{p}}}}λ(P:Sort0).λ(Q:Sort0).λ(p:P).λ(q:Q).p である。この証明は qqq を一度も使わない。体系は、仮定を使わずに済ませることを許している。

含意が推移的であることを証明せよ: Π(P:Sort 0). Π(Q:Sort 0). Π(R:Sort 0). (P→Q)→(Q→R)→P→R\tPi{P}{\Sort{0}}{\tPi{Q}{\Sort{0}}{\tPi{R}{\Sort{0}}{(P \to Q) \to (Q \to R) \to P \to R}}}Π(P:Sort0).Π(Q:Sort0).Π(R:Sort0).(P→Q)→(Q→R)→P→R。

解答

一つの答えは λ(f:P→Q). λ(g:Q→R). λ(p:P). g  (f  p)\tLam{f}{P \to Q}{\tLam{g}{Q \to R}{\tLam{p}{P}{g\;(f\;p)}}}λ(f:P→Q).λ(g:Q→R).λ(p:P).g(fp) で終わる。適用のケースを二回使う。まず f  p:Qf\;p : Qfp:Q、次に g  (f  p):Rg\;(f\;p) : Rg(fp):R である。

goal forall (P : Sort 0), forall (Q : Sort 0), forall (R : Sort 0), (P -> Q) -> (Q -> R) -> P -> R
exact fun (P : Sort 0) => fun (Q : Sort 0) => fun (R : Sort 0) => fun (f : P -> Q) => fun (g : Q -> R) => fun (p : P) => g (f p)
qed

λ(P:Sort 0). λ(h:P). h  h\tLam{P}{\Sort{0}}{\tLam{h}{P}{h\;h}}λ(P:Sort0).λ(h:P).hh が拒否される理由と、アルゴリズム 5.1 のどの行で拒否されるかを説明せよ。

解答

文脈 P:Sort 0,h:PP : \Sort{0}, h : PP:Sort0,h:P において、本体 h  hh\;hhh は適用のケースに達する。Infer\InferInfer は関数 hhh に対して PPP を返すが、Whnf(P)=P\Whnf(P) = PWhnf(P)=P は変数であって Π\PiΠ ではない。アルゴリズムは else fail "not a function" の行で失敗する。PPP の証明は適用できるものではない。Rust でのメッセージは application of non-function である。

覚えておくこと

  • Infer\InferInfer の実行は導出木を映す。値を返す各呼び出しが一つのノードである。
  • Infer\InferInfer は、宣言された定理を証明していない項に対しても成功しうる。それを捕まえるのは、宣言された型に対する Check\CheckCheck である。
  • T-App は、仮定が使われる場所（モーダス・ポネンス）であり、全称命題が具体化される場所（Π\PiΠ の本体への代入）でもある。
  • 型の内部の計算はすべて IsDefEq\IsDefEqIsDefEq が扱う。アルゴリズムは T-Conv をどこで適用するかを決して選ばない。
