第 11 章

替换、捕获与 α 等价

前几章把项上的三种操作当作黑盒：替换（substitution），T-App、Freshen 和每一步计算都要用它；弱头规范化（weak head normalization），用来把 Π\PiΠ 或宇宙暴露出来；定义相等（definitional equality），Check 要用它。这三种操作都属于可信内核，而内核的多数 bug 就藏在其中，因为它们必须正确处理约束变量的名字。本章打开第一个黑盒，即替换，接着展示同样的命名问题如何出现在上下文里，最后定义两个项何时在约束变量的名字意义下相等。

自由变量与替换

Π\PiΠ 和 λ\lambdaλ 会绑定它们的变量：在 λ(x:A). t\tLam{x}{A}{t}λ(x:A).t 中，ttt 内部出现的 xxx 指的是参数。绑定子的作用域只有函数体；xxx 在标注 AAA 中并不受绑定。一个变量出现若不被任何外层的 Π\PiΠ 或 λ\lambdaλ 绑定，就是自由的。

定义 11.1 和 11.2 对应 src/substitution.rs 中的 fv 和 subst。下面是 subst 的绑定子情形。与定义相比，它多了一条捷径：如果 xxx 在函数体中完全没有自由出现，就原样返回函数体，省掉一次遍历，且不会改变结果。

Term::Pi(y, domain, body) | Term::Lam(y, domain, body) => {
    let substituted_domain = subst(domain, x, replacement);
    let (renamed_binder, substituted_body) = if y == x || !fv(body).contains(x) {
        (y.clone(), (**body).clone())                       // shadowed, or nothing to do
    } else if !fv(replacement).contains(y) {
        (y.clone(), subst(body, x, replacement))            // no capture possible
    } else {

        let body_with_z = subst(body, y, &var(&z));
        (z, subst(&body_with_z, x, replacement))

}

fresh 函数不断在提示名后面追加撇号，直到得到一个未被使用的名字。避让集合由 all_names 给出，它收集相关各项中的所有名字，而不只是自由名字；这比定义所要求的更多，但能让输出更易读。

上下文中的变量捕获

人们很容易想去掉 C-Ext 的附加条件 x∉dom(Γ)x \notin \dom(\Gamma)x∈/dom(Γ)，让新假设直接遮蔽旧假设，就像大多数编程语言那样，但这样做会使内核不可靠。考虑

t=λ(x:Sort 0). λ(y:x). λ(x:Sort 0). y.t = \tLam{x}{\Sort{0}}{\tLam{y}{x}{\tLam{x}{\Sort{0}}{y}}}.t=λ(x:Sort0).λ(y:x).λ(x:Sort0).y.

变量 yyy 的类型是外层的 xxx，而最内层的 λ\lambdaλ 忽略自己的参数。所以 ttt 的正确类型是

Π(x:Sort 0). Π(y:x). Π(x′:Sort 0). x.\tPi{x}{\Sort{0}}{\tPi{y}{x}{\tPi{x'}{\Sort{0}}{x}}}.Π(x:Sort0).Π(y:x).Π(x′:Sort0).x.

一个没有 Freshen\FreshenFreshen 的检查器会在上下文 x:Sort 0,  y:x,  x:Sort 0x : \Sort{0},\; y : x,\; x : \Sort{0}x:Sort0,y:x,x:Sort0 中查找 yyy，并返回它的类型，也就是光秃秃的名字 xxx。此时 xxx 指的是内层绑定子，于是检查器返回

Π(x:Sort 0). Π(y:x). Π(x:Sort 0). x,\tPi{x}{\Sort{0}}{\tPi{y}{x}{\tPi{x}{\Sort{0}}{x}}},Π(x:Sort0).Π(y:x).Π(x:Sort0).x,

它的意思是“从任意类型的任意元素出发，可以造出每一个类型的元素”。给定 A:Sort 0A : \Sort{0}A:Sort0 和 a:Aa : Aa:A，项 t  A  at\;A\;atAa 的类型就是 Π(B:Sort 0). B\tPi{B}{\Sort{0}}{B}Π(B:Sort0).B，即 False 的一个证明。而这样的 AAA 和 aaa 在空上下文中就已存在：A=Π(P:Sort 0). P→PA = \tPi{P}{\Sort{0}}{P \to P}A=Π(P:Sort0).P→P 本身就是一个命题，恒等函数 a=λ(P:Sort 0). λ(h:P). ha = \tLam{P}{\Sort{0}}{\tLam{h}{P}{h}}a=λ(P:Sort0).λ(h:P).h 证明了它。

这个问题和替换中的问题是同一个：一个名字被移进了另一个作用域，而它在那里的含义变了。任何按名字识别变量的表示方式都会受影响，无论上下文是列表还是哈希表。常见的补救办法有三种。

  1. 直接拒绝遮蔽，这是最简单的做法，但 A→BA \to BA→B 使用的保留名 _ 必须例外，且永远不加入上下文。
  2. 进入时改名，也就是 Freshen\FreshenFreshen 的做法，这是我们的选择。
  3. 用位置表示约束变量（de Bruijn 索引 [de Bruijn 1972]），或采用局部无名（locally nameless）风格：约束变量用索引，自由变量带唯一标识符；Lean 4 采用后一种方式。

测试套件应当包含上面的 ttt，并检查内核要么拒绝它，要么给它赋予正确的类型。

这个 bug 容易写出来，却很难被发现，因为所有普通的证明照样能通过检查，只有刻意在嵌套绑定子中重用名字的项才会暴露它。内核的测试套件需要对抗性的项，而不只是正确的证明。

α 等价

约束变量的名字不携带任何含义：λ(x:A). x\tLam{x}{A}{x}λ(x:A).x 和 λ(y:A). y\tLam{y}{A}{y}λ(y:A).y 是同一个函数，Π(P:Sort 0). P→P\tPi{P}{\Sort{0}}{P \to P}Π(P:Sort0).P→P 和 Π(Q:Sort 0). Q→Q\tPi{Q}{\Sort{0}}{Q \to Q}Π(Q:Sort0).Q→Q 是同一个命题。只在约束变量名字上有差别的项称为 α 等价（alpha-equivalent）的。内核不能用单纯的语法相等来比较类型，否则第二对项就会被拒绝。

定义 11.3（α 等价）。 =α\alphaeq=α​ 是项上最小的合同关系，使得对 □∈{Π,λ}\square \in \{\Pi, \lambda\}□∈{Π,λ}，

□(x:A). B  =α  □(y:A). B[x↦y]whenever y∉FV(B).\square(x{:}A).\,B \;\alphaeq\; \square(y{:}A).\,\subst{B}{x}{y} \qquad \text{whenever } y \notin \FV(B).□(x:A).B=α​□(y:A).B[x↦y]whenever y∈/FV(B).

（合同关系（congruence）是指被每个项构造器保持的等价关系：各部分相关，则整体相关。）这个定义容易陈述，却不能直接执行，因为它没有说该选哪些名字。实现的做法是同步遍历两个项，并为每一侧记住到目前为止经过的绑定子列表。这样，约束变量就由它指向哪一个绑定子来识别，而不是由名字。

x,y;  a,b⊢x=αa,x, y;\; a, b \vdash x \alphaeq a,x,y;a,b⊢x=α​a,

自由变量按名字比较（α\alphaα-Free），约束变量按位置比较（α\alphaα-Bound），常量按名字比较（α\alphaα-Const）。一侧受绑定、另一侧自由的变量不与任何东西相等，所以这种情形没有规则。由于两侧总是一起穿过绑定子，E1E_1E1​ 和 E2E_2E2​ 的长度始终相同。因此，从右数位置与从左数位置是一回事，实现可以把每个列表存成从名字到绑定深度的映射，只要离开绑定子时恢复先前的条目即可。如果处处都用位置代替名字，就得到 de Bruijn 表示：在这种表示下，α 等价的项在语法上完全相同。

(Term::Var(x), Term::Var(y)) => {
    match (binder_distance(bound_a, x), binder_distance(bound_b, y)) {
        (Some(i), Some(j)) => i == j,     // alpha-Bound

        _ => false,                       // bound on one side only
    }
}

练习

逐步计算 (λ(y:A). λ(x:B). x  y)[x↦y]\subst{(\tLam{y}{A}{\tLam{x}{B}{x\;y}})}{x}{y}(λ(y:A).λ(x:B).xy)[x↦y]。

解答

外层绑定子是 yyy，它在替换项 yyy 中自由出现，所以适用捕获情形：把 yyy 改名为新鲜的 zzz，得到函数体 λ(x:B). x  z\tLam{x}{B}{x\;z}λ(x:B).xz，然后再替换。内层绑定子是 xxx，正是被替换的变量，所以内层函数体保持不动。结果：λ(z:A). λ(x:B). x  z\tLam{z}{A}{\tLam{x}{B}{x\;z}}λ(z:A).λ(x:B).xz。注意内层的 xxx 从来不是自由出现，所以实际上什么都没被替换；唯一的效果是避免捕获所强制的改名。

运行图 11.1 的规则，判断 λ(x:A). λ(y:A). y  x\tLam{x}{A}{\tLam{y}{A}{y\;x}}λ(x:A).λ(y:A).yx 与 λ(y:A). λ(x:A). x  y\tLam{y}{A}{\tLam{x}{A}{x\;y}}λ(y:A).λ(x:A).xy 是否 α 等价。

解答

是。经过两步 α\alphaα-Lam，绑定子列表分别为 x,yx, yx,y 和 y,xy, xy,x，函数体则为 y  xy\;xyx 和 x  yx\;yxy。α\alphaα-App 先比较 yyy 与 xxx，得到的索引分别是 000 和 000；再比较 xxx 与 yyy，索引分别是 111 和 111。名字虽然互换，位置却一致。

要点回顾

  • 替换只替换自由出现；当替换项提到绑定子的名字时（捕获），必须给绑定子改名。
  • 同样的捕获问题也出现在上下文中。允许绑定子遮蔽上下文条目的内核可以证明 False；Freshen 防止了这一点。
  • α 等价按绑定子的位置比较约束变量，按名字比较自由变量。图 11.1 是算法；定理 11.4 说明它与定义一致。
